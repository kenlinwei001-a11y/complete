> 方法（按你的要求）：**逐张图 → 它满足什么场景 → 需要哪些功能 → 我方这些功能在哪 → 是否满足同场景 → 如何整合**。

## 图1 · 本体建模总览（图谱 + 闭环计数 + 双雷达 + 知识激活 + AI 就绪评估）

- **场景**：本体建好后，一眼看"这个本体应用是否就绪、能否进入推演"——健康度、信任度、激活度，AI 直接告诉你"还差哪一步"。
- **所需功能**：①本体图谱可视化 ②闭环计数（状态/动作/写回/查询）③Runtime Health 雷达（规则覆盖/利用率/激活/可观测/环安全/闭包）④Runtime Trust 雷达（运行/可解释/时序/数据信任）⑤知识激活率 ⑥AI 就绪评估 + 唯一待办引导。
- **我方位置**：图谱=`OntologyGraphView`；雷达**组件**=`views/sim/RadarChart.tsx`（但喂的是经营五维 盈利/规模/现金/增长/稳健，**非健康/信任**）；就绪诊断=`A10 verifyBuild`+`GapReport/classifyGap`（7码,`growth/probe.ts`）+自成长驾驶舱`/admin/growth`；闭环度=`databuilder/closure.ts` ClosureReport（有维度但无"State/Action/Writeback/Query 计数面板"）；激活率=无现成。
- **是否满足同场景**：**◐ 部分**。积木齐（图谱+雷达组件+就绪诊断），但**没整合进"本体建模页的就绪评估面板"**，雷达未喂健康/信任维度，无闭环计数面板、无激活率。
- **如何整合**：在 `ModelingPage` 加"就绪评估面板"——**复用 `RadarChart`** 改喂 Health/Trust 维度（数据从 ClosureReport 算）+ 闭环计数（从本体对象/规则/动作聚合）+ `GapReport` 出"唯一待办"。→ 对应原型 **`mockup-readiness`**。

## 图2 · 本体建模数据管道（数据源→处理→实体/链路→本体库 + L0-L4 认证 + 三维准备度）

- **场景**：**从「连接器与上传」导入的原始数据建模**，看清"数据源→实体"的加工管道，并认证仿真就绪。**（=你指出的缺口）**
- **所需功能**：①数据源(连接器/上传 RawDataset)→数据处理→实体/链路→本体库 **管道可视化**（含来源 provenance）②L0-L4 Runtime Certification ③三维准备度（结构/知识/行为）④Trial Tick ⑤AI 解读应用。
- **我方位置**：数据集建模=`ModelingPage`（`fetchRawDatasets():82`，列出 RawDataset → dataset→对象/column→属性/FK→链接:127 + 字段覆盖度:230）；来源 provenance=`RawDataset.sourceCategory`/`Connection.category`（A11，**数据有，前端没前置展示**）；L0-L4=**无**（有 A18 三相 PROVISIONAL→ADVISORY→GOVERNED）；Trial Tick=`A10 verifyBuild`（主问句重跑≈试运行）；三维评分=**无**（有 ClosureReport 缺口码）。
- **是否满足同场景**：**◐ 部分**。**"从数据集建模"的原语有，但呈现是列表、不是管道，且数据源来源没前置**；无 L0-L4、无三维评分。**你的批评成立**：`ModelingPage` 应直接展示「连接器与上传」的数据源并连成管道。
- **如何整合**：`ModelingPage` 左栏**直接列「连接器与上传」数据源**（按 Connection 分组 + sourceCategory + 覆盖度），中区改为**管道画布**（数据源→处理→实体/链路→本体库）；`ClosureReport`+`A18` 升级为 **L0-L4 + 三维评分 + Trial Tick**。→ 对应原型 **`mockup-modeling`**（已把数据源前置）。

## 图4 · 三件套图解（衍生规则 / 业务动作接口 / 图谱查询指令）

- **场景**：解释"可进入推演"的硬条件——**三件套必须同时配齐**：仅规则=能算不能模拟；仅动作=风险不传导；三者齐=解锁推演。
- **所需功能**：①衍生规则配置 ②业务动作接口配置（HITL/副作用）③图谱查询指令配置 ④"三件套齐"门禁 + UI 提示。
- **我方位置**：衍生规则=`DerivationSpec`（`ontology-core.ts`，topo 重算）；业务动作=`ActionType`（`actions.ts`，R4 审批）；图谱查询=`SliceSpec`/`slice-planner`+`catalog/search`；门禁=`closure.ts`（有闭包门，但**非"三件套"显式门**）。
- **是否满足同场景**：**◐ 部分**。三件套**每件都有**，但**没有"三件套齐才可进入推演"的显式门 + 缺件 UI 提示**。
- **如何整合**：新增"三件套门"校验（缺派生/缺动作/缺查询 → 显式拦 + 提示），挂在实体详情与就绪认证。→ 对应原型 **`mockup-entity`** 右栏"可进入推演三件套门"。

## 图5 · 逐实体建模详情（对象定义 + 属性/类型/函数/行动/派生/安全 tabs + 行动 HITL/写回/条件 + 局部准备度 75/100）

- **场景**：编辑**单个实体**，定义其属性/行动/派生/查询，看**这个实体的局部就绪度**（哪一件缺）。
- **所需功能**：①实体定义（标签/类型/字段/描述/存储模式）②多 tab（属性/类型/函数/行动/派生/安全）③行动定义（入参/副作用/HITL/条件）④逐实体仿真准备度评分。
- **我方位置**：实体定义=`ModelingPage` 建模草案（dataset→type）；行动=`ActionType`（`actions.ts`，**有审批，但无显式 HITL flag、无"沙盘态"**）；派生=`DerivationSpec`；查询=`SliceSpec`；逐实体准备度=**无**（只有全局 ClosureReport）。
- **是否满足同场景**：**◐ 部分**。实体/行动/派生定义有，但**行动缺"沙盘模拟态"、无逐实体准备度评分、tab 组织度不如竞品**。
- **如何整合**：`ModelingPage` 实体详情加 6 tab + **行动双态**（沙盘模拟态 vs R4 真值态，`actions.ts` 扩 `sandbox`）+ **逐实体准备度**（局部 closure 算）。→ 对应原型 **`mockup-entity`**。

## 图6 · 全局仿真准备度 + L0-L4 认证 + L4 三准则 + AI 扫描缺陷

- **场景**：发布前**全局就绪认证** + **AI 主动扫描缺陷出结构化报告**，引导补全。
- **所需功能**：①L0-L4 认证（Invalid→Configured→Runnable→Verified→Certified）②Trial Tick 历史 ③L4 三准则（Fanout 安全/Writeback 完整/Observability 达标）④缺口 high/med/low ⑤AI 扫描缺陷→结构化报告。
- **我方位置**：AI 缺陷扫描=`GapReport/classifyGap`（7码 NO_INTENT/NO_PLAN/.../SHAPE_MISMATCH，`growth/probe.ts`）+ `runGrowthLoop` + 自成长驾驶舱 `/admin/growth`（**理念对等甚至更自动**）；Trial Tick=`A10 verifyBuild`；相位=`A18`；L0-L4/三准则=**无产品化**。
- **是否满足同场景**：**◐ 部分（缺陷扫描这块 ✅ 对等/领先）**。我方 `GapReport` 比竞品"扫描缺陷"更自动（能自成长补齐），但**缺 L0-L4/三准则/Trial Tick 历史的认证产品化**。
- **如何整合**：把 `closure.ts`+`A10`+`A18` 升级为 **L0-L4 认证 + 三准则 + Trial Tick 历史**面板；**复用 `GapReport`** 做"AI 扫描缺陷"。→ 对应原型 **`mockup-readiness`**（含 high/med/low + 唯一待办）。

## 图7 · 沙盘初始化向导（世界基准时间 → 推演范围 → 范围预检 + 世界完整度）

- **场景**：开沙盘前——选基准时间（实时/历史快照）、裁推演范围、预检"传导覆盖是否完整"。
- **所需功能**：①基准时间（实时快照/历史 asOf）②范围裁剪（主体对象/关系类型/属性过滤/扩展深度/实体数限）③范围预检（传播实体/状态变量/派生/Action 计数 + 世界完整度%）。
- **我方位置**：基准时间=`SimulationClock`（`simclock.ts`）+ temporal `asOfEpoch`（`ontology.ts:279`，历史快照）；范围裁剪=`SliceSpec`/`slice-planner`（`POST /a/v1/slices/plan`，按类型裁子图）；预检计数=**无现成**（切片有 spannedTypes，但无"世界完整度"预检）。
- **是否满足同场景**：**◐ 部分**。基准时间（时钟+temporal）、范围裁剪（切片规划器）**都有**，但**没整合成"沙盘初始化向导"+ 世界完整度预检**。
- **如何整合**：新建 `SimSession` init 三步向导，**复用 simclock（基准）+ slice-planner（范围）+ temporal（历史快照）**，加范围预检计数。→ 对应原型 **`mockup-init`**。

## 图8 · 沙盘运行（拓扑图 + 时间轴 + AI 推演指挥台）

- **场景**：交互式时序推演——逐 tick 推进、风险沿图传导、自然语言干预、分支对比、回滚、边界拦截。
- **所需功能**：①有状态世界态 ②逐 tick 时间推进 ③风险传导（系数+延迟，沿 link）④沙盘态业务动作 ⑤checkpoint/回滚/场景分支 ⑥多时间线 KPI 对比 ⑦AI 指挥台（NL→工具→结果卡片→审计）⑧边界校验拦截。
- **我方位置**：时间推进=`SimulationClock.tick`；单步 what-if=`generic_inference`（`/inference/whatif`，套假设值重算派生 before/after，**不提交**）；时序曲线=`risk_timeline`/`counterfactual_timeline`（`solvers/risk.ts`，**单发曲线非逐 tick**）；传导时间轴**组件**=`PropagationTimeline.tsx`（但 risk_timeline 喂的固定 4 段）；temporal 回看=`asOfEpoch`；AI 指挥台=QOS 对话坞（classify→path A/B→SSE）；边界拦截=规则 BLOCK + R4 状态机。
- **是否满足同场景**：**❌ 整合层缺**。**积木几乎全有**（时钟/what-if/时序求解器/传导时间轴组件/temporal/QOS），但**没有"有状态、可交互、可回滚、可分支"的沙盘会话**——这是最大缺口。
- **如何整合**：新增 `SimSession` 沙盘会话 + **时序传导引擎**（系数+延迟沿 link，接「规则即引用」）+ 沙盘态 Action + checkpoint/branch + QOS 沙盘 MCP 工具；前端**复用 PropagationTimeline（进化为 tick 轴）+ RadarChart + useLiveSolver**。→ 对应原型 **`mockup-sandbox`** + 详见 `PRD-simulation-sandbox`。
