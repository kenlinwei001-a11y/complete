## §2 主线的目标形态

**总原则（一句话）**：五步 = **一个问题、一屏一件事、每屏一个动作**。
用户永远只需要回答「我要试什么」和「我选哪条」这两个问题，中间三步系统自己走完。

⚠️ 下面每一步的**第 4 问**逐条抄了今天屏上的原话。
标 **【删】** = 用户界面上不该出现；标 **【降层】** = 内容保留，收到第二层（点开 / 悬浮 / 汇总处）才看见。
**没有一条是「删掉诚实位」** —— 诚实位的处理方式单独写在 §4。

### ① 输入多个扰动

**1. 用户此刻在想什么**
> 「碳酸锂又涨了，常州那条线这个月还得停两天检修 —— 这两件事凑一块，我这个月还赚不赚钱？」

**2. 屏上必须出现什么（能让他往下走的最小信息集）**

- 一句提示 + 一个**空的事件行**，和一份**「事情清单」**（8–10 条，全是一句话的业务事件，带两个可改的空）：

  ```
  ▸ ［哪种料］涨价 ［多少］%          →  正极材料 涨价 20%
  ▸ ［哪个基地］减产 ［多少］%        →  常州基地 减产 40%
  ▸ ［哪个基地］停线 ［几天］         →  常州基地 停线 2 天
  ▸ ［哪个客户］加单 ［多少］套
  ▸ ［哪个供应商］断供 ［几天］
  ▸ ［哪张单］提前 ［几天］交
  ▸ 销售预测  ○报多了  ○报少了   ［多少］%
  ▸ ［哪条线］设备故障 ［几天］
  ```
- **已加的事件叠成一个可见清单**（这就是「多个扰动」这三个字的形态）：一行一条，能删、能改数字。
- 一句话的当前状态：「已经加了 2 件事」。

**3. 他下一步点什么**
> **一个按钮：「算一下」。** 屏上最亮、最大的东西，只有它一个。
> 它自己把该走的都走完（施加 + 推进 + 出钱 + 出卡点 + 出方案），用户不需要知道中间有几步。

**4. 什么绝对不该出现在这一步（逐条点名今天的原话）**

| 今天屏上的原话 | 处置 | 为什么 |
|---|---|---|
| 落点对象下拉的占位符「**筛选（共 11337 个落点）**」，选项 `ARAging · obj_araging_ar-90plus` / `obj_model_2170-NCM` / `BOMDetail · obj_bomdetail_BDTL-BOM-2170-NCM-V1_0-0` | **【删】** | 业务人员脑子里是「常州」「碳酸锂」「4680」，不是 `obj_` 开头的编号。**这一格是第 ① 步不可用的单点成因。** |
| 「扰什么 · 根源优先」的 40 项：`换型压力` `清关排队天数` `逾期催收压力` `成本压力` `缺陷压力` `投料压力` `窗口挤压`… | **【降层】** | 这是引擎的中间量，不是人会说的事。事件模板选完之后由系统自己映射过去，用户永远不看这份表。要看的时候在「这是怎么算的」里给。 |
| 「落点对象类型」下拉里的 `Model` / `Order` | **【删】** | 英文类型名 |
| 「怎么扰」的 `增减（delta）` / `乘以（scale）` / `设为（set）` | **【删括号】** | 括号里的英文；中文那三个词留着 |

| 「幅度」`10`（不带单位） | **【删】** | 单位跟着事件模板走：「涨价 20 **%**」「停线 2 **天**」「加单 3 **万套**」 |
| 「**层级『枢纽』 —— 扰它等于从半路插入：这个量的上游那一段不会跟着动，读数只反映从这里往下的传导。**」 | **【降层】** | 这是在讲引擎内部结构。它要说的事（「这条只影响下游一半」）应该变成事件模板旁边一个小记号，见 §4 |
| 「施加只作用在当前 tick，**推进 tick 时才沿本体链路扩散**。」 | **【删】** | 这是实现说明。正确做法是「算一下」自己把该推的推完，**用户不该知道有第二个按钮**。 |
| 「传导边 42 条（其中启用 42 条）」+ 右栏「扰动因素 · 关掉看变化 · 42 条边 · 已关 0」+ 逐条 `Customer.receivablePressure —customer_has_location→ CustomerLocation.deliveryHoldRisk 系数 0.5 · 延迟 0` | **【降层】** | 整栏收进「这是怎么算的」。它是专家工具，不是第 ① 步 |
| 「今天扰不动的量（20）」 | **【降层·保留】** | 这是**诚实位**，内容不删。但它不该是第一层的一个按钮 —— 它该在事件清单末尾一行小字：「还有 20 件事这里试不了」，点开才看名单 |
| 顶部两条并排步骤条：`现状 → 归因 → 试一手 → 求最优 → 影响半径` 与 `① 会话与配置 ② 施加扰动 ③ 世界传播 ④ 影响带读数` | **【删其一】** | **同一屏顶上并排两条互不相同的「步骤」，两条都不是用户要走的五步。** 留一条，就是五步那一条 |
| 「◐ 尚未通过就绪认证 —— 现在推演出的结论仅供参考 / 为什么不能推演（缺件清单前几条）：`NO_SLICE · GLOBAL — 图查询覆盖 95/98 对象，切片 99 < minQueries 1`」 | **【降层·保留】** | 诚实位，内容不删。但 `NO_SLICE` / `minQueries` 是引擎话，且它占了第一层一整条横幅。见 §4 |

## §3 五步之间怎么传值

### 3.1 今天的实测：五步不但不传值，**连「哪个世界」都对不上**

我把两个页面来回点了两轮，逐次抄下屏上的世界编号（脚本 `p17.mjs`）：

```
A. 统一推演控制台 → sims_xb3qpch2323eeqp5
B. 推演沙盘       → sims_weect8wppesfstak     ← 和 A 不是同一个
C. 统一推演控制台 → sims_xb3qpch2323eeqp5     ← 回到 A 那个
D. 推演沙盘       → sims_z5m37t0b4sf7g9a2     ← 和 B 又不是同一个
```

**两条结论，都是实测：**

1. **「统一推演控制台」和「推演沙盘」从来不在同一个世界里。** 我在一边拨的扰动，另一边看不见。
2. **「推演沙盘」每进一次就换一个世界。** 我上一次拨的扰动，走开再回来就没了。
   （旁证：实测该租户下堆着 **18 条会话**。⚠ 我**没有**验证这 18 条里有几条是我这轮走查造出来的 ——
   同一次测量里会话总数前后都是 18，所以更像是「每次从已有会话里另选一条」而不是「每次新建一条」。
   **两种机制对用户是同一件事：走开再回来，上次拨的扰动不在了。** 机制归架构师追。）

再叠上 1.7 那条：**在同一个页面里，「施加扰动」也不会把值传给「钱」** —— 要再点一次「推进 tick」。

> **这就是仓主说的「没有一个主线串起来所有」的字面机制**：
> 不是「页面之间缺链接」，是**每一步都在一个新的、和上一步无关的上下文里重新开始**。

---

### 3.2 目标形态：一条推演 = 一件事，从头到尾一个身份

**核心设计**：把今天散在五处的上下文，收成**一个用户看得见的对象 —— 「一次推演」**。
它有一个用户自己起的名字（不是机器号），五步全部挂在它下面。

```
┌─ 一次推演：「三月碳酸锂涨价 + 常州检修」 ────────────────────────────┐
│                                                                    │
│  ① 我试了什么 ─────────────────────────────────────────────────┐   │
│     · 正极材料 涨价 20%                                         │   │
│     · 常州基地 停线 2 天                                        │   │
│     ─────────────────────────────────────────────────────────  │   │
│     产出：一份【事件清单】（2 条，可删可改）                     │   │
│                                    │                            │   │
│                                    ▼  原样带走，用户不重填         │   │
│  ② 算（2.5 秒，无动作） ────────────────────────────────────────┘   │
│     产出：一份【推演结果】——同一个结果同时喂给 ③④⑤，不再各算各的  │
│                    │                                               │
│      ┌─────────────┼─────────────┬──────────────┐                  │
│      ▼             ▼             ▼              ▼                  │
│  ③ 钱          ④ 卡点        ⑤ 方案        （诚实位汇总）           │
│  毛利 −56.5万   6 个红点      3 条路                                │
│      │             │             │                                 │
│      └─「为什么」──▶│             │                                 │
│                    └─「怎么办」──▶│                                 │
│                                  │                                 │
│                                  ▼                                 │
│                          〔就这么办〕→ 待审批草稿                    │
└────────────────────────────────────────────────────────────────────┘
```

**四条传值规则（每条都能用一句用户的话检验）**

| # | 规则 | 用户那句话 |
|---|---|---|
| **T1** | ①→② **不需要第二个按钮**。「算一下」之后不再要求任何操作才出数 | 「我按了算，就该出结果」 |
| **T2** | ②→③④⑤ **一次结果、三处消费**。钱、卡点、方案读的是同一次推演，不许各自重算 | 「这三个数说的是同一件事吧？」 |
| **T3** | ③→④ 和 ④→⑤ 是**下钻**不是**跳页**。点「为什么」把第 ③ 步那个数留在屏上，第 ④ 步在它下面展开；点「怎么办」把那个红点留在屏上 | 「我不想每点一下就忘了自己在看哪个数」 |
| **T4** | ①的清单**全程可见且可改**。任何一步都能改一个数字重算，前四步的位置不丢 | 「涨 20% 太狠了，改成 10% 再看一遍」 |

**这一条尤其要写死**：**「一次推演」的名字由用户在第 ① 步随手起（或系统按事件自动拟一个），
屏上从头到尾只出现这个名字，机器编号一次都不出现。** 走开再回来，默认回到**上一次那条推演**，
不是新开一个空的。这就是 3.1 那两条实测缺陷在设计上的直接对策。

## §4 诚实位怎么办（不许砍，只准降层）

### 4.1 先说清为什么一个字都不能删

我在走查里亲眼见到诚实位**救了我**：

- 传导识别那一屏，如果没有「**部分是示例 · …不是本次推演算出来的**」这一句，我会把一屏假甘特当成我的推演结果带走。
- 演习那一屏的「**求解器回执（0 次调用）**」，是我判断那 43,468 条成色的唯一依据。
- 「**与基线逐项相等 —— 是「比过了，一项都没动」，不是「没比」**」这一句，区分了两个完全不同的事实。

**删掉这些，屏上就只剩一个安静的数字，没人知道它是真是假。** 所以下面只谈形态，不谈删。

### 4.2 今天的形态问题：**诚实位是段落，且和数字同级**

实测三处最典型：

1. **同一段话在一屏里重复 5 遍**（统一推演控制台，每张指标卡各一份 87 字）：
   > 「推演投影·非实测（种子世界的 tick0 读数由 `**`本体结构派生`**`（确定性占位），不是实测：…量级不可当实测读。）」

   卡片里数字占 3 行，这段话占 12 行。**而且那对 `**` 原样打在屏上**（Markdown 星号没渲染）。
2. **它和数字同一个层级**：不是小字、不是灰的、不是角标，就是正文。
3. **两个诚实记号自相矛盾**：演习那一屏顶上「实测格 0/4373」，每条结论右边却盖着「实测」。

### 4.3 设计：**四个记号 + 一处汇总**，不再用段落

#### 记号 1 · 数字右上角一个**角标**（三态，一眼可辨）

| 角标 | 颜色 | 含义 | 用户什么时候会看到 |
|---|---|---|---|
| **实** | 无（默认，不画） | 这个数来自你们自己的系统 | 默认态，不占任何视觉 |
| **估** | 琥珀 | 这个数是推算出来的，量级不保真 | 今天**所有**推演数字都是这一档 |
| **样** | 灰 + 45° 斜纹底 | 这一格是示例，和你这次推演无关 | 传导识别那一屏的大半 |

**规则**：角标**只有一个字符**，不带任何文字说明。**悬浮/点击**才出那句完整的话（原文一字不改）。

#### 记号 2 · 数字**本身的写法**分档（比角标更早被看见）

- 「估」档的数字**不给小数**：`910.48` → `约 910 万`。
  今天屏上 `-13587.09` 这样的两位小数，会让人以为这是精算过的。**位数就是精度承诺。**
- 「样」档的数字**打斜纹底 + 降到 40% 不透明度**，读得出但一眼知道不是自己的数。

#### 记号 3 · **缺席**要占位置，不能显示成 0 或不变

今天最阴的一条（数据专家也点名了）：收入行 `projected == rolling`，**屏上看起来像「收入不受影响」，实际是「这次没算」**。

设计：**该有数的地方，缺席时画一条删除线 + 一个词，不画数字**：

```
毛利      118.9 万  →  62.4 万      少 56.5 万
  多花成本         + 41.2 万  〔估〕
  少收的钱         ──────────  这次没算    ← 不是 0%，不是「无变化」
  压住的应收       + 15.3 万  〔估〕
```

点「这次没算」 → 出原文：「需求侧与收入之间今天没有换算关系；凭空折算一个系数就是引擎自己发明一个数。」

#### 记号 4 · **矛盾必须自己消解**，不能两个记号打架

演习那一屏「实测格 0/4373」和逐条「实测」**必须只留一个真的**。
判据：**记号说的是这一格数据的来源，不是算法的执行模式。**
逐条那个「实测」今天说的是「算法真跑了」，那就不该用「实测」这个词 —— 换成「**算过**」，
和数据来源那一档（实 / 估 / 样）分成两列，永不同名。

#### 汇总位 · 每次推演结果**页脚一行**，点开是全部原文

```
─────────────────────────────────────────────────────────
这次推演里有 5 处需要你知道的成色 ▸        ← 一行，灰字，永远在页脚
```

点开是一个抽屉，**逐条列出，原文一字不改**，并且每条**可点回到它对应的那个数字**：

```
1. 起点读数：4373 格里 0 格是实测的     → 影响：③ 的三个金额、④ 的全部结论
   〔原文〕种子世界的 tick0 读数由本体结构派生（确定性占位），不是实测：…
2. 收入这一行这次没算                   → 影响：③ 的毛利
3. 卡点结论没有经过求解器（0 次调用）   → 影响：④ 的 6 个红点
4. 传导识别那一屏大半是示例             → 影响：④ 的传导图
5. 有 20 件事这里还试不了               → 影响：① 的事件清单
```

**为什么是「一处汇总」而不是「分散在各处」**：用户要么完全不关心（那就一行灰字，不挡路），
要么在拿这个结论去开会之前一次性全看（那就一个抽屉，全在一起，不用满屏找）。
今天是最坏的第三种：**分散在各处、每处都是段落、且看不全**。

### 4.4 用户什么时候会看到它们

| 时机 | 看到什么 |
|---|---|
| 平时读数 | **只有角标**（一个字符）+ 「估」档数字没有小数 |
| 想知道某个数的成色 | 悬浮/点那个角标 → 一句话 + 「看全部成色」 |
| 有缺席 | **必然看到**（删除线 + 「这次没算」，无法忽略） |
| 有「样」档 | **必然看到**（斜纹底，无法误读成自己的数） |
| 要拿去开会 / 要签字 | 点页脚那一行 → 全部原文，逐条带跳转 |
| 系统级警示（就绪认证没过等） | 页脚那一行**变琥珀色**，不再是横幅占第一层 |

## §5 分歧点（和第 1 轮两位专家吵在纸上）

他们从「补哪条线」出发，我从「用户怎么走」出发。下面六条是真分歧，不是措辞差异。

---

### 分歧 1 · 「A1 是唯一关键路径」—— 从用户走的路看，**它不是第一件**

**架构师原话**：「**A1 是唯一的关键路径**：它不做，B1/B2 做不了，⑤ 永远与 ② 无关」。

**我不同意的部分**：A1（让求解器看得见推演世界）在技术依赖上是对的，但**用户在第一分钟撞上的不是它**。
实测：用户在第 1 分钟撞上的是「首页六张业务语言的卡，六张全是死路」（1.1）；
第 3 分钟撞上的是「钱在屏幕最右边 150 像素里」（1.5）。**这两件都不需要 A1。**

**为什么这是真分歧**：按 A1 排第一，第一批交付之后用户打开系统，看到的还是同样的六张 403 卡、
同样挤在角落的三个数字 —— 他不会知道底下有什么变了。**「主线」这个词是用户视角的词，
它的第一次可见改善必须发生在用户点得到的地方。**

**我的排法**：
`首页六张卡能点开` → `钱搬到屏中央` → `①的输入换成事件模板` → 然后才是 A1 那一批。
前三件加起来不改一行后端。

---

### 分歧 2 · 「先修压力累加」是唯一阻塞项 —— 同意，但**它和版面必须同一批做，不许拆**

**数据专家原话**：「**先修「压力无上界累加」** —— 一处种子改动，同时解锁 ②③⑤ 三步…**这是全局唯一的阻塞项**。」

**我同意它是唯一阻塞项**，但要顶一句：**修完它，屏上仍然没有主线**。
修完之后毛利不再是 −210 万了，但那个数**还在屏幕最右边 150 像素的窄栏里**，用户照样看不见。

**而反过来更危险**：如果先做版面、把钱搬到屏幕正中央而数还是错的 ——
**我等于把一个错的、方向反的数放大到全屏**。今天它藏在角落还算不幸中的万幸。

⇒ **这两件事必须捆成一批交付，不许任何一件单独上。**
这是真分歧：两位专家把它们排成了两个不同优先级的独立项，我认为它们是**一件事的两半**。

---

### 分歧 3 · 「两个沙盘并存」是 D 档（最后）—— **我认为它是第一档**

**架构师原话**：把「两个沙盘并存」放在「**档 D · 要重画（接线改不动，属信息架构/产品决策）**」，列在 A/B/C 之后。

**我不同意的理由是实测的**（3.1）：这不是「信息架构不好看」，是**用户的输入会凭空丢**：
- 两个沙盘从不在同一个世界里（A≠B、C≠D）；
- 推演沙盘**每进一次换一个新世界**（B≠D）。

⇒ 「上一步的产物到不了下一步」正是仓主问的那句「**没有一个主线串起来所有**」的字面答案。
**这不是排版档，这是主线档。**

⚠️ 此条落在**禁令 2** 范围（沙盘信息架构），下面 §5 末尾统一标注。

---

### 分歧 4 · 「④ 卡点堵点今天能答」—— **用户点得到的那条路今天答不了**

**数据专家原话**：「**④ 全流程卡点堵点 ✅ 今天能答**（定位层面）」，依据是 `chain_impediments` 实测 17 条。

**我不同意这个定档**。17 条那个东西是真的，但**用户在沙盘里点「开始演习」拿到的是 43,468 条**（1.8 实测），
逐条形如 `obj_arinvoice_arinvoice_0_1·逾期压力 现值 3689921.19 已越过 P95 分位（95）← propagation`，
且「求解器回执（0 次调用）」。

**判据分歧**：定档要按「**用户点得到的那个东西**」定，不是按「后端能算出的最好那个东西」定。
按后者定档，会让排期以为这一步不用做，而用户面前那条路一动不动。

---

### 分歧 5 · 「61 个求解器不是负债」—— 同意，但产品口径上**54 个等于不存在**

**架构师原话**：「**61 个求解器不是负债**。它们是这套系统里唯一有真算力的部分…问题是只有 8 个连到了推演」。

**我同意「不是负债」，要补一句**：从用户视角，**演习路径上零命中的 54 个 = 不存在**。
它们既不是资产也不是负债，是**待接的线**。

**这句话的产品后果**（这才是分歧所在）：**对外口径上不许把 61 说成「我们有 61 种分析能力」**，
也不许在界面上把「求解器目录 61 个」摆成一个能力展示。
用户能点出来的那几个，才是这个产品今天有的能力。

---

### 分歧 6 · 「把 agent 放在听懂人话那一步」—— 完全同意，但**别等 agent**

**架构师原话**：「**别把 agent 放在算的路上，放在「听懂人话」那一步。**」——
这一条我不但同意，还要把它提到第一位：第 ① 步今天要用户从 **11,337 个 `obj_` 编号**里挑一个，
这一格就是「听懂人话」该站的位置。

**我要顶的那半句**：**agent 不是唯一解，也不该是第一版。**
§2 里那 8–10 条**写死的事件模板**（「［哪种料］涨价［多少］%」）今天就能做，不需要任何 LLM、
不需要 A2 那个转换器先落地，也就没有 3 分钟看门狗那一整类风险。

⇒ **先上模板（覆盖 80% 的话），agent 后补（兜住剩下 20% 的自由说法）。**
今天的排期把这一步整个押在 A2/A3 上，等于让第 ① 步在整条链最后才可用 —— 而它是用户碰到的第一格。

## §6 我判断今天做不到的

**判据：不设计一个需要不存在的数据才成立的界面。** 下面每一条都点名「所以界面上今天只能怎么写」。

---

### 6-1 · 「毛利会掉多少」这个数，**今天不能放大**

**事实**（实测 1.5）：零扰动、世界态「与基线逐项相等」，屏上已经是「毛利 118.90 → **−210.48**」。
再空推两拍变成 **−1,626.11**。而真值基线是 **+118.9 万**。

**这不是版面问题，UX 救不了它。** 我在 §2③ 设计的「三个数占屏幕正中」，
**在这个数修好之前一天都不能上** —— 上了就是把「你公司在巨亏」这句话放大到全屏。

**今天界面上只能怎么写**：维持现状层级（不放大），并在页脚汇总位第一条明写
「这几个金额今天的量级不可用，只能看方向」。**这条是 §2③ 与分歧 2 的同一件事，两处都点了名。**

---

### 6-2 · 「少收多少钱」这一行，今天只能写「这次没算」

**事实**：需求侧和收入之间今天没有换算关系，收入行恒定不动（回包自陈「凭空折算就是引擎自己发明一个系数」）。

**做不到的体验**：一个完整的「收入 − 成本 = 毛利」三行卡。
**今天只能怎么写**：收入那一行画删除线 + 「这次没算」（§4 记号 3）。
**绝对不许**显示 `0%` 或「无变化」——那是把「缺席」伪装成「结论」，业务人员必然读成后者。

---

### 6-3 · 「这个卡点会在几号发生」，今天写不出来

**事实**：会话上有 `tickDays: 1`（所以「拍」能换成「天」，见 §2①），
但卡点那一层的结论要么是本体真值上的快照（没有时间轴），要么是带拍号却没有业务落点的扫描结果。

**今天只能怎么写**：红点上只能写「**第 9 天**」，不能写「**3 月 18 号**」。
第 ③ 步的时间口径同理 —— 只能说「往后 30 天」，**不能说「这个月」**（推演走天数，财务走另一套滚动口径，两者今天没对齐）。

---

### 6-4 · 方案**不许排名、不许标推荐**

**事实**：不施加任何扰动，指标自己一路恶化 ⇒ 方案好坏取决于**谁先被评估**。
今天屏上已经有「★在推荐组合内」。

**今天只能怎么写**：三张卡**平级并排**，按用户选的一个维度（补回最多 / 花得最少 / 最快见效）排序，
**由用户点表头切换**，系统不给默认推荐。等 6-1 那件修好，再谈推荐。

---

### 6-5 · 「换成你们真数据以后会有几条卡点」，不能承诺

**事实**：17 这个数是「demo 种子恰好有 17 处越线」，换客户真数据可能 3 条也可能 300 条。

**今天只能怎么写**：界面上**不许**把「17 个卡点」这类计数当成产品能力展示（比如首页卡片写「17 个卡点待处理」）。
计数只能出现在**本次推演的结果里**，且旁边永远跟着「这次」两个字。

---

### 6-6 · 自然语言问一句就出结果 —— **本轮未验证，不下结论**

我试了「常州基地减产四成，我这个月的毛利会掉多少？」，对话框接住了但没有出结果，
浏览器报的是事件流跨源被拦（`ERR_FAILED`）。

**这大概率是我这台机器起 AgentCore 的方式，不是产品结论。**
按铁律 0.5，**本条标记为「未验证」**，不作为「做不到」的依据，也不作为「做得到」的依据。
§2① 的设计因此**不依赖它**：事件模板路线不需要自然语言也能跑通，自然语言是它的增强项。

---

### 6-7 · 首页六张卡的 403/404，我只追到「跳错键」这一层

我证到的是：导航进 `/v/risk` 正常，场景卡进 `/v/risk-board` 报 403；
后端下发的是 `{ key: "risk", renderer: "risk-board" }`，`navigation` 里有 `risk`、没有 `risk-board`；
而 `apps/frontend-shell/src/views/registry.ts:25-45` 的 `VIEW_ALIAS` 把 `risk` 解析成 `risk-board` 之后拿去跳转。

**我没有追到「这是不是还叠了一层权限配置问题」**。这一条是给架构师的**线索，不是结论**，修法归他。
从 UX 侧我只主张一件事：**这是全系统里唯一用业务语言写的六个入口，它们必须能点开**，
优先级高于所有版面工作。

⚠️ **收工时发现有人正在并行修这一条**：主工作目录里 `apps/frontend-shell/src/components/ScenarioLauncher/rankHotScenarios.ts`
在 `2026-08-27 09:16`（正是我做走查的时段）被改成用 `resolveViewKey` 判可达。
**我按范围边界没有碰它**，也**没有复验它修没修好**。
但要提醒一句：那处改的是**排序里的可达判断**（让点不开的卡排到后面），
而我实测的症状是**跳转本身落到了渲染器键上**（`/v/risk-board` → 403）。
**「排到后面」不等于「能点开」** —— 六张卡如果全被判为不可达，用户看到的仍是六张点不开的卡，
只是顺序变了。**这一条要请架构师复验：修完之后再点一次那六张卡，看是不是真进得去。**
