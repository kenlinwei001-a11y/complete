## §1 一句话结论

**沙盘是"从底往上建到了一半"的诚实产物,不是坏了。** 设计初衷正确且有野心(通用、配置驱动、诚信可信);落地策略理性——**先啃最难最诚信的引擎底座**(SimSession 状态机 + 通用逐-tick 传导核),把**面向人的顶层**(问题输入、一句场景倒推、主动指挥台、答案与业务语义、数据血缘徽标)**明确后放到"增量 4"或标为"头号诚实缺口"未闭合**。改造的任务不是再抄一遍竞品形式,而是**把每个功能重新锚到"它服务哪个决策"上**——底座真价值保留,顶层按价值补齐,纯形式砍掉。

## §2 尺子：价值优先，拒绝"copy 竞品形式"

当年沙盘对标一个竞品的三栏决策屏(左图谱·中双雷达·右 AI 指挥台,`GROUNDING-MAP §F.1`)。**对标带来两类东西,必须分开:**
- **真价值(该学)**：沿本体 link 逐 tick 传导、checkpoint/分支多时间线、采纳经审批、"须配置规则非魔法"、Temporal Trust 防未来窥视——这些是**决策能力**,竞品成品验证过。
- **纯形式(不该照搬)**：三栏布局本身、把雷达做成 3 套(structure/knowledge/behavior + 健康6维 + 信任4维)、L0-L4 台阶的黑话、抽象维度名——这些是**竞品的界面外壳**,搬过来却答不出"帮用户决策什么"。

**裁定原则(每个功能过这三问)**：
1. **它回答哪个决策问题?**(答不出 → 砍或降级)
2. **用户看完能不能行动?**(只给机制不给结论 → 改成答案优先)
3. **它是不是只是"竞品有所以我也有"?**(是 → 砍或合并)

## §4 价值优先的重构（不是照抄形式，是重锚决策）

把 §3 裁定归三档,**改造 WO 按此排,而非按竞品三栏排**:

**A · 保留(真价值底座·一行不动)**：传导核(#2)、SimSession 状态机(#3 留)、采纳→Action 正门(#5)、拓扑图与 R13 溯源(#4 留)。→ 这是沙盘立得住的地基。

**B · 改造(有价值但形式/语义错·答案优先)**：
1. **补"情景问题条"(#1+#13 合一·最高杠杆)**——一个真问题框:"常州二线停3周,交付缺口多大?"→ 分类器解析→需求图→自动配 scope+注入扰动+映射 tick↔周→跑。这一条同时解掉"没入口"和"主动指挥台没落"。
2. **答案先行(#15)**——跑完顶部横幅先给"交付缺口 X · 建议 Y",机制(DAG/tick/雷达)收进"看依据"。
3. **业务语义 + 数据血缘徽标(#7/#12)**——每个数绑单位/阈值/Δ + LIVE/合成/未校准徽标(补上沙盘唯一缺的诚信位,呼应 Data Trust)。
4. **tick↔业务时间(#6)** + **归因(#4 改)** + **分支可注入不同方案(#3 改)** + **对比换决策维(#11)**。
5. **就绪认证折成人话(#9)**、**运行历史存结论接工单(#14)**。

**C · 砍/合(纯竞品形式·无独立价值)**：
- **三套雷达 → 合并为 1 张(#10)**：竞品只 2 雷达,我方做成 3 套是形式膨胀;维度名换人话,其余收详情。**这是"拒绝 copy 形式"的标志性一刀。**
- **黑话 stepper(#9)**:保留 GATE 判据,砍掉台阶黑话展示。

## §5 升级对应（沙盘顶层缺口 = 倒推②上游 = Decision-OS 脊柱 L1）

沙盘未闭合的顶层,**和另两处是同一个缺口的三个面**:
- 沙盘"一句场景→推演"(#1) ＝ 倒推精度②的**上游 classify** ＝ Decision-OS 升级的 **L1-A RequirementGraph + classify 融合**。
- 沙盘"答案先行/入口收口"(#14/#15) ＝ **入口过多①** ＝ **L0-C console 收口**。
→ **沙盘改造不必单独造轮子**:情景问题条直接复用 `PRD-upstream-classify-precision`(融合分类器)+ `PRD-gap-analysis-engine`(需求图闭包);沙盘是这套脊柱的**第一个消费场景**(问题→需求图→what-if 推演→答案→采纳)。

## §7 配套依赖与缺口（功能 ≠ 配套·每个功能背后是全栈配套）

系统第一性:一个决策能力要有全栈配套(对象→派生属性→数据→规则→求解器→意图→技能),即 R16 倒序发育 / gap 引擎 13 类模块。沙盘的配套链与状态:

| 配套 | 作用 | 证据 | 状态 |
|---|---|---|---|
| 对象类型 / 链路 | 拓扑节点 / 传导边 | `SandboxViewConfig.nodeTypes/linkTypes` | ✅ 可 scaffold |
| **派生属性 = 状态变量** | **沙盘态载体** | `app.ts:1504` stateVars 从传导规则派生·`:1361` 只认真数值派生属性缺则退 0 | ⚠️ 须先建真数值派生属性 |
| **传导规则 PropagationRule** | **核心:沿 link 系数×延迟** | `contracts/sim.ts:38`·表 `sim_propagation_rule`(migration026) | 🔴 每租户须自建·0 条=惰性 |
| 物化对象 data | 世界态真值 | `nodeObjectIds/State` | ⚠️ demo=合成 |
| 系数校准 rule.params | 系数真值 | `coefficientRef→rule.params`(G-10) | 🔴 冷启动=默认值 |
| sim 技能/MCP(tick/act/branch) | AI 指挥台真驱动 | 当前=前端 regex `SandboxView.tsx:535` | 🔴 未注册 |
| 沙盘意图(目录) | 一句话问题路由 | S1 前提 | 🔴 无 |

**三个致命缺口**:
1. **状态变量是派生出来的**——链条"派生属性 → 传导规则引用它 → 沙盘才有态";少一环即惰性。
2. **`PropagationRule` 不在 gap 引擎 13 类覆盖里**(`provisioners.ts` 13 kind 无 propagation/state_var)——**沙盘最吃劲的配套对"检测缺什么"的引擎隐形**。→ **本节最高杠杆修复 = S0**。
3. **AI 指挥台无技能配套**(前端 regex,非 QOS 路由技能)——S1 若不补真意图+技能,又是 regex。

**如何配套(用系统自己的机制,不手搓)**:①**S0**:给 `MODULE_PROVISIONERS` 加 `propagation_rule`/`state_var` 两类 → 主 PRD `diffGap/preAnalyzeQuery` 即能诊断"这问题的推演缺 N 条传导规则/M 个派生属性" → 落 GrowthTicket。②补沙盘意图+技能(经 ONTO-SCEN 发育)。③**诚实边界**:PRD"任意行业零代码开沙盘"——渲染零代码(view-config 自动派生),**建模不是**(系数×延迟/状态变量挂哪需领域判断·autoCreatable=false);正解表述="**开箱即建(gap 倒推该建什么)+ 引导补齐**,非开箱即跑"。

## §8 页面定位:沙盘无需独立存在,应为"时序推演"意图的落地视图

**代码事实(决定性)**:`views/registry.ts` 注册的意图落地渲染器有 dashboard/risk-board/project-sim/plan-audit/plan-generate/sop-balance/order-chain 等——**它们是"意图命中→`targetView`→渲染进去"的目标**;而 **`SandboxView` 不在注册表**,是独立路由 `/v/sim-sandbox`(`App.tsx:143` 静态段),只能从导航或 what-if URL 进。

**依赖/跳转关系(核实)**:
- **上游(谁进沙盘)**:`RiskBoardView`/`ProjectSimView`/`LedgerView`/`WhatIfCalculatorCard` 经 `whatif.ts whatIfQuery` → `/v/sim-sandbox?whatif=...`;导航「推演」组;`SimInitWizard`。
- **下游(沙盘出口)**:采纳→Action 草稿(/admin/actions 审批·RL4);深链 `/admin/tickets`(缺口)。
- **同类重叠**:`project-sim` 也是推演类视图(registry.ts:10 注释),与沙盘概念重叠。

**裁定(有据)**:**沙盘不该"主要作为独立页"存在。** 它孤立于"问题→意图→渲染"主链,正是"没入口/不知道怎么用"的根因。应改为:
- **主态 · 意图落地渲染器**:`registerRenderer("sim-sandbox", …)`,让一类"**时序推演/传导 what-if**"意图(停线冲击/急单挤占/需求上调/传导预演)的 plan 带 `targetView:"sim-sandbox"` → 问题经**全局 QueryDock**(每个 /v 页常驻)命中即渲染进沙盘、情景预载。→ **"问题输入"用现成 dock,不必新造框**(呼应 S1);**从不冷开**(问了才来·配置好);**入口 −1**(收敛①);"不知道怎么用"自解(你不"用"它,你问、它答)。
- **副态 · 沙盘工作台**:保留自由探索(分支/对比/连推)为**次要模式**(暗发·power-user·从任一推演答案"展开为工作台"进入),**从一级导航降级**。

**非此即彼是错的——是主(渲染器)+ 副(工作台)混合**:业务视图渲染器没有分支/checkpoint/对比,这是沙盘独有工作台价值,保留但不作默认入口。
