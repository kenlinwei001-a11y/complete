## 一、参考产品把本体分成三层

参考产品的本体文档明确分成**语义层**（objects / properties / links）与**动力层**
（actions / functions / dynamic security），外加一圈**运营层**（对象视图 / 写回 / 分支提案 /
权限 / 索引检索 / 变更管理）。

> 原文措辞：本体是「组织的运营层，坐在已接入平台的数字资产之上，把它们和现实世界的对应物连起来」，
> 且**同时包含语义元素与动力元素**。

**这个三层划分本身就是一条结论**：只有对象和链路的「本体」不是本体，是数据字典。

| 参考产品的能力 | 本仓实测 | 判定 |

| **对象类型** Object Type | 98 类 / 12,740 对象 | ✅ |
| **属性** Property | 873 个。**量纲刚由「24 个有声明 / 849 个沉默」补到 873/873**，并新增 `scale` 区分比率与百分点 | ✅ 刚补齐 |
| **共享属性类型** Shared Property Type<br><small>可复用的属性定义，跨对象类型保持口径一致</small> | **全系统 0 个**（金丝雀：`interfaceKey` 9 命中、`DerivationSpec` 16 命中，工具是活的） | 🔴 **完全没有** |
| **链路类型** Link Type（1-1 / 1-N / N-N） | 103 条 | ✅ |

**共享属性类型缺失的直接后果**，本会话已经付过学费：
`Line.utilization`(0–100 百分点) 与 `Process.utilization`(0–1 比率) **同名不同量纲**，
消费方只能按取值范围猜；`revenueWan` / `marginWan` **名字说万元实际是亿元，差 10⁴**。
有共享属性类型，这两类错在建模期就被挡住了。

## 四、按这份盘子看，缺口排序

**阻塞级（不补，本体不成其为本体）**

1. **共享属性类型 = 0** —— 量纲/口径不一致的病根。本会话两次付费（100× 显示错、10⁴ 金额错）都源于此。
2. **10/11 事件不写世界态** —— 动力层名存实亡：改输入不改输出。
3. **「99 条切片」把 4 条真路径和 95 个存根加在一起报** —— 第一屏的数在误导人。

**结构级（补了才算企业级）**

4. **本体分支与提案流程** —— 今天改本体是直接改，没有提案/评审/发布三段。
5. **函数不是一等公民** —— 求解器与对象的绑定靠约定不靠声明，改名即断。
6. **接口只有 1 个实例** —— 机制齐全，没人用。

**可达性级（有东西但人找不到）**

7. **对象视图没有导航入口**
8. **全局搜索只索引对象、不索引页面** —— 结构性缺陷，不是配置问题
9. **9 条图谱导航只画出 5 张图**，其中 `graph-mvp` 屏上承诺「实色高亮 MVP 核心闭环」而实测与普通图谱**逐字节相同**
