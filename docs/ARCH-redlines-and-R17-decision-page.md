# 架构红线 + UX 决策单页设计原则（拟立 R17）· 大改不乱、单页看全

> 两个目标：① 给推演沙盘这类大改立**红线**（越线即停，避免把系统搞乱）；② 借鉴竞品 UX（高信息密度、单页看全、少跨页），把"**决策单页**"升为**系统本体的一条设计不变量 R17**，并反向驱动现有页改造。
> 立场：20 年架构师。红线是硬约束（有门兜底），UX 原则是设计宪法（写进本体 §5，所有决策页遵循）。

---

## 第一部分 · 十条红线（越线即停 · 每条挂门）

> 红线 ≠ 建议。**任一条违反 = 不合并、回退。** 都映射到既有不变量/门，不是新发明。

| # | 红线 | 越线表现（禁止） | 兜底门/不变量 |
|---|---|---|---|
| **RL1 本体先行** | 沙盘任何代码合并前，本体 §2/§3/§4/§8 必须先回写 | 代码先行、本体后补/不补 | `ontology:check` |
| **RL2 暗发** | 每能力挂 `sim.sandbox` entitlement，默认**关**；关=404/入口消失 | 默认开、直接影响现有租户 | features（R3） |
| **RL3 单一来源（不出双份）** | 一能力一处实现；数据源=connections、就绪=closure、审批=actions、对话=QueryDock、时钟=simclock、重算=generic_inference，**其余深链引用** | 第二个数据源管理/就绪算法/审批页/对话框 | `ia-single-source:check`（新） |
| **RL4 走正门** | 沙盘动作=模拟态（改 session，不写真值）；写真值只经 R4 | 沙盘直写结果表/绕审批 | R4 / replay 红线 |
| **RL5 去行业锁死** | 沙盘引擎+前端零业务常数；全配置驱动 | 代码出现"基地/订单/锂电"实体名 | `debattery:check`（R14） |
| **RL6 确定性** | 同基准+范围+操作序列=字节一致 | 仿真核用 `Date.now()`/随机 | R6 + 单测 |
| **RL7 CLI 对等先于 UI** | 每沙盘 op 先注册 `OPERATION_CATALOG`(cliCommand)，**CLI 先跑通再做 UI** | UI-only 能力、CLI 洼地 | `cli-parity:check`（R15） |
| **RL8 倒序发育起步** | 沙盘依赖经数据构建发动机长出（连接器/合成/runStory），**禁硬编码 seed** | 沙盘内写死实体/规则/数据 | `ontogenesis:check`（R16） |
| **RL9 additive 可回退** | 不删现有页/路由/schema；旧路径共存；关 flag 即回改前态 | 删旧视图、big-bang 重写 | 迁移 down + 共存降级 |
| **RL10 不与在建打架** | 动手前读重叠 PRD（sim-views/A8/recompute/replay/ontogenesis），**扩展不分叉** | 平行造一套、与在建冲突 | `meta:sync` + 评审 |

> 一句话：**本体先行、暗发、单一来源、走正门、零业务常数、确定性、CLI 先于 UI、倒序长出、可回退、不分叉。** 十条任一红 = 停。

## 第二部分 · UX 决策单页原则（拟立 **R17**，写进本体 §5）

> 竞品 UX 核心（8 图共性）：**一页看全决策所需——左图谱/数据 · 中推演/分析 · 右 AI 指挥台/审计，不跨页跳转。** 这与 Palantir「操作型决策在一个工作区完成」同源。立为不变量：

**R17 · 决策单页（Decision-on-one-page）**：**凡"支撑一个决策"的页面，必须让用户在一页内看到并完成：数据(what) → 推演/分析(why) → 解释/溯源(trust) → 动作(act) → AI 协助(assist)，禁止为凑齐一个决策所需信息而跨页跳转。** 密度服务决策（专家工具非消费 App），但靠**渐进披露 + 就地下钻**控制，不靠堆砌。

**R17 的 7 条操作化子原则**：

| 子原则 | 含义 | 已有抓手（复用） |
|---|---|---|
| **17.1 决策闭环单页** | 观测→分析→解释→动作→AI 在同一页 | 沙盘三栏 / 对话坞 |
| **17.2 三栏决策布局** | 左 上下文/图谱/数据 · 中 推演/时序/分析 · 右 AI 指挥台/审计 | 沙盘 / 项目推演 |
| **17.3 信息密度优先** | 计数/雷达/delta/溯源内联可见（专家工具） | RadarChart / KPI 条 |
| **17.4 就地下钻不跳页** | 点节点/KPI/行 → 原地展开(面板/overlay)，不导航走 | Provenance / DAG / order-chain 下钻 |
| **17.5 AI 指挥台贯穿** | 对话坞作常驻栏，随当前页上下文，可问可令不离页 | QueryDock（已贯穿） |
| **17.6 可溯源内联** | 每数字带来源/规则/新鲜度/信任徽章，在页内建立信任 | ⟦ref⟧ / RuleRef / trust badge（R13） |
| **17.7 配置驱动密度** | 布局声明式、按租户/角色可配，密度由 widget 组成非写死 | ViewConfig / DASH_LAYOUT / SandboxViewConfig（R14） |

## 第三部分 · 用 R17 反向驱动现有页改造（哪些页违反、怎么调）

> R17 一旦立为不变量，**现有决策页须逐一对齐**（非决策的纯 CRUD 管理页从宽，但仍守 17.4 就地下钻）。

| 现有页 | 违反点 | 按 R17 调整 |
|---|---|---|
| **任务详情 TaskDetailPage** | 用户为看「分类结果」要从答案卡**跨页跳**到详情页（你亲历） | 17.1/17.4：把分类/路由/关键 trace **内联进答案卡/对话坞**（点"详情"原地展开，不跳页） |
| **业务视图 + 对话坞** | 答案在 dock、KPI 在视图、溯源要再点——分散 | 17.1/17.2：决策视图统一三栏，dock 结果与视图数据同屏联动 |
| **风险看板 RiskBoardView** | 风险卡→对症方案→采纳→审批 多处 | 17.4：方案/采纳/工单在卡内原地完成（已部分做），接沙盘 |
| **本体建模 ModelingPage** | 数据源/建模/就绪分散 | 17.2：左数据源(连接器)·中管道·右 AI+就绪（已在新设计兑现） |
| **自成长驾驶舱 GrowthCockpit** | 就绪/缺陷/工单可能多面板分散 | 17.1：LOOP→GapReport→工单→就绪雷达 一页闭环 |
| **规划体检/方案/SOP（sim-views）** | 单发求解器视图，改参重算已有 | 17.1/17.3：升格沙盘三栏，KPI+溯源+动作同屏 |
| **管理 CRUD 页（~30）** | 多为单一职责（可保留） | 仅守 17.4：列表点行→原地详情/编辑，不跳新页 |

> 改造纪律：**沿用 RL9（additive 可回退）**——R17 改造经 ViewConfig 配置切换、按租户灰度，旧布局可回退；**不一次性重排所有页**，决策页优先、CRUD 页渐进。

## 第四部分 · 落本体 + 门

- **回写 §5**：新增 **R17 决策单页**不变量（7 子原则）；归类"设计宪法"层（与 R14 零业务常数、R15 CLI 对等并列——三者共同约束"前端怎么长"）。
- **回写 §3/§7**：新增门 **`decision-page:check`**（决策页须含 数据+推演+溯源+动作+AI 五要素的 data-testid，缺则红；静态 + 门B 真浏览器抽查）+ **`ia-single-source:check`**（RL3）。
- **回写 §8**：G-11 条目下记"UX：决策单页 R17 + 十红线治理大改"。
- **CLI 对等仍守**：R17 是前端密度原则，但每决策能力仍有 CLI（R15）——密度是 GUI 的事，能力对等不受影响。

## 第五部分 · 一句话给决策者

**红线十条把"大改不乱"变成可执行约束（越线即停、每条有门）；R17 决策单页把竞品"一页看全"升为系统设计宪法（与 R14/R15 并列），反向要求所有决策页对齐——但经 additive + 配置灰度落地，决策页优先、CRUD 页渐进、旧布局可回退。** 这样：沙盘大改既有硬约束防乱，又顺势把全系统 UX 收敛到"高密度、单页决策、就地下钻、AI 贯穿、可溯源"的统一原则——而这原则本身也是配置驱动、去行业锁死、CLI 对等的，与历史一脉相承。

> 落地顺序：先把 **R17 + 十红线**写进 `SYSTEM-ONTOLOGY.md §5/§7/§8`（增量0 本体先行的一部分，零代码）→ `ontology:check` 绿 → 之后每页改造对照 R17 与红线。
