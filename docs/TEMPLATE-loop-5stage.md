# LOOP 五阶段模板（填槽式）

> **用法**：把 `{{}}` 里的槽填掉，按阶段依次派。**每个角色只发言 2 次** ——
> 第 1 次在阶段①（出视角），第 2 次在阶段⑤（对行动清单表态）。中间三个阶段由主持方合成，
> 角色不再发言。这是硬约束，防止讨论无限延长。
>
> **⏱ 每次发言 ≤ 200 字**（仓主 2026-08-29 定）：「每次讨论 2 轮，每个角色每轮发言 1 次，
> 每次不超过 200 字」「**每个角色无需输出思考过程，只需要输出 200 字的论点和论据即可**」。
> 一次发言 = 一份产出 ≈ 200 字，**论点与论据都在里面**，没有长附录、没有逐步流水、没有思考过程。
> **数字与金丝雀嵌进论据句**，不是省掉 —— 合格句式：
> 「插单无入口：落点类型下拉只有 `Model` 1 项（金丝雀：沙盘同一控件 12,740 项，枚举可用）」。
> 只有**外部来源 URL 脚注**与**截图文件**不计入字数。
> ⚠ **这是逼角色排序，不是准他省掉金丝雀/对照实验** —— 200 字塞不下的，说明它不是最强证据。

## 🎯 题目边界 —— LOOP 是价值裁决会，不是技术评审会

> 仓主 2026-08-29 原话：「**LOOP 的核心讨论哪些功能是必须的、是有价值的，而不是讨论如何做这些功能。**」

| ✅ LOOP 要的（该不该有） | ❌ LOOP 不要的（怎么做） |
|---|---|
| 这个功能**不做**，用户会缺什么？缺得了吗？ | 它要几个人天 |
| 今天屏上有的这些，**哪几个删掉没人会发现**？ | 硬编码还是配置、要不要重 build |
| 这一行公认**必须有**的能力，我们缺哪几项？ | 缺的那项要改哪个文件第几行 |
| 换个客户时，哪些是**核心**、哪些是本行业专属可以扔 | 迁移要动多少代码 |
| 这功能**承诺了价值但没兑现** ⇒ 该补还是该删 | 它为什么没兑现（源码病因） |

**每条功能都要过这三问**（= `scripts/wo-value-check.mjs` 的三问）：
**谁会看见它 · 不做会缺什么 · 删掉会不会有人发现**。答不上就不许写进发言。

⚠ **实施成本可以提一句当分级依据，不许当讨论对象。**
「这条必须有，且今天要改源码」合法；「要改源码所以先不做」**越界** ——
做不做是价值裁决，成本只影响**排序**，不影响**该不该有**。

⚠ **本仓已踩过**：2026-08-29 派 LOOP10，五份派单里三份在问「怎么做」（人天表 / 要改几个 TS 常量 /
几步能配完），被仓主当场纠正。**形态**：「我用『建起来要多少人天』当作『这功能该不该有』的证据。」

## 五个角色（本仓改造版）

原模板的五视角是给**研究议题**设计的。软件系统要换一组，但**保留它的精髓：每个角色对一类失败免疫**。

| # | 角色 | 它对哪类失败免疫 | 对应原模板 |
|---|---|---|---|
| 1 | **使用者**（COO / 计划员…） | 「功能存在」≠「我用得上」 | PRACTITIONER |
| 2 | **建设者 / 运营负责人** | 「能用」≠「建得起来、维护得住」 | —（**本仓缺的就是这个**） |
| 3 | **怀疑者** | 「看起来对」≠「真的对」；专攻「绿测试 ≠ 能用」 | SKEPTIC |
| 4 | **实施者 / FDE** | 「我们这台机器上能跑」≠「换个客户能落地」 | ECONOMIST（换成落地成本而非资本利益） |
| 5 | **研究者** | 「我们想到的」≠「这一行的标准做法」 | ACADEMIC + HISTORIAN |

> ⚠ **研究者的问题要问对**：不是「参考产品有哪些功能」（会得到一张概念清单），
> 而是「**同类角色的一天是怎么过的、卡在哪**」。本仓吃过这个亏：一次调研只抄回概念清单，
> 整个「创建与维护」维度一个字没有。

## 阶段① · 五视角（每个角色的**第 1 次发言**）

```
你是【{{ROLE}}】。就 {{TOPIC}} 给出你的视角。评的对象是 {{ARTIFACT}}。

## 你必须亲手做，不许读代码代替
在 {{ENV}} 上**亲手走一遍你这个角色每天会做的事**，卡在哪一步就写哪一步：
想做什么 → 屏上给了什么 → 卡在哪 → 只能怎么绕（或绕不过去）。
⛔ 不许读代码去补屏上没有的东西。你是 {{ROLE}}，屏上做不到就是做不到。

## 交付：一份 ≤200 字的发言，论点和论据都在里面
- **论点**：一句话回答 {{TOPIC}}
- **论据**：2–3 条，每条**自带那个数**和**括号里的金丝雀**，必须是你亲手测的，不是转述
- **只有你会说、别的角色不会说的那一条**

⛔ **不要输出思考过程**：没有「我本来以为…后来实测…」，没有逐步操作流水，没有大表格，没有长附录。
⚠ 200 字塞不下的证据，说明它不是最强证据 —— **这条限制是逼你排序，不是准你省掉金丝雀**。
只有外部来源 URL 脚注与截图文件不计入字数（正文只提文件名，不展开）。

## 三条硬纪律
1. **金丝雀**：报「没有 / 0 命中 / 做不到」之前，先用同样方法找一个你确定存在的东西。
   找不到 ⇒ 报「**我的工具坏了**」，不许报「它不存在」。
2. **对照实验**：凡涉及计算的结论，判据不是「跑得起来吗」，而是
   「**把 X 改成 X'，Y 必须按可预言的方式变化**」。给出修前修后两个数。
3. **清单是下限不是范围**：主持方给的检查项是最低要求。
   **你必须另外找出至少 3 条主持方没列的问题** —— 找不到，说明你只是在核对清单，那不叫评审。

## 顶回去
主持方给的前提（file:line、数字、判断）**是线索不是结论**。实测与之冲突 ⇒
**以实测为准，把证据顶回来**，不许迁就。
```

## 阶段② · 矛盾地图（主持方合成，角色不发言）

> 原模板漏了这一段，补上。**它的作用是把「五个人各说各话」变成「哪几条真的打架」。**

```
基于上面五个视角，画出矛盾地图：

1. **哪两个（或更多）视角直接互相矛盾？** 逐条列出冲突，写清**具体是哪两句话在打架**。
2. **哪个视角的证据最强？哪个最弱？为什么？**
3. **哪一个问题，一旦被回答，就能解开最大的那条矛盾？**
4. **五个视角**一致同意**的是什么？**（这条很可能是真的 —— 连对手都在确认它。）
5. **哪个话题五个视角一个都没碰？**（这是整个领域的盲区，**往往是最值钱的发现**。）
```

**本仓追加两问**（原模板没有，但我们各付过一次账）：

```
6. **假一致**：哪些地方看起来五人都同意，但其实**用的是不同定义**？
   ⚠ 第 4 问会把「一致」当成真，而假一致长得和真一致一模一样。
   本仓真例：所有人都说「本体切片有 99 条」—— 而其中 95 条是 `hops=0/paths:[]` 的零跳存根，
   同一个数在两个人嘴里指两样东西，谁都没错，合起来是错的。

7. **谁被谁的前提带跑了**：有没有角色直接采信了主持方（或别的角色）给的数而没自己测？
   逐条点名。本仓实测：主持方给的六条前提被推翻四条 —— **信了的那些不会自己浮出来。**
```

## 阶段③ · 研究简报（主持方合成）

```
把五视角 + 矛盾地图合成一份简报：

1. **一段话**：给一个只有 60 秒的决策者讲清楚。要有分寸，不要只有结论。
2. **五条关键发现**，**按可靠度排序**。每条注明：哪些视角支持、哪些视角挑战、
   **证据是亲手测的还是转述的**。
3. **隐藏关联**：一条只有把五个视角摆在一起才看得见的非显然联系。
4. **可执行结论**：{{ROLE_FOR_ACTION}} 应该**换个做法**做什么？要具体到能派单。
5. **前沿问题**：哪一个问题一旦被回答，会改变我们对 {{TOPIC}} 的整个理解？
```

## 阶段④ · 自我同行评审（主持方，对自己的简报开火）

```
现在同行评审你自己刚写的简报：

1. **可信度打分**：五条关键发现各打 1–10 分，**逐条说明为什么是这个分**。
2. **最弱一环**：哪一条你最没把握？**要拿到什么具体信息才能验证它**？
3. **偏见检查**：哪个视角在合成里被过度代表了？有没有某个声音压过了别人？
4. **缺失视角**：有没有第 6 个角度，加进来会改变结论？
5. **总评**：这份简报如果交给一个严格的评审，会得几分、会被要求先改什么？

## 本仓追加的两问（原模板没有，但我们付过账）
6. **有几条结论是「转述」而不是「亲手测」的？** 逐条点名。
   本仓有过：一句「已经能编辑」转述了三轮，第四轮才有人亲手去点，发现是对的 ——
   **对不对是运气，没人验才是问题**。
7. **哪几条结论建立在主持方给的前提上，而那个前提没被任何人复核？**
   本仓有过：主持方给的六条前提，被实测推翻四条。
```

## 阶段⑤ · 结论与行动清单（每个角色的**第 2 次发言**）

```
【主持方】先出行动清单，每条含：
- 做什么（具体到能派单）
- **谁会看见它 · 前后差什么（两个数）· 不做会怎样**
  ⇒ 这三问必须过 `node scripts/wo-value-check.mjs`，答不上来的条目**不许进清单**
- 分级：不做则{{TOPIC}}不成立 / 做了才算交付级 / 能忍

【每个角色第 2 次发言，只说两件事，不许重复阶段①】
1. **清单里与你相关的条目，你同意还是反对** —— 反对要给替代方案，不是只说「不行」。
2. **清单漏了什么你在阶段①说过、但被合成时丢掉的** —— 点名哪一条被丢了。

⛔ 到此为止。角色不再发言，主持方定稿。
```

## 为什么加「每角色 2 次」这条限制

不只是防止讨论太长。**两次发言的位置是有讲究的**：

- **第 1 次在看到别人之前** —— 保住独立性。五个人同时看到彼此的观点会趋同，
  而 LOOP 的全部价值在于**他们不趋同**。
- **第 2 次在看过矛盾地图和简报之后** —— 这时他才知道自己和谁打架、
  自己哪条被合成时丢了。**这一次的信息量远高于让他中途插三次嘴。**

## 本仓已知的三个坑（写进模板，防复发）

1. **角色只覆盖消费侧**。本仓 LOOP 跑了四轮（COO / UX / 数据经理 / 后端）都在问「好不好用」，
   **没有一个角色的职责是「把这东西建起来」** ⇒「建不起来」这整个维度从来没人看。
   **五个角色里必须有生产侧（建设者/运营）和实施侧（FDE）。**

2. **主持方的清单会压制角色**。本仓实测：给 UX 六项要量的，他就量了那六项；
   而 COO 那轮没被列死，他自己设计出「+15% → +100% 对照实验」，
   **那是全轮最重的发现**。⇒ 阶段① 的「另找 3 条」是硬约束不是客套。

3. **没跑过 LOOP 的页面就是 demo 级**。这不是巧合是因果 ——
   本仓跑过 LOOP 的页面（决策台）实测 0 个 `<12px`、假控件 0、诚实位三态齐；
   没跑过的那七个面被仓主一句「都是垃圾，只是 demo 级」。
   **派任何开发单之前，先确认这个页面跑过 LOOP 没有。**
