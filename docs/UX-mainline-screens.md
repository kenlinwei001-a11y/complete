## §1 · 顶层 5 项各自的第一屏

**共同硬规**（五项都适用，下面不再重复）：

- **一屏不滚动**（1600×900）。滚动条以下的东西一律当作「第二层」，不进本节的信息点计数。
- **信息点** = 用户要单独读一次的东西（一个数 / 一条结论 / 一个名字）。**不是元素数。**
- **动作按钮 ≤3 个，动词开头，每个后面跟一个决策窗口**（「还剩 N 天」或「今天就得动」）。
  ⛔ 不许写「查看」「分析」「去推演」—— 那三个词是浏览不是决策。
- 页脚永远一行灰字：**「这一屏有 N 处成色你需要知道 ▸」**（§3）。它不占版面预算。

## §2 · 主线五步的逐屏规格（核心）

**总规则**

- 五步 **全在「推演与对策」这一页**上，是同一屏上的五个区，**不是五个页面**。
  用户在第 ③ 步改一个数，第 ①④⑤ 区**当场跟着变，位置不丢**。
- 每一步 **≤5 个信息点**、**1 个继续动作**（第 ⑤ 步除外，它是四栏并排）。
- 整条主线不出现：`扰动 / 推演 / 传导 / 世界 / 拍 / tick / 张力 / 敞口 / 落点 / 求解器 / 状态变量`。
  **「拍」一律写「天」**（实测所有会话 `tickDays: 1`，一拍就是一天）。

## §3 · 诚实位的记号体系

### 3.0 前提：一个诚实标注都不许删

今天的问题**不是标得太多，是标的形态错了** —— 它是**段落**，且和数字**同级**。实测三处：

1. 统一推演控制台上，同一段 **87 字**的成色说明**一屏重复 5 遍**（每张指标卡各一份）；
   卡上数字占 3 行，这段话占 12 行。
2. 卡点页 17 条结论，每一条底下都跟着**同样两句**：

**F · 数字写法本身分档**（比角标更早被看见，而且零组件成本）

### 3.3 「没数」必须占位置，不许显示成 0 或「无变化」

**这是对签字的人最危险的一类。** 实测两处：

- 归因接口传 `gross_profit` 回 `{"target":112,"actual":118.9,"gap":-6.9,"noGap":true,"levels":[],"atomicLeaves":[]}`
  ⇒ 屏上若画成一张空白卡，会被读成「毛利没有问题」。
- 三个基地（江门 / 邯郸 / 自贡）的敞口 `status = EMPTY`，若显示成「0 亿」，会被读成「这三个基地很安全」。
  而接口自己写的原因是：「该批窗口内无订单——**无分母不报准时率（不回落 0%/100%）**」。

**做法**：

```
   交不出去的货    31.1 亿
   现金差多少      2 亿
   毛利差多少      ─────  这次算不出来是谁害的
   ↑ 点它 → 原文：「毛利今天没有超出目标，引擎只对缺口做归因，
                    所以这一格是空的，不是没有问题。」
```

> **今天引擎在这件事上做得比界面好。** 它宁可回一句
> 「本窗无产能缺口（可用产能覆盖在产+未来订单）→ 不存在"自然消化天数"这件事，**不编一个数**」
> 也不回落成 0。**这份克制必须原样传到屏上，而不是在界面层被折成一个 0。**

   〔原文〕枚举已跑完，有效候选 0 个（探了 10 个杠杆锚点 / 34 次试算），

## §6 · 做不到的

**判据：不设计一个需要不存在的数据才成立的界面。** 每条都点名「所以界面上今天只能怎么写」。

### 6-1 · 「毛利被哪些因素影响」—— 今天答不了

**事实**（我今天亲手跑的）：归因接口传 `gross_profit` 回
`{"key":"gross_profit","target":112,"actual":118.9,"gap":-6.9,"noGap":true,"levels":[],"atomicLeaves":[]}`；
传 `gm_rate` 回 `{"target":16,"actual":17,"gap":-1,"noGap":true,"levels":[],"atomicLeaves":[]}`。
**金丝雀**：同一接口传 `ess_attain` 回 `levels[0].label = "基地"` 非空、传 `cash` 回 `levels` 非空
⇒ **是真 0，不是接口坏了。**

**成因（只报到我证到的这一层）**：这套归因只对**缺口**做分解，而毛利今天是**超额**的（118.9 > 112），
`noGap: true` 是引擎自己标的。

**界面上今天只能怎么写**：毛利**不进经营现状那三个大数**；若出现在归因区，那一格画删除线 +
「这次算不出来是谁害的」，点开给原文。**绝不许画成空白卡或 0。**

**替代**：今天能挂上因子的财务指标只有**经营现金**（3 条，单位是亿）。§1.1 的归因区因此以现金为主角。

### 6-2 · 「出事后几天波及谁」—— 逐跳的时间给不出来

**事实**：传导边 42 条，`delayTicks` **只有 0 和 1 两个取值**（27 条是 0、15 条是 1），一步 = 一天；
全图 44 节点、8 个根源、最长 8 跳，而**最长累计传播时间 = 2 天**；
所有（根源→节点）对里 33 对是 0 天。最刺眼的一条：
`材料涨价 → 型号成本 → 订单成本 → 客户应收压力` = **0 天**。
（我今天在沙盘右栏逐条复见了这些边，逐字如 `Model.costPressure —model_demanded_by_order→ Order.costPressure` `系数 0.9 · 延迟 0声明值`。）

**为什么这是「做不到」而不是「做得糙」**：真实供应链里，供应商断供到影响生产之间隔着安全库存，
是**十几天**的量级；这张图会说**当天**。**量级差一个数量级的时间轴，画出来就是错的。**

**界面上今天只能怎么写**：
- **可以画**：链条本身（谁影响谁、几跳、经过哪些环节）—— 42 条边、8 个根源是真的，且有真名字。
- **不许画**：任何形式的「隔 N 天」时间轴、任何把跳数标成天数的坐标。
- **屏上写法**：`供应商交期 ▸ 物料短缺 ▸ 采购加急 ▸ 清关排队`（**用箭头，不用天数刻度**），
  下面一行灰字：「这条链上每一环隔多久，今天还测不出来」。

### 6-3 · 「按你刚输入的事重算首屏三个数」—— 今天这条线是断的

**事实**：§1.1 那三个数来自 30 天风险窗口这条线（`risk_timeline`），
而用户在第 ① 步输入的事情走的是推演那条线。**两条线今天不共享结果** ——
输入之后，三个数不会跟着变。

**界面上今天只能怎么写**：第 ① 步的〔算一下〕**今天只能重算它自己那条线**。
在两条线接通之前，**经营现状那三个数旁边不许出现「按你刚才输入的重算」这类承诺**。

⇒ 这是我认为最该优先接的一条线，但它是工程排期的事，**此处只点名「设计不许假装它已经通了」**。

### 6-4 · 方案不许排名、不许标推荐

**事实**：今天真正逐候选试算出来的 12 个方案，代价 / 周期 / 风险 / 敞口 / 可逆 **五维全是空的**；
而带六维的那三张卡，引擎自陈「**恒 3 条·任何 metricKey 都一样**」。
叠加另一条：不施加任何扰动，指标自己一路恶化 ⇒ **方案好坏取决于谁先被评估**。

**界面上今天只能怎么写**：三张卡**平级并排**，按用户点的表头（多久见效 / 代价 / 风险）排序，
**系统不给默认推荐、不标星**。今天屏上已经有的「★在推荐组合内」**要撤掉**。

### 6-5 · 「六维」放不进第 ⑤ 步

**事实**：同 6-4。**要六维，就得编三维。**
引擎自己写了为什么不合并：「合并就得替它们编数，而编出来的数会被比对矩阵与推荐组合当真用」。

**界面上今天只能怎么写**：**只上三维真的**（多久见效 / 代价档 / 风险档），不上六维半真的。
这是我和「决策清单要六维」那一方的**真分歧**：他要决策完整性，我要每一格都站得住。

### 6-6 · 「毛利差多少」这个数今天不能放大

**事实**：零扰动、世界态「与基线逐项相等」，屏上已经是「毛利 118.90 → **−210.48**」；
再空推两天变成 **−1,532.13**（跌 1,388%）。而 CEO 那轮实测：
**「什么都不做」「常州负载拉满 100」「施加 3 条扰动」三组，三个 tick 的毛利逐位相同。**

**这不是版面问题，UX 救不了它。**
§2③ 设计的「三个数占屏幕正中」，**在这个数修好之前一天都不能上** ——
上了就是把「你公司在巨亏」这句话放大到全屏。今天它藏在页面下方 3,666px 处算不幸中的万幸。

**界面上今天只能怎么写**：维持现状层级（不放大），并在页脚汇总位第一条明写
「**这几个金额今天的量级不可用，只能看方向**」。

### 6-7 · 「少收多少钱」这一行，今天只能写「这次没算」

**事实**：需求侧和收入之间今天没有换算关系，收入行恒定不动
（回包自陈「凭空折算就是引擎自己发明一个系数」）。

**做不到的体验**：一个完整的「收入 − 成本 = 毛利」三行卡。
**今天只能怎么写**：收入那一行画删除线 + 「这次没算」（§3.3）。
**绝对不许**显示 `0%` 或「无变化」。

### 6-8 · 「这个卡点会在几号发生」写不出来

**事实**：会话上有 `tickDays: 1`（所以「拍」能换成「天」），
但卡点那一层的结论要么是快照（没有时间轴），要么是带天号却没有业务落点的扫描结果。

**今天只能怎么写**：红点上只能写「**第 14 天**」，不能写「**6 月 24 号**」。
第 ③ 步的时间口径同理 —— 只能说「往后 30 天」，**不能说「这个月」**。

### 6-9 · 「换成你们真数据以后会是什么样」—— 不能承诺

**事实**：17 这个数是「这份种子数据恰好扫出 17 处越线」；8 张基地卡里 4 张标 `LIVE` 4 张标 `MOCK`，
但**八张全部带合成血缘**。31.1 亿、264 天、第 14 天，全部建立在同一份合成数据上。

**今天只能怎么写**：这些计数**只能出现在「本次结果」里**，旁边永远跟着「这次」两个字；
**不许**把「17 个卡点」「31.1 亿敞口」当成产品能力展示（比如首页写「17 个卡点待处理」）。
页脚成色抽屉第 1 条必须写明这一点。

### 6-10 · 我没有验证过非 admin 角色

**事实**：本轮全部实测在 `demo / admin`（admin + planner + catalog_admin）下完成。
后端按角色下发不同的 `navigation`（今天 51 条）/ `views`（33 条）。

**所以**：**§1 的顶层 5 项对 `planner` 和 `base_manager:常州` 是否仍然成立，我没量过。**
落地前必须按角色各走一遍（尤其第 5 项「系统后台」对 `base_manager` 应当整个不出现，
那样顶层就只剩 4 项 —— 这可能反而更好，但我没实测，不写进结论）。
