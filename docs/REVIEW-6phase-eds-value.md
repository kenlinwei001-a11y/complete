# REVIEW · 6-phase 企业数据集(EDS)生成规范 · 对平台的价值与"三条道"归位

> **这是什么**:评审用户提交的 `系统数据.docx`(Phase1-6 企业数据集标准:企业主数据→产品工程→制造执行→决策优化→决策运行时→运行时基础设施,每 phase 附 LLM 生成提示词)对**当前平台**的价值,并把它的每类产出**归到三条性质不同的道**上,让 dev 一眼看清"哪些是模拟导入进库、哪些是平台从字段派生生成、哪些是作为系统能力装载"。
> **一句话**:**Phase1-3 高价值(走"模拟导入"道)· 本体/切片/决策字段应走"派生生成"道(不是直导预制本体)· Phase4-6 大部分是平台自我本体,属"能力装载/设计参考"道,误当数据导入=类别错误。**
> **状态**:评审稿。锚点已核对(`complete` 分支 · `modeling.ts`/`battery.ts`/母体行号 · `2026-07`)。

## §1 结论 + 三条道框架(本文核心)

用户提出的关键区分——**"哪些是模拟导入进系统、哪些是基于导入字段做的生成、哪些是真的作为系统能力导入"**——正是把这份 6-phase 规范讲清楚的最好尺子。三条道**性质不同、进系统的方式不同、可见位置不同**:

| 道 | 名 | 进系统方式 | 前端可见 | 后端可见 | 典型物 |
|---|---|---|---|---|---|
| **A** | 🟦 **模拟导入(记录进库)** | 当客户数据**导入** → RawDataset → 派生对象 | ✅ 对象列表/详情/台账 | ✅ `objects`/`raw_datasets` 表可查(不写死) | Phase1-3 主数据+事务表 |
| **B** | 🟩 **基于导入字段派生生成** | 平台从 A 的**记录+外键算出来**(非导入) | ✅ 本体图/切片/驾驶舱 | ✅ `ontology_types`/`link_types`/派生属性 | 本体/关系/切片/决策派生字段 |
| **C** | 🟧 **真作为系统能力装载** | 可执行制品**在平台内生成/审核晋升**(非当数据导入) | ✅ 求解器审核台/Agent 台 | ✅ `solver_artifacts`/Agent runtime | 求解器/模拟器/Agent/MCP/Skill/Workflow |

**三条道的铁律差异**:
- **A 是"导入"**——数据**原样进库**,前后端可见,像客户真导数据(已验证基线:上传→物化→查 `F001=51` 不写死)。
- **B 是"生成/派生"——不是导入**。本体、切片、决策字段是平台**从 A 的字段+外键确定性算出来的**(`deriveModelingSuggestion`)。**❌ 直接导入 Phase5 的 `objects.json` 当本体 = 绕过派生 = 反模式**(切片易空壳)。这正是用户一直强调的"**真正基于数据字段生成切片,而不是把切片直接导入**"。
- **C 是"装载能力"——既不是导入数据、也不是从字段派生**。求解器/模拟器是**可执行制品**;Agent/MCP/Skill/Workflow 是**平台自我本体**(母体 §2.H)。生成器/模拟器本身**留外部不进系统**(R14),只有它的产出走 A/B。

## §2 三条道逐道详解

### 🟦 道 A · 模拟导入到系统(记录进库·前后端可见)
- **定义**:把外部生成的企业数据当**客户数据**导入——落 `RawDataset`(原始行)→ 派生成对象实例,前端对象台账可看、后端数据库可查,**零写死**(R14)、可溯源到 rawDatasetId(R13)。
- **归此道**:Phase1(基地/车间/产线/设备/产品族/产品/物料/BOM/客户/供应商/仓库/日历…18 表)· Phase2(BOM主表/明细/物料替代/工艺路线/工序/制造能力…15 表)· Phase3(订单/报工/WIP/三类库存/库存流水/设备状态/停机/技能矩阵/物流/异常/KPI…24 表)。
- **判据**:它是**世界的记录**(有什么、正在发生什么),不是平台该算的结论。
- **走哪个闸**:**G1 多表 FK 批量导入**(`PRD-enterprise-dataset-import.md`)。Phase1 的"外键关系总表"直接喂 `detectFkCandidates`。
- **可见性验收**:导入后前端对象列表出现基地/产线/设备;后端 `objects` 表按 type 查得到真行数(green→red:删源→报孤儿 R-NO-ORPHAN-SOURCE)。

### 🟩 道 B · 基于导入字段派生生成(平台算·非导入)
- **定义**:平台**从道 A 的记录字段 + 外键 + 唯一度**,确定性**派生**出本体结构与决策量——**这些东西不导入,是算出来的**。
- **归此道**:
  - **本体对象类型/主键/属性** ← `deriveModelingSuggestion`(`modeling.ts:86`,主键=唯一率≥0.95 字段)。
  - **关系 LinkType** ← `detectFkCandidates`(`modeling.ts:23`,值集包含度≥0.9 + 目标唯一率≥0.95 → ref+LinkType)。
  - **切片 SliceSpec** ← 从派生本体生成(修空壳后真 resolve,非空 paths)。
  - **决策派生字段**(util/bottleneck/costBreakdown/oee_current…)← 派生引擎从道 A 真记录算,**换掉 battery.ts 的 hash 假值**(G4·治假推演源头)。
- **判据**:它能**从记录+关系推出来**,就该派生,不该导入。
- **走哪个闸**:导入(A)之后**平台派生**;**G4** 换假值。Phase5 的 `objects.json/relations.json` **只当派生结果的校验 oracle**(比对派生对不对),**不当导入源**。
- **⚠ 红线**:走 **G2 直接导入 Phase5 预制本体 = 违背用户"真正基于字段生成"的诉求 = 反模式**。G2 本体直导仅适用于"客户已有成熟本体、且愿放弃再派生"的场景,不适用于"想让平台从主数据长出本体"。

### 🟧 道 C · 真作为系统能力装载(可执行/自我本体·非数据)
- **定义**:既不是记录、也不是从字段派生,而是**系统的机器本身**——可执行求解器、模拟器、以及 Agent/MCP/Skill/Workflow 运行时。
- **归此道 + 各自处理**:
  - **生成器 / 模拟器本身**(6-phase EDS generator·Stage 3.15):**留外部,不进系统**(R14)。平台是下游决策引擎,不吞生成器逻辑。只有其**产出**走 A/B。
  - **求解器 Solver**(Phase4 的 Solver 逻辑/约束):平台内**生成为 SolverArtifact 并审核晋升**(A18 PROVISIONAL→GOVERNED,带接地校验拒绝编造实体);**❌ 不把 Phase4 的"Solver 结果/Simulation 结果"当数据导入**(那是让平台自己算的,导入=假绿)。
  - **Phase5/6 Agent/MCP/Skill/Workflow/Runtime/审计/权限**:**已是平台自我本体**(母体 §2.H 交互编排域)。**不导入**——当作**母体设计对照清单**:逐条查平台是否已覆盖(如数据血缘、Agent Trace、OLS 权限),缺的进母体断点 G,不是进导入管线。
- **判据**:它是**会跑的东西**或**平台运行时自己产生的东西** → 装载/自持,不导入。

## §4 逐-Phase 价值评分(造合成数据 / 生成本体)

| Phase | 造合成数据 | 生成本体 | 净判 |
|---|---|---|---|
| 1 企业主数据 | **高**(主数据骨架) | **高**(FK 总表喂派生) | 走 A→B,最高价值 |
| 2 产品工程 | **高**(Solver 核心输入) | **高** | 走 A→B |
| 3 制造执行 | **高**(WIP/库存流水/停机=治 hash 真原料) | 中 | 走 A+G4 |
| 4 决策优化 | 中(仅输入侧) | 中 | 输入 A;结论 C 别导入 |
| 5 决策运行时 | 低 | **参考**(对照母体查缺) | 道 C·别导入 |
| 6 运行时基础设施 | 低 | **参考** | 道 C·别导入 |

**Q1 造合成数据 = 有条件价值(3.5/5)**:Phase1-3 因果闭环补上 battery.ts 缺的(WIP/库存流水/停机/技能矩阵/换型/时间连续),是更好的 bootstrap/演示/压测数据集;但必须走"外部生成→导入"(R14),且平台已把 synthetic 定死为 bootstrap 源·不做运营态真实数据替身(母体自我本体登记),天花板明确。
**Q2 从主数据生成本体 = 高价值(4.5/5)**:Phase1 主数据+外键关系总表是 `deriveModelingSuggestion` 的理想输入(这就是"真正基于字段派生本体");唯一岔路是别走 G2 直导 Phase5 预制本体。

## §5 类别边界警告(最易踩的坑)
Phase4 的 Solver/Simulation **结果**、Phase5 **全部**、Phase6 **全部**,描述的是**平台运行时自己产生/自己拥有的东西**。把它们当"要生成并导入的数据",等于**让客户导入平台该自己算、自己持有的运行时**——这会**把"假绿"合法化**(导入一份预制 Solver 结果冒充真结论)。母体铁证:Agent/Skill/MCP=§2.H 自我本体;synthetic=bootstrap 不做运营替身;决策数字经本体算出零写死;A18 接地校验拒绝编造实体。**Phase5/6 正确用法 = 拿它逐条对照母体 §2/§8 查平台自我本体有没有覆盖(数据血缘/Agent Trace/审计/OLS),缺的进断点 G,不是进导入。**
