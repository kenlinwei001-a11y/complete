# SOP · 测试分层（L1 变更面 / L2 集成门 / L3 漂移巡检）

> **上位法**：仓主 2026-09-16 两句原话（「我认为你测试的模式，太传统了」/「花了几个小时测试，结果失败行都是 0，
> 岂不是浪费了很多时间？有没有其他测试模式，避免按照顺序从头测试」）＋ 铁律 2（并发画像纪律）＋ 铁律 1.5（对照实验判据）。
> **配套工具**：**无**。本文零新增门 / 零新增棘轮 / 零新增基线 JSON（禁令 3）——
> 它是「什么时候跑什么」的调度纪律，不是一道新门。既有四包门作为 canonical 准入的地位**不变**（见 §5）。

---

## 0 · 这份 SOP 为什么存在

WO-REAL-CELLS 验收那天：datacore 全量 362 文件 / 2,557 条跑了 **3.1h**（负载 200–330），
抓到的 4 条红**没有一条与那批 diff 有关**（3 条负载抖落 + 1 条基树前置红）。
全量门回答的是「**4 个文件的 diff 弄坏了什么**」这个局部问题，却重证了 2,537 条早已绿的测试。

形态句（铁律 0.6 句式）：

> **「我用『全量绿』当作『这次 diff 安全』的证据，而全量的 99% 并不度量这次 diff。」**

## 1 · 三层各回答一个问题（拿错层 = 拿错证据）

| 层 | 回答的问题 | 内容 | 何时跑 | 墙钟量级 |
|---|---|---|---|---|
| **L1 变更面** | 我**这次改的东西**坏了吗 | ① `vitest related <改动的 src 文件>` ∪ ② 本单交付物自己的接缝测试 ∪ ③ 守门员/金丝雀清单 | **每次交付增量**（每提交一批文件） | 分钟级 |
| **L2 集成门** | 这棵树**能进 canonical** 吗 | 四包全量（`pnpm -r build && pnpm -r --workspace-concurrency=1 test`），`--maxWorkers=2`，**安静时间窗**（§4） | 并 canonical 前，一次 | 小时级 |
| **L3 漂移巡检** | 仓里有没有谁**悄悄坏了** | 全量定时扫（内容同 L2，目的不同） | 定期 / 大收编后 | 小时级（不挡交付） |

**L3 的存在理由 = ⑤b 那类红**：基树前置红与任何在跑单的 diff 都无关，不全量扫就永远没人知道。
L3 抓的红**逐条归属**（隔离复跑 + 基树对照），记台账，⛔ 不许记在当时正在交付的单头上 ——
「全量里红了」与「你的 diff 弄红了」是两个命题（形态句同上）。

## 2 · L1 操作判据

1. **变更面 = diff 触及的 src 文件 → 受影响测试文件**。首选 `npx vitest related <file...>`；
   拿不到可靠 related 集合时手工圈定（本单 seam + 直接 import 链上的测试文件），并在报告里明写圈定依据。
2. **本单交付物自己的接缝测试永远在内**（SEAM-GATE：绿测试 ≠ 能用，断在接缝）。
3. **守门员/金丝雀永远在内**（本仓惯例：本单触及的机制都有对应守门文件）。
4. L1 全绿 RC=0 才许报「交付件绿」；⛔ L1 绿**不构成**并 canonical 的资格（那是 L2 的判据）。

## 3 · L1 的诚实边界（related 会退化，别装没退化）

`vitest related` 按 import 图反查。本仓核心文件（如 `synthetic/battery.ts` 经 `helpers.ts`
被几乎全套件传递引入）的 related 集合 ≈ **全集** —— 此时「变更面」名存实亡。
判据：related 命中数 > 套件 50% ⇒ 在报告里**明写「related 已退化为全集」**，
L1 实际跑 = 本单 seam ∪ 守门员 ∪ 金丝雀，⛔ 不许声称「跑了变更面测试」。

## 4 · 安静时间窗纪律（L2/L3 专用）

实测依据（2026-09-16）：同一测试文件负载下 187s vs 平静 79s = **2.4×**；
负载来自门外的用户应用（会议/窗口服务），4 核机 `maxWorkers` 默认吃满即自伤。

1. 起 L2/L3 前 `uptime` 看 load avg：高负载 ⇒ 要么等窗口，要么报告里**预告耗时上限与抖落风险**。
2. 窗内 `--maxWorkers=2`，全机同时只许一个 datacore vitest（铁律 2 重画像纪律）。
3. **负载抖落红的判据**：全量红 + 平静机隔离复跑绿 ⇒ 记「抖落」，不归咎交付单；
   隔离复跑**同错** ⇒ 基树对照（base worktree 复跑），基树同错 = 前置红，转 L3 台账派修。

## 5 · 与既有纪律的关系（不冲突声明）

- 四包门仍是 **canonical 准入**（铁律 / LOOP 派发复验纪律不变）：**没有 L2 绿，不许推 canonical。**
- L1/L3 不改准入，只改**节奏**：交付途中不空等全量（铁律 2：被非产出动作阻塞的只有它自己），
  漂移不归咎无辜 diff。
- 本 SOP 不强制任何 CI 钩子、不产生新门；违反本文 = 调度失误，按铁律 2 记账，不按门红处理。

## 6 · 结构性大杠杆：确定性快照还原（已派 WO-SNAPSHOT-RESTORE）

R6 已证：同 (industry, scale, seed) 重铺世界**字节级一致** ⇒ 各测试文件的世界合成是**纯函数重放**。
把「每个文件自己 seed 一遍（几十秒到几分钟）」换成「seed 一次、序列化、各文件还原字节」，
套件墙钟 **÷5–10**。落地后 L1/L2 的墙钟进一步降，本层表不必改 —— 它省的是每层的成本，不是层本身。
