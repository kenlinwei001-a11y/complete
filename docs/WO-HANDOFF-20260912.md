# 所有单通用的开工纪律（每单都要照做，不再逐单重复）

## A · 自证你的树是新的

**本仓的 dev 工作树一律从旧树起步 —— 连续 12 个 agent 全部撞上，落后数千提交。别信派单里写的坐标，自己测：**

```bash
PIN=origin/claude/inspiring-gates-aqczjg
git fetch origin
git rev-parse --short HEAD
wc -l apps/datacore/src/synthetic/battery.ts   # 新树 ≈7053 行；≈1249 行 = 旧树，必须重开
git merge-base --is-ancestor HEAD $PIN && echo "落后⇒必须重开" || echo "不落后"
```

**报告头必须回显这三个数。**

> 不纠正的后果是实的：同一个问题在两棵树上得出「20 单」与「500 单」两个都正确、**差 25 倍**的答案。

## B · 第一条命令就建分支 + 空提交 + push

```bash
git checkout -B <wo-name> origin/claude/inspiring-gates-aqczjg
git commit --allow-empty -m "WIP·<wo-name> 起点"
git push -u origin HEAD:refs/heads/claude/handoff-<wo-name>
```

之后**每改完一个文件**就 `git add -A && git commit && git push` —— 不是「写完一个功能」，更不是「测试跑绿了再推」。提交信息写 `WIP·未验` 都行。

> **为什么是第一步不是收尾**：本仓三次真丢过整天产出，最近一次 6 张单被容器重启杀掉、3 张全丢 —— 而那 5 张派单里都白纸黑字写了「立刻 push」。把判断题变成肌肉记忆。

## C · 环境前置

```bash
pnpm install --prefer-offline
pnpm --filter @platform/contracts build
pnpm --filter @platform/llm-adapters build
```

不建会报 `Failed to resolve entry for package "@platform/contracts"` —— **与本单无关的假红**，极易误判成契约包坏了。

## D · 坐标是线索不是结论

把单里给的 `file:line` **原文读出来**，各写成一句「**今天的行为是 X，应该是 Y**」。**写不出来别动手。**

若实测发现**已经做了** ⇒ **停手，把证据（file + 符号 + 触发条件）顶回来，改台账不改代码。**

> 本仓真发生过：判某道门今天做不了，实际那个函数**早已存在且接了两处** ⇒ 把工作量从「接一条线」错报成「造一道门」，直接歪掉排期。同类事故一天内发生过 **5 次**。

## E · 测试只跑三样，⛔ 不跑全量

| | 跑什么 |
|---|---|
| ① | **自己的接缝门** —— 驱动接缝的**组合**测试，不是各半 unit |
| ② | **变异反证** —— 把实现改坏 ⇒ 断言**必须红**，记 RC；还原 ⇒ 必须净，记 RC。**报两个数** |
| ③ | **爆炸半径** —— 只跑 import 了你改动文件的那批，**逐个给 RC** |

全量是**并入正线的门**，由收编方在合成好的集成线上跑一次。

> **一道从没红过的门，绿了不说明任何事。** 没有变异反证那两个数 = 这道门是装饰品。

**退出码写法**：
```bash
cmd > out.log 2>&1; RC=$?
```
⛔ **禁止** `cmd | tail -n; echo "EXIT=$?"` —— `$?` 取的是 `tail` 的退出码（**恒 0**）。本仓曾据此把一个**编译失败**的提交判为「BUILD 通过」并入正线，直到部署方 build 失败才暴露。失败时打印 `error TS|FAIL|AssertionError` **原文**，不许只 tail 几行把错误挤掉。

## F · 对照实验：四个数，缺一个不算交付

**不是问「跑不跑得起来」，是问：「把 X 改成 X'，Y 必须按某个可预言的方式变。」**

每单的判据写在各自段落里。**必须给四个数**：修改前两个、修改后两个。

⚠ 这条判据**不需要读一行代码就能设计** —— 它来自业务常识。一直在读代码却设计不出这种判据，本身就是信号。

⚠ **改前那一组要把文件 checkout 回基点真跑，不许估。**

## G · 金丝雀：报否定结论前必跑

报「没有 / 零调用方 / 做不到 / 整条缺」之前：

1. **沿调用链再追至少一层** —— grep 是线索不是结论。注意这四种间接形态，**grep 一次都看不见**：
   **字符串键分发** · re-export · 高阶函数 / 依赖注入 · 事件订阅
2. **先跑一个已知必中的样例**。金丝雀不中 ⇒ 报「**量法坏了**」，⛔ 不许报「不存在 / 零命中 / 代码干净」
3. 报告里**每一条否定结论都必须附金丝雀的命中证据**

> **「我没找到」和「它不存在」是两个不同的命题。**

⚠ **已知工具坑**：含通配的 pathspec **不当目录前缀用** —— `git grep -- 'apps/*/src'` **恒 0 命中**，要写 `apps/*/src/*`。

## H · 四态（混了必修错地方）

| 态 | 判据 | 修法 |
|---|---|---|
| ① 没接线 | src 调用方为空（**只有 test 引用 = 已排练，不是已实现**） | 接线 |
| ② 接了线没数据 | 有 src 调用方，但输入恒空/恒假，分支从未进入 | 补数据或删死分支 |
| ③ 接了线接错地方 | 挂在错误的路径上 | 补挂载点 |
| ④ **接对了、跑通了、但算错了** | 链路完整、屏上有数、**测试全绿**，但公式缺项/口径不对 | 改公式/改口径 |

⚠ **前三态查不出第四态。** 实例：`amount = coeff × sourceVal × factor` **没有用量项** ⇒ 碳酸锂（BOM 大头）与铝箔（很小一块）各涨 15%，得到**完全相同**的成本压力。

## I · 端口与并发

- **本机没有 `ss` / `netstat`** —— 探针的沉默**不等于**端口空闲。**唯一可靠判法是真去 bind**（`net.createServer().listen()`）。4001/4002/5173 大概率被占，**自己挑冷门口**。
  起服务后必须**自证「我连的是我自己起的那一个」**（回显端口 + 一个只有你这次改动/种子才有的字段）。
  > 真发生过：探针报「空闲」，实际被别的进程占着 ⇒ **读了别人遗留的旧服务**，对**自己的代码**下了错误结论。
  ⚠ 进程表里可能有别人的服务，**⛔ 一个都不许杀** —— 杀掉会让别人读到半截数据后对自己的代码下错判。
- **起 vitest 前数并发**：判据是「**父进程不是 vitest 的 vitest 进程**」（每棵进程树只算它的根）。
  **双向金丝雀**：机器空闲**必报 0**（报非 0 ⇒ 把自己或 worker 算进去了）；只跑一个 run **必报 1**（报 ≥2 ⇒ 在数 worker）。**跑不出这两个数 ⇒ 量法坏了，⛔ 不许拿它做避让决策。**
  一律加 `--no-file-parallelism`。
- ⛔ **杀进程别用会自匹的 `pkill -f`** —— 命令行里含该字串会把探针自己也匹进去（本会话已自杀 4 次）。
  用 `ps -eo pid,args --no-headers | grep -F '<key>' | grep -v grep` 取确切 pid。
- ⚠ **一批红先按失败类型分桶再谈归属**：`Test timed out` 属 CPU 争抢，`AssertionError` 不是。
  今天真有 dev 把两类混成一桶整体作废，险些放走一条自己造的红。
  > 形态：「我用『这次跑受了 CPU 争抢』当作『这次跑的红都不算数』的证据。」

## J · 产出格式（每单都要）

**报告头**：起点 HEAD · 重开后 HEAD · 树龄两个数 · 分支 tip · `git status --porcelain` 是否为空

**正文**：
- 「今天的行为是 X，应该是 Y」**逐条原文**
- **对照实验四个数**
- **变异反证两个 RC**（改坏 / 还原）
- 爆炸半径 RC（**逐个给**，⛔ 不许只写「全绿」）

**末尾两节**：
- **《屏幕上多了什么 / 少了什么》** —— **答不出 = 这一轮无效**。改后端的可以答「屏上暂时没多，但 X 现在能画 Y 了」，**如实写，别粉饰**

# WO-WORLDSTATE-SURFACE · 统一世界态读取面

> **画像：重**（跑 datacore 测试）· **同时只许 1 个** · 预估最大的一张

## 背景（实测，你要复核）

系统本体 `docs/SYSTEM-ONTOLOGY.md:144` 记着这个病的原文：

> `financePnl(ctx: AuthCtx)` **零世界态入参**、读 `listByType("FinancePlan")` 本体真值 ⇒ **同一租户下施加任何扰动它都返回逐字节相同的一组数**

**当时的修法是「另起一个 `finance_world_projection`」（吃 `args.worldId`），不是让读取面认世界态。** 于是：

| | 数 |
|---|---|
| 求解器总数 | **63** |
| 能碰到世界态的文件（`args.worldId` / `getTickState` / `buildWorldReadView`） | **3** |
| 直读本体真值（`listByType`）的求解器文件 | **9** |

**⇒ 「求解器算的是真值口径，不是这次推演的口径」是默认行为，不是例外。**

今天已坐实的三个实例：
- `chain_impediments` 不吃扰动（`sessionId|simWorld|perturb|worldVersion|tick` 在 `apps/datacore/src/solvers/chain-impediment.ts` **0 命中**；金丝雀 `scope` 32 命中 ⇒ 量法有效）
- `supplyDemandGapAttribution` 消费入参集为空 ⇒ 改任何杠杆那个数逐字节不动
- 年度情景页 capex 查表 ⇒ 扰动前后 **8 → 8**

## 要做什么

**把「世界态读取面」做成求解器的统一入参**，让「真值口径 / 推演口径」变成**一个开关**，而不是**两个求解器**。

已有可复用的零件（别重造）：
- `apps/datacore/src/sim/world-read.ts` 的 `buildWorldReadView`
- `apps/datacore/src/solvers/finance-world.ts` 的取世界态路径：`repos.sim.getSession` → `repos.sim.getTickState(tenant, world, curTick)` → 回落 `world.baseSnapshot`
- 诚实处置先例：`apps/datacore/src/sim/impact-analysis.ts:87 (analyzeImpact)` 的「世界的态为空时如实说明」

## ⛔ 四条硬约束

1. **⛔ 不许一次改 63 个。** 先建**机制**（统一入参 + 读取面），再挑 **3 个**求解器接上去验证，其余留清单。
   一次全改既验不动也回滚不了。
2. **⛔ 不许把「该读真值的」也改成读世界态。** 有一类求解器答的是「**今天的事实是什么**」（台账、目录、体检、校验），随推演变**反而是错的**。
   ⇒ 每个求解器必须明确标注 `worldAware: true|false`，**并给一句理由**。判不了的标「判不了 + 缺什么证据」，⛔ 不许硬塞。
3. **R6 确定性**：不传 `worldId` 时，回包必须**逐字节不变**（这是最重要的兼容判据）。
   无 `Date.now` / 无随机；明细按稳定键排序。
   ⚠ **R6 断言不许写成空循环** —— 今天真抓到过一条「遍历空集合恒绿」的假断言。断言前先证明被遍历的集合**非空**。
4. **⛔ 不许内联业务常数**。系数来自配置或本体。
   ⚠ 已知事实（**只读不修**）：`base_outlook_coeffs` / `portfolio_optimize_coeffs` 两条规则**有读方零写方** ⇒ 所有 `coeff(k, dflt)` 恒走代码兜底。那是另一张单，**别顺手改**，但你新增的系数**不许再造第三条同样的死路**。

## ✅ 对照实验：四个数

> 取**接上去的那 3 个求解器中的 2 个**：
> **同一 args、同一 scope**，**施加扰动前 / 后**各调一次，比回包 hash。
> **接线前两次必须相同**（那正是病）；**接线后必须不同**。
> **四个数（两个求解器 × 前后）缺一个不算交付。**

**外加 R6 判据**：不传 `worldId` 的调用，接线前后回包 hash **必须相同**。给两个 hash。

# WO-RULE-DISCOVERY · 规则库进全量发现面

> **画像：中**（跑 agentcore 测试）

## 背景（实测，你要复核）

**规则不是一等可发现能力，是求解器的附属品。**

`apps/agentcore/src/agent/navigation-slice.ts:545-549`：
```ts
const rules: string[] = [];
for (const key of solverKeys) {              // 只遍历那 6 个求解器
  const hint = SOLVER_RULE_HINTS[key];       // 查一张手写静态映射表
  if (hint && !rules.includes(hint)) rules.push(hint);
}
```

对照实测：

| | 求解器 | 规则 |
|---|---|---|
| 总数 | 60 | **约 39**（`C01–C34` 一族，在 `apps/datacore/src/synthetic/battery.ts`；**这个数你要自己数准**，我是 grep `"C[0-9]+"` 数的，可能重复或漏） |
| `description` | **60/60 有** | **无** |
| `tags` | **60/60 有** | **无** |
| `answersQuestions`（这条能回答哪些问题） | **60/60 有** | **无** |
| 进模型视野的方式 | 语义检索 | **不检索**，只能被求解器带出来 |

**两个后果**：
1. 规则数量被求解器数量夹死（`MAX_SOLVERS = 6`）⇒ 39 条里绝大多数在**任何问句下都不会出现**
2. `SOLVER_RULE_HINTS` 是**手写映射会漂** —— 新增规则不会自动被带出来，得有人记得加一行（本仓「手抄册」形态，系统本体 §8 登记为 `G-GATE-ROSTER-HANDCOPIED` 同族）

## 要做什么

**让规则复用求解器那套发现面**：补 `description` / `tags` / `answersQuestions`，进同一个目录，可被检索。

## ⛔ 三条硬约束

1. **⛔ 不许另造一套发现面。** 复用求解器那套。若实测发现复用不了，**停手把障碍顶回来**。
2. **⛔ 描述不许照 `name` 扩写。** 必须**从 `expression` 反推**它到底约束什么、什么时候触发。看不懂的标「判不了 + 缺什么证据」，⛔ 不许编一句听起来对的话。
3. **⛔ 不许动 `SOLVER_RULE_HINTS` 的既有条目**（那是现役通路），只做**加法**。

## ✅ 对照实验：四个数

> 取**两条规则**：一条今天带得出来（A 类），一条今天**结构性带不出来**（`SOLVER_RULE_HINTS` 里没有任何条目指向它）。
> 用**同一条真实问句**，改前 / 改后各跑一次导航切片，看返回的 `rules[]`。
>
> | | 改前 | 改后 |
> |---|---|---|
> | 规则甲（本来可达） | 在 | **仍必须在**（不许把老路弄坏） |
> | 规则乙（本来不可达） | **不在** | **必须在** |
>
> **四个数全给。** ⚠ 若改前规则乙**居然在**，说明样例挑错了 —— 换一条并说明依据，⛔ 不许硬套。

## 🚦 范围边界

**只碰**：规则定义处的元数据字段（`apps/datacore/src/synthetic/battery.ts` 的规则条目）· `apps/agentcore/src/agent/navigation-slice.ts` · `apps/agentcore/src/agent/live-capability-map.ts` · 对应接缝测试

# WO-TEST-RETROFIT · 存量测试断言形态回溯

> **画像：轻**（先只读审计，不跑套件）· 分两阶段，**第一阶段只审计不改**

## 背景（实测数）

| | 数 |
|---|---|
| 测试文件总数 | **881** |
| 含「两次调用做对比」形态的 | **67（7.6%）** |
| 只断言「有东西 / 形状对」（`toBeDefined`/`toBeTruthy`/`toHaveLength`）的 | **514（58%）** |

**今天四个 bug 全部在绿测试底下活下来，四种机制**：

1. **断言是单点的，而缺陷是关系性的** —— severity 单因子 / 影响 500 张 / 不吃扰动 / 传导无用量项，每一个都需要**两次调用相比**才看得出来
2. **测试把 bug 编码进了断言** —— 实测有两处断言写的是「severity 必须能由 `metricValue/threshold` 重算」，**那正是单因子公式本身**。测试不是没测到，是**在守护这个 bug**
3. **夹具量级差 1–2 个数量级** —— 接缝门用 **4 张订单**夹具，生产 **500 张**；「500 该不该是 150」在 4 张单上**不存在**

# WO-INPUTSCHEMA-B · 剩余 48 个求解器的 inputSchema

> **画像：重** · ⚠ **有前置**：等 `WO-SOLVER-INPUTSCHEMA`（前 12 个）合并后再开工，否则会在同一文件上冲突

## 背景（实测）

标准 MCP 的工具需要 `name` / `description` / **`inputSchema`**。本仓现状：

| MCP 要素 | 现状 | 达标 |
|---|---|---|
| `name` | `mcp__solvers__{key}`，内置 server 已建（`apps/agentcore/src/mcp/solvers-catalog.ts`） | ✅ |
| `description` | 60/60 全有 | ✅ |
| 标签 / 语义索引 | 60/60 有 `tags` + `answersQuestions` | ✅ |
| **`inputSchema`** | **0 条** —— `apps/datacore/src/solvers/args-schemas.ts` 是**空的** | ❌ |

只有 `argHints` 这种散文：`{ modelId: "型号 ID，如 4680-NCM" }` —— 无类型、无必填、无枚举。

**代价是实的**：`lineGranularity` 这个开关**全仓零调用方**，因为它**不在任何 `argHints` 里** —— 模型不知道可以传，线级排产能力整个等于不存在。

## 要做什么

给**剩余 48 个**求解器补 `inputSchema`（前 12 个由前一张单完成，**照抄它的写法保持一致**）。

## ⛔ 三条硬约束

1. **从实现反推，⛔ 不许照 `argHints` 抄。** `argHints` 本身就漏（`lineGranularity` 是活证据）。
   每个求解器的参数集必须从**它的实现**里读出来：真读了 `args` 的哪些键、类型、必填、枚举。
   ⚠ 注意**字符串键分发**与**解构默认值**两种形态，grep 一次看不见。
2. **⛔ 不改任何求解器实现。** 本单只是**如实声明已经存在的入参**。
   入参自相矛盾或读不出来 ⇒ **如实标「判不了」并写清缺什么证据**，⛔ 不许发明一个 schema 硬塞。
3. **R6**：schema 是静态声明，无 `Date.now`/随机；新增字段一律 optional，既有回包逐字节不变。

## ✅ 对照实验：四个数

> 取**两个**你补的求解器：
> **补 schema 前** —— 从 MCP 工具描述里能看到的可传参数个数 = ?
> **补 schema 后** —— 同一处 = ?（必须**多于**改前，且新增的键要能点名）
> **四个数缺一个不算交付。**

**外加一条能力性判据**：补完后，参数必须能被**校验** —— 给一个布尔参数传 `"yes"` 这种错类型要被**拒绝**，不是静默转 false。给拒绝前后两个回包。
