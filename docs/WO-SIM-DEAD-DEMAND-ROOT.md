## §1 病是什么（四条全部实测，每条带金丝雀）

| # | 核的是 | 实测 | 金丝雀 |
|---|---|---|---|
| ① | `Order.demandPressure` 有几条入边 | **1 条**，`coefficient: -0.6` | 同法数 `costPressure` = **3 条** ⇒ 数法有效 |
| ② | `Model.forecastBias` 有几条入边 | **0 条** ⇒ **外生根**，只由种子生成器写 | 同上（①②③ 同一条查法） |
| ③ | `forecastBias` 的域 | `STATE_VAR_DOMAINS.forecastBias = { min: **-100**, max: 100, restPoint: 0 }` | — |
| ④ | 种子生成器值域 | `round(hash01(\`${objectId}\|${stateVar}\`) × 100)`（`sim/seed-world.ts:335` 自陈式）⇒ **[0, 100]，恒非负** | 域表里两个外生根实测 97.00 / 96.00，均落在 [0,100] |

**推论链（每一步都可复验）**：

```
forecastBias ∈ [0, 100]（生成器只产非负）
  → demandPressure 的唯一入流 = −0.6 × forecastBias ≤ 0  （恒为负或零）
  → demandPressure 是压力族（min = 0，restPoint = 0）
  → 硬底板把它按死在 0
  → 每一个 Order 实例的 demandPressure ≡ 0
```

### 两句自相矛盾的话，就摆在同一个仓里

- `battery.ts:3318` 原文：「⚠ `forecastBias` 是本表**唯一带方向**的量纲（正=高估 / 负=低估）」
- `battery.ts:3398` 原文：「下界取 `−max` 以**保持两侧对称**」
- 那条边 `seed.ts:1312` 的注释原文：「负号即方向：**高估(+) ⇒ 需求压力被下修；低估(−) ⇒ 需求压力上冲**」

⇒ **设计明明白白要双向，而生成器只给一侧。「低估 ⇒ 需求上冲」那一支从上线起一次都没执行过。**

> **形态（照 CLAUDE.md 铁律 0.6 句式）**：
> **「我用『我给这个量纲声明了双侧域』当作『它会取到两侧的值』的证据，而前者并不度量后者 —— 生成器只产得出一侧。」**

### 为什么这条要单独立单

它与「饱和」是**两个独立的病**，修法也不同：
- **饱和**（`WO-SIM-CALIBRATION`）：所有通道顶到上界，扰动被压平 ⇒ 改标定
- **本单**：一整条链**从源头就没有信号**，不是被压平，是**根本没进来** ⇒ 改生成器

⚠ 且本单与 `WO-SIM-DAMPING` 有交集但不重复：那张单问「该不该有需求下降这条路」，**本单证明那条路已经修好了、只是入口是堵的**。**两张单必须互相知道**，否则阻尼单会去新造一条已经存在的边。

## §2 要做什么

**让 `forecastBias` 的种子取值覆盖它自己声明的双侧域。** 就这一件事。

**⛔ 三条硬约束**：
1. **⛔ 不许改 `hash01` 本身** —— `seed-world.ts:247` 原文写着「**与前端 `views/sim/edgeActiveModel.ts:370 hash01` 同式，这是刻意的，不是『又造了一份』**」。改它就是让两边分叉。
2. **⛔ 不许只给 `forecastBias` 开后门而不写出处**。域表的门槛是原注释自己定的：「**域表只收『写得出出处』的量纲**」。生成式同理 —— 改了要能说清「为什么这个量纲的生成式与别人不同」。
3. **R6 确定性不许破**：同 `(industry, scale, seed)` 重跑必须字节级一致。⛔ 不许引入 `Math.random`。

**建议方向（不是指令，实测后自己定）**：带方向的量纲，生成式应当映射到 `[min, max]` 而不是 `[0, max]` —— 即对**声明了负下界**的变量走 `min + hash01 × (max − min)`。
⚠ 若这么改，**必须核查它会不会波及别的变量**：今天 `min < 0` 的变量有几个？（先数，别假设只有 `forecastBias` 一个。）

## §3 验收判据（⛔ 写不出对照实验 = 本单没法验收）

**判据 1（本单命门·四数）**：
- **修前**：`demandPressure` 在**全部** Order 实例上 ≡ 0（先自己测出这个 0，它是病的指纹）
- **修后**：必须出现**非零且有分布**的读数，且**有正有负的 forecastBias 源**
- 四个数：修前 `min/max(demandPressure)` · 修后 `min/max(demandPressure)`

**判据 2（方向对不对·这才是业务判据）**：挑两个 Order —— 一个挂在 `forecastBias > 0`（高估）的 Model 上，一个挂在 `forecastBias < 0`（低估）上。
- **高估的那个，`demandPressure` 必须更低**；低估的必须更高
- **方向反了比恒为 0 更糟** —— 恒为 0 至少是诚实的空值，方向反了是**言之凿凿的错答**

**判据 3（变异反证）**：把生成式改回单侧，确认判据 1 的非零分布**当场塌回 0**。不塌 ⇒ 你改的地方不在生效路径上，退。

**判据 4（不误伤 R6）**：同 seed 连跑两次，`measuredCells` / `derivedCells` / 世界态哈希**逐字节一致**。

**判据 5（不误伤别的量纲）**：若你的改法影响了 `min < 0` 的其他变量，逐个给修前修后的 `min/max`。**一个都不许漏报。**
