两处我在图里如实标了「今天做不到」

这些不是设计缺陷，是系统现状。画出来是为了让你看见代价，不是为了好看。

  1. 设备子页：OEE 四个字段扰不动 它们只在对象属性上，没进 world.state，而引擎只读 state。硬加进 UI = 用户选了「OEE −10%」、请求成功、下游一动不动。要扰得先把属性投进状态层——后端一张单。
  2. 需求子页：「预测偏差」没有独立变量 现在只能借 demandPressure，但压力没有方向而预测偏差有（高估 / 低估）。独立的 forecastBias 在另一张单里，尚未并线。

一条订正 —— 我上一版说错了

你问「PUT/PATCH 要不要补」，我去量了，前提不成立：那个能力今天就有。

「关掉一条边看结论怎么变」两条端点都在：
POST /a/v1/sim/sessions/:id/disabled-rules（关）　+　POST /a/v1/sim/sessions/:id/counterfactual（看变化）
会话上就有 disabledRuleKeys 字段，前端模型 edgeActiveModel.ts 的 toggleEdge() / buildDiff() 也齐了（带 baseline / counterfactual / absentIn 三态）。

PUT/PATCH 真正缺的是另一件事：永久改一条边的系数或延迟——那是真值变更，要走 R4 审批链， 和边册页要的「本次假装它不存在」根本不是一条路。

所以第 4 条不用做。我差点为一件已经做完的事派单——这正是本仓记过的老病： 拿「清单上还没划掉」当「这活还没做」的证据。
范围边界：这一版零后端改动、零数据源改动——把已有的 renderer 与已有的端点重新排一次版。 四页 pixel 用例会因版面变动而红，那批断言需同批更新（预期内，不是回归）。
