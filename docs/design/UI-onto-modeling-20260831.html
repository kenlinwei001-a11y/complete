设计意图（不上屏）
1七个面收敛成一条动线。实测 0/7 达可用标准，运营在上面完成不了本职工作。
2新建对象类型补屏上入口。写端已存在（POST object-types = upsert，改得了 unit/displayName）⇒ 接线不是造门。
3单位可选可扩。今天 9 项写死 TS 常量，t/kW/h 全 400。
4口径冲突在建模期拦下。今天 Line.utilization 百分点 vs Process.utilization 比率，已付 100× 与 10⁴ 两次费。
5每步可回退。今天建域 = 一步、不可逆、无提示地锁死发布；下线类型返回 200 但无事发生。
6波及面前置。该能力已实装（四桶＋逐跳＋未解析位），今天埋在「边界册治理」名下，而那页 0 个按钮。
7动线主脊换成 对象 → 关系 → 状态 → 事件 → 规则 → 约束 → 因果 → 数据 → 场景/求解 → 发布，不再按 API 表面排。
8就绪度表 = 能不能做产销推演的验收表。20 条核心关系「有关系 + 有数据 + 可遍历」三者缺一不算可用。待测 由后端盘点回填，不臆造。
9已有实测的三条：compatible_with 缺（capacity_forecast(EX-220) → 400 has no certified lines）· fulfills 疑断链（42 条因果边成 3 个互不相通分量，无一条决策同时碰交付与钱）· 时间窗产能缺（tickDays 粒度 1 天，表达不了 2 小时停机）。
10结构边与因果边是两套机制（LinkType upsert/有 version/115 条 ｜ PropagationRule 追加/无 version/42 条/改删 404）。统一成单一 Relation + facet 后，「同 key 双算」与「三个分量互不相通」可能同时消失 —— 待盘点证实。
11关系行内可改可停可删。今天因果边表行内 0 控件，PUT/PATCH/DELETE 全 404，同 key 连写两次得系数 0.5 与 9.9 两条并存且 combine:"sum" 双算。停用必须可逆 —— 结构边今天的「停用/下线」点了回不来，别复制。
12约束走引用，不走内联。对象的约束（设备产能、最小批量、换型时间）在配置器里引用规则库，规则改一次全体生效。⚠ 本仓已有 coefficientRef 这个引用机制，注释写着「禁内联业务常数（RL5）」，而实测 42 条边里 0 条在用，全部内联回落 —— 机制在、没人走，属接线不属造门。
13切片按域分层：域 → L1 完整切片 → L2 子集，另设跨域切片。L1 的验收是域内类型 100% 覆盖；跨域切片的验收是至少一个交集节点（D03✕D04 交于 Line，D04✕D05 交于 BOM）。无交集的域对必须显式标红 —— 它意味着那条多跳检索今天走不通。
14⚠ 本节数字为设计目标，非实测。今天实测：99 条切片里仅 4 条真多跳（3–31 跳），其余 95 条是 hops=0 / paths:[] 零跳存根；切片有无域归属字段、有无父子层级、`slices/plan` 支不支持域内限定与 L2 切分——全部待盘点回填。
