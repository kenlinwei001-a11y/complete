# 系统协同进化运行模型（"宪法"）

> 本文是**元框架**：统摄 `docs/SYSTEM-ONTOLOGY.md`（现状本体）与各 PRD（意图）之上，定义"人 × Claude Code × 系统"如何协同、持续开发、并在演进中保持**敏捷 + 稳定**。
> 版本 v0.1 · 日期 2026-06-15 · 所有人与 AI 的开发行为遵此模型。

## 0. 本体引用与影响（自我引用 · dogfood）

- **触及对象类型**（本体 §2）：全部 11 域（§10）—— 本文定义它们如何被治理。
- **触及链路/切片**（§3/§10.3）：`sys.meta.change_loop`（协同进化闭环本身）。
- **触及不变量**（§5）：R1–R12，尤其 R11 全链闭包（本文把它定为机制核心）。
- **触及门禁**（§7）：`ontology:check` · 全链闭包门 · 测试 · 断链审计。
- **回写承诺**：本文若改变机制 → 同步 SYSTEM-ONTOLOGY §9/§10 与 CLAUDE.md 铁律 0。

## 1. 核心原理（一句话）

**系统拥有一个机器可用的全域自我模型（本体），并把 Claude Code 绑定其上——使"需求→开发→演进"成为以本体为脊柱的闭环。** 本体是三方（人的需求、AI 的开发、代码的实现）唯一的共享真相 + AI 跨会话的持久记忆。

> **敏捷与稳定同源**：本体让影响分析瞬时（快）；同一本体上的不变量+闭包门让每次改动被兜住（稳）。速度与安全来自同一处。

## 2. 三件套（同一张图的三个视角）

| 件 | 是什么 | 载体 | 视角 |
|---|---|---|---|
| **现状本体** | 系统当前全域接线（功能/信息流/权限/数据/规则/事件/断点） | `SYSTEM-ONTOLOGY.md` | AS-IS |
| **PRD库** | 需求/意图，**链到**它将触及的对象/链路/缺口 | `docs/PRD-*.md`（§4 待结构化入图） | TO-BE |
| **运行模型** | 三方如何协同把 TO-BE 变 AS-IS 的机制 | 本文 | 机制 |

三者**同图**：现状与意图挂在同一组对象/链路上，AI 才能做真正的影响分析与追溯。

## 3. 协同进化闭环（机制骨架 = 切片 `sys.meta.change_loop`）

```
需求(人)
  │ ① 理解  读本体 → 定位域(§10.2) → 沿域内切片(§10.3) → 跨域节点提示涟漪(§10.4) → 查断点(§8)/不变量(§5)
  ▼
本体(AS-IS)
  │ ② 设计  PRD 入库 + 强制《本体引用与影响》→ 需求挂到将触及的制品/链路/缺口
  ▼
PRD库(TO-BE)
  │ ③ 实现  Claude Code 改代码（沿切片、守不变量、重点设防跨域节点）
  ▼
代码
  │ ④ 回写  新增/改的对象/链路/事件/门禁 → 同步本体（否则 ontology:check 红）
  ▼
本体(更新)
  │ ⑤ 门禁  ontology:check(不漂) + 全链闭包(切片端到端通) + 测试(全绿) + 断链审计
  ▼
发布 → 回到 ①
```

**每一步都已有强制载体**：① SessionStart 钩子+铁律0+`/ontology` skill；② PRD 模板《本体引用》段；④⑤ `ontology:check` + 全链闭包门（建设中）+ 测试。

## 4. 域 / 切片 / 跨域节点 = 闭环的操作单位（本体 §10）

- **域（11 个）= 影响分析与责任的单位**：需求先落到域，缩小搜索面。
- **域内切片 = 闭包门的验证对象**：尤其中枢链 `sys.orch.query_to_answer`、构建链 `sys.ingest.build_closure` 必须端到端通。
- **跨域节点（接缝）= 风险地图**：断点几乎全在这（G-1/G-2/G-8 均坐其上）→ 改动经过跨域节点时**重点设防 + 闭包门聚焦**。

## 5. Claude Code 如何嵌入（三层，全强制不靠自觉）

1. **绑定层**（已建）：CLAUDE.md 铁律0 + SessionStart 钩子 + `/ontology` skill + PRD 模板 + `ontology:check`。每次必经本体。
2. **记忆层**：本体 = Claude 的长期记忆（无状态不再是问题，每会话注入；回写+自动派生保鲜）。
3. **融合层**（待建）：本体做成系统暴露的**活查询面**（MCP/端点），Claude 直接问运行中的系统"改 X 影响哪些切片"；再进一步把本体**落库**为平台对象，用平台自己的 `executeSlice`/规则/推演分析系统自身。**人与 AI 共用同一条对话入口（CLI/QOS）驱动平台。**

## 6. 防腐三防线（让模型永远为真——成败所系）

模型失真比没有更糟（虚假信心）。三道，从弱到强：
1. **自动派生**：能从代码生成的（事件/求解器/实体/端点/链路）就别手写（`ontology:check` 已覆盖事件/求解器/锚点，待扩 §2/§3/§4）。
2. **门禁强制**：漂移即 build 红；钩子不许硬编码断点；回写缺失即拦。
3. **终态——平台自己的门禁即真相，本体是其投影**：当全链闭包/validate 成为发布硬门禁，"系统能不能跑"被平台强制，本体由门生成、结构上不可能过期。

## 7. 稳定的形式化（不变量 = 门禁）

R1–R12（本体 §5）是改动不可违反的铁律；其中 **R11 全链闭包**是本机制的核心——把"场景→答案可运行"从"靠人工审核"升级为**构建时硬门禁**（统一构建发动机落地）。稳定从此是结构属性，不是纪律期望。

## 8. 角色与职责

| 角色 | 职责 | 边界 |
|---|---|---|
| **人** | 提需求、审批真值写入（R4 Action）、策展本体的承重语义、拍板架构决策 | 不手维护可派生段 |
| **Claude Code** | 读本体→影响分析→改代码→回写本体→过门禁；产出含《本体引用》 | 真值写入产草稿、不直接改库（R4） |
| **门禁** | `ontology:check`/全链闭包/测试 仲裁"能不能发" | 红即拦，无例外 |
