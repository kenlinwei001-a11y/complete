PART 1 · 技术实现模式

系统本体开发轮

本体（SYSTEM-ONTOLOGY）= 系统的单一接线真相源 + 活体自我模型。一切开发绕它转——"不靠人记性，靠机器约束"地保持架构一致、可演进、不腐化。

技术实现（治理不靠自觉，四层强制）

  • 必读前置：铁律 0 + SessionStart 钩子（每会话注入本体未修断点）+ /ontology skill
  • 模板必填：PRD §0《本体引用与影响》——对象类型/链路/事件/不变量 R1–R16/断点/数据闭环 checklist
  • 门禁红线：ontology:checkchain:checkdebattery:checkprd:check——漂移/悬空即 CI 红，合不进
  • 回写强制：改了链路/事件/对象/不变量/门禁 → 必须回写本体，否则"大脑过期失效"
  • 载体：16 不变量 · 8 断点登记 · 11 自我域 + 域内切片（端到端可验证子图）
价值：大型双系统平台的"架构防腐 + 协同进化"机制——把"系统怎么接线、改这会影响什么"沉淀为机器可校验的单一来源，让多人/多 agent 并行开发不漂移、可持续演进。
协同进化闭环 · sys.meta.change_loop ：需求 → 本体影响 → 编码 → 回写 → 门禁 → 发布 →（循环）

PART 2 · 发育论 · 技术 + 商业价值

从胚胎到完整系统

系统像受精卵发育成人：倒序发育（从一句场景/需求，倒着长出数据·对象·规则·求解器·Agent）⊕ 正序运作（用户使用）—— 同一有机体的两个相位（runId 归一）。

技术实现

  • 倒序发育引擎：StoryScript→comprehend(LLM)→BuildPlan→跨系统 scaffold（对象/规则/求解器/Agent/工作流/场景）
  • 三环自动闭合：数据(build-to-verify)·本体(活体自更新)·能力目录(从注册表自派生)
  • 成熟分相位：合成/补出的产物先 未审核态，经使用+审批(R4)成熟为 GOVERNED 真值
  • 正序↔倒序咬合：用户问句答不出→GapReport=生长信号→自动补齐→回写本体+刷新目录
  • 护栏：有界收敛 · 单一上传口 · 确定性(R6) · 真断点→工单（不自动改架构）

商业价值

交付提速一句场景倒推全栈；新行业/客户从"零"到"可推演"一键引导(bootstrap)，周期从月级→天级
越用越强缺口即生长信号，系统随使用自我补全（需求拉动），无需预先穷举需求
低边际成本换行业=换种子配置/模版，不改代码（模版+种子双层），一套引擎多行业复用
可信可审计产物分相位成熟·全程溯源·走审批；"绿测试≠能用"守诚实，企业级决策敢用
护城河活体本体=自我认知，平台用自己分析自己(dogfooding)，数据+演进双壁垒，竞品难复制
发育闭环 · sys.meta.ontogenesis_loop ：场景→倒推建域→未审核产物→正序生长信号→成熟 GOVERNED→回写活体本体+派生目录
