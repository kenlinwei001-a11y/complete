# 全仓 UI 第一层信息密度普查（AUDIT-ui-first-layer-density）

> **来历**：2026-08-11 仓主的全仓级判词 ——
> 「你所有页面类型旧版的『推演沙盘』，**大量信息在第一层堆砌**，所以**都需要重新设计前端**」。
> 这不是一页的问题，是**通例**。本文把它从一句判断变成**逐文件、可复算的账**。
>
> **规范单一来源**：`docs/CONVENTION-ui-information-layering.md`（§1 三层准入 · §2 三条硬判据

> **本文不自创任何判据** —— 每个指标都注明它对应规范的哪一句，以及**它为什么度量的就是那句话**。
>
> **复算命令**（本文所有数字均由此产出，无一手抄）：
> ```bash
> node scripts/check-ui-first-layer.mjs --census            # 全量读数（JSON）

## 1 · 三条硬判据各自能机检到什么程度（**先说做不到的**）

规范 §2 给了三条判据。**它们的可机检性差别极大**，混为一谈会把"判不了"的假装成"判过了"。

| 规范判据 | 能否机检 | 本文采用的代理指标 | 它凭什么度量的就是那句话 |
|---|---|---|---|
| **R-UI-1 视线距离**（标签与数值同时读进眼里，是否需移动视线超过一张卡宽） | **❌ 判不了** | —— | 这是**渲染后的几何量**：依赖视口宽度、flex 分配、字体度量。**源码里不存在这个量。** 硬编「full-width flex + space-between」之类的形状代理，度量的是**写法**不是**视线距离** —— 那正是本仓铁律 0.6 点名的病（「我用 X 当作 Y 的证据，而 X 并不度量 Y」）。**本文与本门都不假装能判它**，仍由规范 §5 人工复审。 |
| **R-UI-2 字号层级 ≤ 3** | **✅ 能** | 该文件**实际用到**的不同 font-size 值个数（内联 `style={{fontSize}}` ∪ 它 `styles.X` 引用到的那些 CSS 类的 `font-size`） | 规范原文就是数"级"。**唯一口径差**见 §7 诚实边界①：规范的"级"是**语义级**，本文数的是**物理值**。 |
| **R-UI-3 公式与口径不在第一层** | **✅ 能** | 第一层文案里命中规范**原文点名**的形态：`×` `÷` `∩` `min(`、「口径」、「按 X 显示不按 Y」等 | 词表**逐条抄自规范 §2 R-UI-3 原文**，不是我自拟。且只数**第一层**的 —— 同样字串进了浮层**不计**，本门咬的是**位置**不是**内容**。 |
| **§1 三层准入**（第一层只放 ①数值 ②状态 ③名字） | **✅ 能（部分）** | ①「第一层信息块数」= 规范 §5 复审判据 2 原文「**数一数第一屏有几个信息块**」；②「第一层长说明串」= 第一层里 ≥24 字的文本 | 名字/状态天然短；**成段文字出现在第一层，按定义就不是"名字"**。 |

### 阈值 24 字是怎么定的（**实测分布，不是拍的**）

扫描面内全部 JSX 文本字面量 **3188** 条，长度分布实测：

| | min | p25 | 中位 | p75 | p90 | p95 | max |
|---|---|---|---|---|---|---|---|
| 字数 | 1 | 2 | **4** | 9 | 22 | 35 | 145 |

| 阈值 | ≥10 | ≥16 | ≥20 | **≥24** | ≥30 | ≥40 |
|---|---|---|---|---|---|---|
| 条数 | 793 | 495 | 367 | **280** | 202 | 124 |
| 占比 | 24.9% | 15.5% | 11.5% | **8.8%** | 6.3% | 3.9% |

**读法**：中位数 **4 字** —— 绝大多数第一层文本确实是"产能缺口""可行"这类**名字/状态**，
与规范 §1 的准入清单一致。分布在 p90（22 字）之后迅速变稀，
而规范点名的反例（如 `CapacityDerivationDag` 那句「6 层沿产能金字塔既有派生链路（本体 §3·不改链路，
仅可视化）；锚点真值溯 base_capacity_outlook…」）在 60 字以上。
**24 落在 p90 之后的稀疏带**，命中 8.8% —— 既不会把常规标签扫进来，又能罩住成段说明。

**⚠ 这个阈值的敏感度不高，因为它只作棘轮基线用**：存量 283 条全部登记、只防新增。
阈值取 20 或 30 会让基线数变化，但**不改变任何一个文件的达标/不达标结论**（存量一律入基线）。
真正靠它的只有"新增了一条成段说明"这一个判断。

## 2 · 金丝雀：这套指标**对已知的真实改善敏感吗**

> 这是本次普查的**保命判据**。若指标对一次**已知为真**的治理毫无反应，
> 那是**指标坏了**，不是页面没改 —— 此时任何排名都不可信。

**⚠ 先纠正一条派单前提**：派单说「沙盘系已被 `claude/handoff-wo-sandbox-ui-integrate` 改过一轮」，
据此要求普查区分「已治理/未治理」两态。**实测：那一轮改动并不在 canonical 上。**

| 事实 | 实测 |
|---|---|
| 沙盘整合分支 tip | `cd4205d5`（`refs/heads/claude/handoff-wo-sandbox-ui-integrate`） |
| 它与 canonical 的 merge-base | `4ae28e0e` |
| 它领先 merge-base | **44** 个提交 |
| canonical 领先 merge-base | **2** 个提交 |
| `cd4205d5` 是否 canonical 的祖先 | **否** —— 未并线 |

⇒ **canonical 上的 `views/sim/**` 全部处于「未治理」态**，本文排名即按此如实计。
两态因此被**分支**干净地切开，反而给了一个理想的改前/改后对照组。

### 改前（canonical）→ 改后（`cd4205d5`）

| 文件 | 第一层 | 可折叠 | 口径/公式 | 长说明 | 原生 title |
|---|---|---|---|---|---|

**判读（这正是 D4 守恒要认的那个形态）**：

- `SandboxConsole.tsx`：第一层 **199→183（−16）**，而可折叠 **19→64（+45）**、
  长说明 **32→17（−15）**、口径公式 **5→3**。
  ——**内容没有消失，是被搬下去了**：first↓ 而 deferred↑↑。这是"真分层"的指纹。
- `ChainLineMapView.tsx`：原生 title **2→0**。
  这正是规范 §2 白纸黑字点名的那次事故（「`ChainLineMapView.tsx` 的两个 SVG `<title>`

- `SandboxView.tsx`：可折叠 **0→19**，第一层持平。

**结论：指标对这次已知的真实改善敏感（金丝雀通过）。** 三个被改过的文件全部有反应，
且反应方向与改动性质一致；**未被改的 23 个沙盘文件读数逐字不变**（无噪声）。

### 这轮对照当场抖出了本指标的两个真实缺陷（都已修 + 已上回归金丝雀）

| # | 缺陷 | 若不修会怎样 | 修法 |
|---|---|---|---|
| ① | 字号 design token 被按「每个成员访问算一级」计数：`CAP_TYPE_SCALE = {hero:28, value:19, label:12}`（**正好三级，正是 R-UI-2 要的改法**）被判成多级 | **门会奖励继续散写内联魔数、惩罚把字号收进命名常量** —— 指标奖励错方向，就不再是在守这份规范 | 成员访问解析回字面值；三元/逻辑表达式**逐分支**取值；`font-size:0`（折叠空白的排版手法）不计 |

两个都可能错，但**错法不同**，对不上就说明至少有一个坏了。

## 7 · 诚实边界（本文与本门做不到什么）

1. **R-UI-2 的"级"是语义级，本文数的是物理值。** 一页出现 `9px / 9.5px / 10px / 10.5px / 11.5px`
   在语义上可能都属"第三级辅助说明"，本文记作 5 级。方向是对的（规范反对的正是这种字号涂抹），
   但**绝对值偏严**。故硬上限 3 只对**新文件**生效，存量一律走棘轮。
   *实例*：沙盘分支治理过的 `CapacityDerivationDag.tsx` 自称"三级字号"且**确实**把主数值收进了
   `CAP_TYPE_SCALE`（28/19/12），但它的 CSS module 另有 5 个尺寸 ⇒ 本文记 8 级。
   **连唯一按规范治理过的页面，在严格口径下仍不满足 R-UI-2** —— 这是真实发现，不是误报。
2. **`first` 是静态模板计数**，`.map()` 的行模板计一次。它度量"这一屏摆了几**种**信息块"，
   不是"屏上最终有几个块"。跨文件比较有效，但不要当成 DOM 节点数。
3. **"第二层"的判定靠披露式条件变量名**（`open/expand/tab/mode/selected…`）与浮层组件名。
   用别的命名法写的折叠会被误判成第一层 ⇒ **偏保守，宁可多报**（分数只会偏差、不会偏好）。
4. **不含跨文件展开**：页面 import 的外部组件，其内部结构不计入本页读数。
5. **原生 `title=` 本门只报数、不据此红** —— 该项另有专门棘轮（见 §8），两道门各设一份基线必然漂移。
