# SOP · 审核方下结论前的自检纪律

> **配套工具**：`scripts/claim-check.sh`（可执行半）。
> **上位法**：`CLAUDE.md` 铁律 0.5（grep 不是结论）/ 0.6（同错第二次必须建机制）/ 1（长任务主动探针）。
> 本文是那三条铁律的**操作手册**：铁律说「必须验」，本文说「怎么验、验什么、验完怎么说话」。

---

## 0 · 这份 SOP 为什么存在

2026-08-11 一天之内，审核方（我）连下 **一串错误结论**，逐条写出来之后发现它们是**同一句话**：

> ## 「我用 X 当作 Y 的证据，而 X 并不度量 Y。」

而且其中过半**不是判断力问题，是工具在骗人**——树旧了、dist 旧了、端口被占了、
pathspec 写法不跨斜杠、变异根本没生效。这些**都是机器能替我查的**，靠人记得去查就一定会漏。

所以本 SOP 只做一件事：**把「我以为」变成「机器说」**。

---

## 1 · 当天的错账（形态归一后）

每条都按「我用 X 当作 Y 的证据」写。**结构相同即同错**，哪怕工具、模块、语言完全不同。

| # | X（我拿来当证据的） | Y（我想证明的） | 后果 |
|---|---|---|---|
| 1 | 我脚下这棵树 grep 不到 | 全仓不存在 | 主目录落后 canonical **112 提交**；`GATE_UNAVAILABLE` 实有 5 处，是 dev 顶回来才发现 |
| 2 | 换个词 grep 得到 | 我的 grep 工具是好的 | 那个词**新旧两棵树都有**，压根不度量「树新不新」——**金丝雀选错对象等于没有金丝雀** |
| 3 | 我改了个名字 | 我做了变异反证 | `cadenceGates`→`cadenceGatesXX`，`toContain("cadenceGates")` **照样过**，变异没变异 |
| 4 | 我加了个金丝雀 | 这道门自证过了 | 那个金丝雀**在任何情况下都不会开火**（三种 rev-parse 形式都被 try/catch 吃掉） |
| 5 | 分支名在我要合的清单里 | 它的内容已经完整 | 并了**agent 仍在跑**的分支 ⇒ 拿到中间态 ⇒ 门跑满 41 分钟红在一个不存在于任何分支的状态 |
| 6 | 我记得它在那一批里 | 它在那条分支上 | 对仓主说「cert 绿了沙盘 UI 就一起进正线」——实测 7 条分支对 cert 的 merge-base **全部不在** |
| 7 | 这个符号我 grep 不到 | 这个功能要从零建 | S3 枚举器整环都在（实现+接线+数据），差点让 dev 造第二套 |
| 8 | 我在 WO 里写的字段名 | 这些字段真的存在 | 三个字段名全仓零命中，是 dev 查完顶回来的 |
| 9 | `pnpm x \| head -3; echo $?` | 这条命令的退出码 | `$?` 取的是 **head** 的退出码（恒 0）——RC=0 与「🔴 有问题」同屏出现 |
| 10 | 我 sed 了一下 | 变异真的生效了 | sed 的正则没匹配上，文件一字未改，而我据此说「门没牙」 |
| 11 | 注释里写着这条纪律 | 这条纪律在被执行 | 4 个文件的注释写着「每个 var(--x) 必须有定义」，同一条规则**仍被违反 14 次** |

**第 11 条是本 SOP 的存在理由本身**：
> **写在注释里的纪律不是机制。写在文档里的纪律也不是。**
> 机制的判据只有一条：**下次同样的错发生时，是机器先说话，不是人先想起来。**

## 2 · 三级处置（不许跳级、不许降级）

| 次数 | 必须做的 | **不算数**的 |
|---|---|---|
| 第 1 次 | 修 + 记账 | — |
| 第 2 次 | **当场建机制**：门 / 封装 / 检查清单，三选一 | 「下次注意」· 在报告里写一句「已知此坑」 |
| 第 3 次 | **写进 `CLAUDE.md`**，注明前两次的日期与原文 | 只在本文件里记一笔 |

## 3 · 开口之前：跑 `claim-check`

```bash
scripts/claim-check.sh tree                 # 报「代码里没有」之前
scripts/claim-check.sh dist <pkg>           # 起服务 / 读 dist 之前
scripts/claim-check.sh has <什么> <哪条分支>  # 说「某某会随某分支进正线」之前
scripts/claim-check.sh port <端口>           # 起服务之前
scripts/claim-check.sh grep <符号> [路径]     # 报「零命中」之前
scripts/claim-check.sh all                  # tree + 各包 dist 一起过
```

**退出码三分**（本仓所有门统一此约定）：

| RC | 含义 | 你可以说什么 |
|---|---|---|
| 0 | 干净 | 可以下结论 |
| 1 | 真有问题 | **你现在看到的证据不可信**，先修再说 |
| **2** | **工具自己坏了** | **只许说「我没查出来」，绝不许说「它不存在 / 代码干净」** |

RC=2 与 RC=1 的区别就是本仓一整天的教训：

> **「我没找到」和「它不存在」是两个不同的命题。**

## 4 · 按结论类型分的自检清单

### 4.1 要下**否定结论**（「没有」「零调用方」「死代码」「做不了」）

- [ ] `claim-check tree` —— 树是不是旧的？旧树上的「没有」不算数
- [ ] **追一层间接调用**：re-export / 高阶函数 / 依赖注入 / 字符串键分发 / 事件订阅
      —— 这些 grep 一次都看不见
- [ ] **金丝雀选对了对象吗**：它必须是「**只可能存在于我要测的那个维度里**」的东西。
      随便找个词能 grep 到，只证明 grep 能跑，不证明结论对
- [ ] 报告里**同时给出金丝雀的命中证据**。没有金丝雀证据的否定结论 = 无效结论

### 4.2 要区分**三种「不工作」**（修法完全不同，混了必修错地方）

| 形态 | 判据 | 修法 |
|---|---|---|
| **没接线** | 调用方集合里**只有 test** | 接线 |
| **接了线没数据** | 有 src 调用方，但输入恒空/恒假，分支从未进入 | 补数据或删死分支 |
| **接了线接错地方** | 有 src 调用方，但挂在错误的路径上 | 补挂载点 |

> **只有 test 引用 = 已排练，不是已实现。** 测试咬的是**函数**，不是**链路**。

### 4.3 要说**「这道门有牙」**

- [ ] **金丝雀与主逻辑共用同一份实现** —— 不许各抄一份正则。
      抄了就是装饰品：改主正则时金丝雀拿旧的去测、照样绿
- [ ] **变异真的生效了**：改完**读回文件确认差异**。sed/正则没匹配上是常态
- [ ] **改名换成不含原子串的新名**（`foo`→`fooXX` 这种，`toContain("foo")` 照样过）
- [ ] **改行为要语义反转**，不是微调
- [ ] 变异后门**当场红**，还原后复绿，`git status --porcelain` 干净
- [ ] 诚实位（「金丝雀 N/N 命中」这类计数）**现算，不写死**

### 4.4 要说**「某某会随某分支进正线」**

- [ ] `claim-check has <它> <目标分支>` —— **判据是祖先关系，不是文件存在性**。
      文件在老支线上恰好也存在时，「文件在不在」这个探针**恒真**
- [ ] 只并「**它的 agent 已经交回**」的分支。agent 还在跑 = 你并的是中间态

### 4.5 要说**「某个后台任务卡死了 / 还在跑」**

- [ ] **先判机器**：`uptime` < 静默时长 ⇒ 容器刚重启 ⇒ 全体**阵亡**而非卡死
- [ ] **判据是「还在不在动」，不是「跑了多久」**。跑 40 分钟输出一直在长 = 正常；
      跑 8 分钟 8 分钟没动 = 卡死。**只看时长必然误判**
- [ ] **二次采样**，且**采样对象要对**：日志字节可能被缓冲（TEST 阶段常见）。
      更可靠的是**它自己的进程树**的 CPU 时间与子进程 pid 更替 ——
      全机 `ps | grep vitest` 会把**别人的** vitest 也算进来
- [ ] 杀进程**别用会自匹的模式**：`pkill -f "scripts/gate.sh"` 会把探针自己也匹进去 ⇒ 自杀

### 4.6 要跑一条命令并**据其退出码下结论**

- [ ] `out=$(cmd 2>&1); rc=$?` —— **禁止** `cmd | tail -n; echo "EXIT=$?"`。
      管道里 `$?` 取的是**末端命令**的退出码（`tail`/`head` 恒 0）
- [ ] 失败时打印 `error TS|FAIL|AssertionError` **原文**，不许只 tail 几行把错误挤掉

## 5 · 派单时必须写进 WO 的两条环境前置

被 dev 顶回来过多次，一律写进派单模板：

```bash
# ① 分支对不对：判据是祖先关系，不是文件存在性
CANON=origin/claude/inspiring-gates-aqczjg
git fetch origin && git merge-base --is-ancestor HEAD $CANON \
  && { echo "HEAD 是 canonical 的祖先 ⇒ 落后，必须重开"; git checkout -B <wo-branch> $CANON; } \
  || echo "HEAD 不落后，可原地开工"

# ② worktree 可能没有 node_modules / contracts 可能未 build
pnpm install --prefer-offline
pnpm --filter @platform/contracts build   # 不装会报与本单无关的假红
```

不写这两条，dev 会在一个落后上千提交的树上开工，把已实现的读成「不存在」，
得出**与事实相反**的结论 —— 这不是假想，一天之内骗到过 4 个 dev。

## 6 · 派活与「等」的关系（铁律 2 的操作面）

**被非产出动作阻塞的，只有它自己。** gate / 测量 / 取证 / 复验 / bisect / 写审计文档 /
等某个 agent 回来 / 读代码想清楚 —— **一律不构成派活的前置条件**。

> 一句话判据：**「我现在手上这件事，产出的是可交付物，还是只是知识？」**
> 若是后者，**它同时必须有 agent 在跑**，否则就是调度失误。

每次想说「我先去测/先看看/先等一下」之前，逐条过：

- [ ] 当前并发 agent 数 vs 上限（重 ≤1 且 gate 跑着时为 0 · 中 2–3 · 轻不设限）。**差额 > 0 就是欠派**
- [ ] 待派队列里有没有**不依赖我这次测量结果**的单？有 ⇒ **现在就派**
- [ ] 我这次测量**会不会改变某张待派单的内容**？不会 ⇒ 那张单立刻派；会 ⇒ 只推迟**那一张**
- [ ] 我要等的那个 agent，它的产出是**别的单的前置**吗？不是 ⇒ 别等，继续派

**并发的真实约束不是「agent 数量」，是「同时跑 datacore vitest 的数量」**（4 核机）。
错的不是「6 个 agent」，是「6 个都是重画像」。

## 7 · push 与过 gate 是两回事

- 推旁支**零风险、零成本**；gate 只决定「能不能进 canonical」，**不决定「要不要落盘」**
- **每完成一个可命名单元就 commit + push**，起 gate 之前先确认被验的那个 commit 已有远端分支
- 「gate 跑着」**不是**「工作已落盘」

沙箱定期重启。本仓真丢过一次 dev 产出；另一次 12 个提交 / 3397 行零远端分支，
靠磁盘没被清才幸存。
