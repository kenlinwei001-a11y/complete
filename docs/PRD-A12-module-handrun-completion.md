## 0. 本体引用与影响（强制）
- **触及对象类型**（§2 全域）：被审模块涉及的 `Connection`/`ObjectInstance`/`OntologyType`/`Agent`/`Skill`/`Rule`/`Calibration`/`Policy` 等——A12 是**横切验收**，不新增对象，但会**暴露并修各模块接缝缺口**。
- **触及链路**（§3 全链）：沿每模块的关键链路 hand-run（如连接器：`建连接→同步→RawDataset→物化→对象可见`；Agent 页：`配 Agent→绑工具/技能/规则→场景调用→出答案`）。
- **触及事件/数据流**（§4）：验证产出操作发对应事件、下游订阅刷新（D-29 实测，非单测）。
- **触及不变量**（§5 全部）：A12 是 R1–R14 的**实跑体检**——尤其 **R10 D-29**（事件刷新真生效）、**R11 全链闭包**（端到端真跑通）、**R13 可溯源**（数字悬浮可溯）、**R3 entitlement**（关功能真 404）。
- **关闭/影响断点**（§8）：是 G-1…G-8 的"实跑复验"——AUDIT-hand-run 已记数据构建主线断点；A12 覆盖其余模块。
- **门禁**（§7）：跨服务联调冒烟 + 各模块 hand-run 清单（新增 `docs/AUDIT-hand-run.md` 逐模块小节）· `debattery:check`/`chain:check`/`ontology:check`。
- **回写承诺**：每模块审完回写 `AUDIT-hand-run.md` + 命中真缺口回写本体 §8（新断点登记或闭合）。

## 1. 目标 / 非目标
### 目标
1. **系统化 hand-run**：对剩余模块逐一起真服务（datacore:4001 + agentcore:4002，SEED_DEMO，跨系统配齐），以 admin 真请求走端到端，记"声称完成 vs 实际能用"。
2. **缺口清单 + 修复**：每模块产出"体验验收项 × 实测结果"表（✅/◐/🔴 + 锚点），🔴/◐ 项开修复任务或就地修。
3. **优先模块**：连接器（建连接/同步/可溯）· 对象浏览（A4 实跑）· Agent 页（配置/绑定/调用出答案）· 规则库 · 校准 · 权限行级过滤 · 场景启动器（PUBLISHED 可见性，AUDIT 已记缺口）。
4. **固化**：把"亲手跑通"的关键路径沉淀为跨服务冒烟回归（守不回潮）。

### 非目标
- 不追求一次审完所有 20+ 页；按价值/风险排序，逐模块交付（每模块一小节 + 修复）。
- 不替代单测；A12 是**真服务真请求**的体验级验收（fde-delivery SOP）。

## 3. 设计（hand-run 矩阵 + 逐模块小节 + 修复回路）
### 3.1 hand-run 矩阵（每模块统一格式）
- 复用 `AUDIT-hand-run.md` 表式：`体验验收项 | 实测结果(✅/◐/🔴) | 锚点/证据 | 修复动作`。
- 每模块定 3–6 个**体验级验收项**（非单测断言），如连接器：① 建连接默认 category（A11）② 同步产 RawDataset 可溯 ③ 物化对象 A4 可见 ④ 事件刷新列表（D-29）。
### 3.2 真服务跑法
- 起 datacore:4001 + agentcore:4002（SEED_DEMO，SERVICE_TOKEN + AGENTCORE_BASE_URL 配齐），admin（或 X-Debug-User）真请求；记录请求/响应/界面证据。
### 3.3 修复回路
- 🔴/◐ 项 → 就地修（小）或开任务（大）→ 修后重跑该项转 ✅ → 关键路径补**跨服务冒烟**回归（守不回潮）。
### 3.4 模块排序（价值/风险）
1 连接器(+A11) → 2 对象浏览(A4) → 3 Agent 页(端到端调用) → 4 场景启动器(PUBLISHED 可见) → 5 规则/校准/权限。

## 4. 契约 / 端点
- 无新契约/端点；A12 是验收 + 修缺口。新增/修订**跨服务冒烟测试**（`apps/datacore/test/xservice-smoke.test.ts` 扩各模块关键路径）。

## 5. 关键流程（每模块）
起真服务 → 按验收项真请求走一遍 → 记 ✅/◐/🔴 + 证据 → 🔴 修 → 重跑转 ✅ → 关键路径补冒烟 → 回写 `AUDIT-hand-run.md` 小节 + 命中真断点回写本体 §8。

## 6. 非功能（§5）
全 R1–R14 实跑体检；尤重 R10/R11/R13；产出为真请求证据（非单测绿）。
