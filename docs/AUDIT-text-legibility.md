# AUDIT · 屏上可读性（WO-R9-CONTRAST · 2026-08-14）

> **一句话**：仓主实拍读不了的那 16 个元素，量出来是 **4.52:1 —— 它「通过」WCAG AA**。
> 因为 WCAG 的 4.5 是给**正文尺寸的拉丁字母**定的，**公式里根本没有字号**，而那 16 个是 **9–10px 的中文**。

## §1 判据怎么定的 · 为什么

### 1.1 公式

```
required(S, w) = max( 3.0 , 72 / S_eff )
S_eff          = S × (w ≥ 700 ? 24/18.66 : 1)
```

### 1.2 两个锚点全部来自 WCAG 2.1 SC 1.4.3 自己 —— **零自由参数**

| 锚点 | 出处 | 本门取值 |
|---|---|---|
| 正文阈值 **4.5:1** | SC 1.4.3 正文 | 参照尺寸取**浏览器默认正文尺寸 16px**（CSS `font-size: medium`） |
| 大字阈值 **3.0:1** | SC 1.4.3 大字豁免（≥18pt = **24px** 常规） | 24px |
| 粗体折算 **1.2862** | 同一条豁免的粗体分支（≥14pt = **18.66px**） | 24 / 18.66 |

由 `4.5 = k/16` 与 `3.0 = k/24` **联立**解出 **k = 72，且指数恰好是 1**。
**两式相容本身就是这条反比律的证据**：若真实关系不是反比，这两点解不出同一个 `k`。

于是本门**不与 WCAG 冲突，而是把它的阶跃函数补成连续曲线并向小字外推**：

| 字号 | 16px | 24px | 14px | 13px | 12px | 11px | 10px | 9px | 8px |
|---|---|---|---|---|---|---|---|---|---|
| 阈值 | **4.5**（=WCAG） | **3.0**（=WCAG） | 5.14 | 5.54 | **6.00** | 6.55 | **7.20** | **8.00** | 9.00 |

### 1.3 诚实边界（本公式**唯一**一处判断，摆在这里让人可以直接反对）

- **16px 这个锚是「取」的不是「算」的**。WCAG 没写正文参照尺寸；取浏览器默认值 16px 是外部既成事实，但仍是一个**选择**。若取 14px，则 `k=63`，整张表等比下调 12.5%（10px 要 6.3 而非 7.2）。
- **反比律是从两点外推的**。24→16px 区间是**内插**（两端有 WCAG 背书）；12px 以下是**外推**，没有 WCAG 背书。外推方向与 APCA（WCAG 3 草案，把字号/字重写进查表）一致 —— 小字要更高对比 —— 但本门**不声称**复现了 APCA 的数值。
- **本公式算的是颜色对比度，不是笔画对比度**。中文 9–10px 时笔画与抗锯齿糊在一起，那部分损失公式**测不到** —— 判据 B 就是为此存在的。

### 1.4 判据 B（字号硬底 12px）**不是又一个自由参数，是 A 的推论**

判据 A 是**颜色**判据，它默认「提高对比度总能补回来」。对 9–10px 的中文这个默认是假的，**而且能在本仓调色板上现算出来**：

- 暗色最亮面（`--panel-glass` 半透白 veil 叠在 `--bg` 上 ≈ `#2f3e5b`）上，三级文本令牌的可用窗口是 **4.44 – 9.14**。
- 判据 A 在 **10px** 要 **7.2**。让三级文本达到 7.2 需要中性灰 **#d3d3d3**，而二级文本当时的等效灰只有 **~#bbb**
  ⇒ **三级会比二级更亮，层级当场反转。**

⇒ **10px 及以下的中文正文，在本调色板内无解**，唯一的修法是**升字号**。
12px 是 A 与调色板的**交点**：`required(12) = 6.0`，而三级文本在 6.05 时仍能与二级（7.3）、一级（9.1）拉开可辨的档。
**换调色板 ⇒ 交点自己会动**，FLOOR 跟着重算，不是钉死的常数。

### 1.5 判据 C（令牌矩阵）—— 本门唯一「精确」的那一条

A/B 是站点级判据，靠静态解析近似。C 不靠任何近似：把 `tokens.css` 里声明的「文字令牌 × 表面令牌」逐对在**三套主题各自的**取值下现算，要求 ≥ `required(12px)`。
**无基线，必须绿。** 它守的正是本次事故的根：**调色板本身在最亮的那个面上就不够用**。

### 4.1 为什么要「拆职」而不是把语义色调亮

语义色与领域色在本仓身兼两职：既当**填充/描边**，又当**文字色**。两职对颜色的要求**方向相反**。实测（三套主题最差面）：

| 令牌 | 暗色 | 冷蓝 | 暖砂 |
|---|---|---|---|
| `--danger` | 3.11 | 3.02 | 3.06 |
| `--warn` | 5.65 | **1.66** | **1.68** |
| `--ok` | 4.64 | 2.02 | 2.05 |
| 领域色 `--c-*` | 3.3–5.2 | **1.8–2.9** | **1.9–3.0** |

直接把这些令牌调到文字可读，图元就会褪成一片粉/淡黄，「红=风险」的语义当场失效。
故 `--X` 保持原值继续当填充（**视觉识别不变**），新增 `--X-txt` 只作文字色，**HSL 只动 L**（色相/饱和不变）。

### 5.1 建门过程中门**真的**红过两次（不是造出来的变异）

1. **CSS `font:` 简写**：门第一版只认 `font-size:`，`.optSub { font: 9px … }` 这类（本仓 **72 处**）一处都扫不到 —— 真浏览器复测时那 35 个 9px 元素还红着，而门报「这些文件干净」。
2. **同一个病换马甲**：React 内联样式键叫 `font` 不叫 `fontSize`，`SandboxView.tsx` 顶栏三处 `style={{ font: "600 10px …" }}` 同样扫不到。
3. **主题解析器**（这条是**金丝雀在第一次运行时当场判 RC=2 逼出来的**）：第一版用 `css.indexOf(":root {")` 找块 —— 写成 `:root{`（无空格）就返回 null；且 `indexOf(":root")` 会先命中 `:root[data-theme="light"]` 的**前缀**（前缀匹配 ≠ 相等匹配）。

前两条已固化为**常驻回归金丝雀**。

### 5.2 我自己也犯了本单立的那条纪律（记账）

批量把 `fill: var(--X)` 换成 `-txt` 时，我把 **9 处图形**也换了 —— `fill` 在 SVG 里**同时**是文字色和图形填充，而「填充要饱和、文字要对比」正是本单立的拆职纪律。
被 `chain-line-map.seam.test.tsx`「⑤ 增值段用不同图元/颜色」当场咬住。
修正时第一版又用了**词形启发式**（类名里含 `text|label|value` 即判为文字），把 `.stationValueAdd`（一个圆圈）按 "Value" 误判 ——
形态同样是铁律 0.6：**「我用『类名里有 value』当作『它是文字』的证据，而前者并不度量后者。」**
最终判据改成**读 TSX 现算「该类名是否真的挂在 `<text>/<tspan>` 上」**。

## §7 门的诚实边界（不许把本门当成「可读性已被证明」）

1. **底色靠「该主题最差面」代替真实层叠** —— 「这段字最终落在哪块颜色上」是渲染期事实，源码里不存在。故彩色实心块上的**反相字**会被误报。**偏保守：登记进棘轮基线并逐条写明 why，不放宽判据**（放宽会同时放掉真违规）。
2. **只判「同一声明块里同时写了 `color` 与 `font-size`」的单元**；只写其一的靠继承，静态判不了 —— 计入 `unjudged`（实测 1352 处）**只报数不红**。
3. **看不见文字内容 ⇒ 分不出中文与拉丁**，按尺寸一刀切（**比命题严**，纯数字/拉丁微标签也被咬）。
4. **`opacity` 量不到** —— 它是「静态 CSS 里看不见的降对比」。本单实测两处（0.6 / 0.75）都是真浏览器才现形的。**这一条只有真浏览器测得到。**
5. **`currentColor` / `inherit` 一律跳过。**
6. **扫描面只有 `.css` 与 `.tsx`** —— 写在 `.ts` 字符串字面量里的**内嵌 CSS** 看不见。
   实测本仓有一处：`apps/frontend-shell/src/views/graph/mappingExport.ts:69/75`
   （导出成独立 HTML 的报告模板，`color:#9aa8b6; font-size:11px` 压白面 ≈ **2.4:1**）。
   **⇒「全前端 `<12px` = 0」这句话要读成「本门扫描面内 = 0」**，两者不是一回事。
   **本单没顺手修它**：它是**导出产物**（脱离应用主题系统、自带写死配色，范围边界也没覆盖 `.ts`），
   判它需要另一套「导出文档」的口径；混进来会让本门的命题变糊。**登记在此，留给专门的单。**

⇒ **「屏上读得了」的最终判据仍是真浏览器逐元素量 + 亲眼看屏；门只保证增量不再劣化。**
