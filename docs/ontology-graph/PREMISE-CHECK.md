# 派单前提自检器 · `premise-check.mjs`

> 本体图谱（`docs/ontology-graph/`）的**第一个消费方**。
> 一份没人消费的图谱就是一本机器写的台账，第二天没人看。这个工具是那个消费方。

```bash
node scripts/ontology-graph/premise-check.mjs docs/WO-XXX.md
node scripts/ontology-graph/premise-check.mjs docs/WO-XXX.md --graph docs/ontology-graph
node scripts/ontology-graph/premise-check.mjs docs/WO-XXX.md --md          # 贴进报告用
node scripts/ontology-graph/premise-check.mjs --selftest                   # 回归用例 + 金丝雀
```

## 一、它要拦的是什么

2026-09-12 一个会话里，审核方**连续五张派单的前提被 dev 实测推翻**。五条都是真的，不是假想：

| # | 派单里写的 | 实测真相 | 当时用的错判据 |
|---|---|---|---|
| 1 | 求解器 **60** 个 | **63**（`ALL_SOLVER_CATALOG` = 23+18+22） | `grep -c` 的命中数 |
| 2 | `args-schemas.ts` **是空的** | **22 行薄 re-export**，真表在 `packages/contracts/src/solver-args.ts`，已有 **11** 条 | 打开看了一眼文件短 |
| 3 | 规则 **39** 条 | **30**（`BATTERY_RULES`；同区间裸 `/C\d\d/` 命中 **69** 次，多数在注释里） | grep `C\d\d` 的命中数 |
| 4 | description 是**一句话** | **p90 301 字 / max 714 字 / 全量 16,450 字节**，喂不起 | 抽样看了两条 |
| 5 | `lineGranularity` **零调用方** | **6 处 src 引用**（`portfolio.ts` ×5 + `service.ts:3512`） | grep 直接命中数，没追间接层 |

**共同形态**（CLAUDE.md 铁律 0.6 句式）：

> **「我用一次 grep 的命中数当作事实，而真相要用真数组 / 真服务 / 真引用图去量。」**

代价不是记账错误，是**白做**：`WO-PROP-QTY` 那张单 dev 实测后一行代码没改就顶了回来，
整张单的前提已过期 9 天。这个工具要在**审核方下笔的那一刻**把这类错拦下来。

## 二、⛔ 它不是一道门

仓主禁令 3 冻结了新增门 / 棘轮 / 基线 JSON。本工具：

- **不输出红绿判定**，只输出**对账表**；
- **不注册进 `pnpm gates`**，不进 `scripts/run-gates.mjs` 名单；
- **对账结论一律 `rc=0`**。

| rc | 含义 |
|---|---|
| **0** | 报告已产出（**无论有没有差异**） |
| 3 | 用法错 / 读不到派单文件 |
| 4 | **工具自证失败**（内置金丝雀不中）⇒ 拒绝输出任何否定结论 |

## 三、它抓的五类声明

| 类 | 派单里长什么样 | 图谱怎么核 |
|---|---|---|
| **① 计数** | 「求解器 **60** 个」「规则 **39** 条」 | `INDEX.yaml` 的 `registries[]`（带 `source` + `breakdown`）；缺则退化到 `counts.*`，再缺则退化到同标签原子条数 |
| **② 零调用方 / 引用计数** | 「`lineGranularity` 零调用方 / 是死代码」「有 **6** 处调用方」 | 该符号所有同名原子的 `state` 与 `inbound.src` / `inbound.test`，**合并去重**后比对 |
| **③ 空文件** | 「`args-schemas.ts` 是空的 / 只有个壳」 | 该文件的原子数与 `reexportOf`；**全是 re-export ⇒ 报「不是空的，是薄 re-export」** |
| **④ file:line 坐标** | `` `service.ts:3512` `` | 该文件 ±容差行内有没有原子**声明**或对某原子的**引用** |
| **⑤ 长度** | 「description 是一句话」「p90 **301** 字」 | `INDEX.yaml` 的 `fieldStats[]`；缺则退化到图谱侧 `brief` 长度分布（**并在第四列明说这是降级**） |

### 抽取纪律（噪声控制，和抓错一样重要）

本仓实测过一个探针「机器空闲时报 0 正确、忙时把 worker 数成 2」——
**「错的时候能抓」不度量「对的时候不吵」。噪声大的工具没人会跑第二次。**

**下面六条规则没有一条是拍脑袋定的 —— 每一条都对应一次在真派单上实测到的误报。**

1. **代码围栏与行内代码里的数字不当声明**（`` `grep -c` `` 里的数字不入账）。
2. **上下文窗口一律不跨行**。实测教训：±24 字的全局窗口跨过空行把下一段的「求解器」吸了进来，
   于是「…`service.ts` 1 处写），\n不是死代码。\n\n求解器的 description…」里的**「1 处」被认成了「求解器 = 1 个」**。
   形态：「我用『字符距离近』当作『说的是同一件事』的证据。」
3. **名词必须贴着数量结构，不能只是出现在同一行**（`docs/WO-SUITE-skill-migration.md` 三条连着误报）：
   - 「把迁移 PRD 拆成 **5 张可派发的 WO**，把依赖关系与**切片**顺序定死」→ 曾报成「切片 = 5 条」
   - 「今天 7 份，与意图零引用**边**」→ 曾报成「边 = 7 个」
   - 「使 32 份 Plan 降为…」（上句尾还留着「边」）→ 曾报成「边 = 32 个」

   ⇒ 现在只认两种中文数量语序：**量词后紧跟名词**（只许隔「的」）·
   **名词与数字之间 ≤8 字且中间无断句标点、无另一个数字**。
   形态：「我用『名词与数字同行且距离近』当作『这个数在数这个名词』的证据。」
4. **否定词守卫**。「`lineGranularity` **不是**死代码」里的「死代码」⛔ 不许入账 ——
   否则工具会对一句**正确的话**报不一致。守卫词：不是 / 并非 / 而非 / 不算 / 远非 / 绝非 / 称不上 / 不属于 / 误以为 / 曾以为 / 别写成 / 不能写成 / 不再是。
5. **定性长度谓词要系词，且不许当定语**（两次真误报）：
   - 「（**不改一行代码**）」曾被读成「`params` 的长度只有一行」（`WO-66-RULES-FIRST-CLASS.md:114`）
     ⇒ `一句话 / 一行 / 一句` 这档必须紧跟在**系词**后（是 / 只是 / 就是 / 仅 / 只有 …）。
   - 「它是**一句话的决策**，不是工作量」曾被读成「`plan` 是一句话」（`WO-SUITE-skill-migration.md:521`）
     ⇒ 谓词后紧跟「的」= 定语，整句不在说长度，不入账。
6. **一行有多个候选时⛔ 不挑第一个**。「（`plan` vs `steps`）」里挑 `plan` 纯粹因为它排在前面。
   形态：「我用『它排在这一行的第一个』当作『这句话在说它』的证据。」
   ⇒ 候选唯一才敢用，否则进「已识别·无法对账」区并列出全部候选。
7. **词表覆盖不到的名词一律不硬猜**，进「已识别·无法对账」区而不是进差异区。
   **「我没找到」和「它不存在」是两个不同的命题** —— 硬猜等于把前者写成后者。
8. **相符的行照样打印**。让读者看见它核过了，而不是靠沉默推断。

**实测噪声基线**（全仓 `docs/*.md` 445 份逐份跑过，零崩溃、零非 0 退出）：
`wo-right.md`（7 条可核声明）产出 **0 条「不一致」**；
`WO-66-RULES-FIRST-CLASS.md` 从 1 条误报降到 **0**；
`WO-SUITE-skill-migration.md` 从 4 条误报降到 **0**。

## 四、第四列：图谱这一格可不可信（本工具最重要的设计判断）

对账表四列：**你写的是 X · 图谱说是 Y · 证据在哪 · 图谱这一格可不可信**。

**第四列不许省。** 图谱自己会错 —— 立项当天审核方的探针就报过两个假数
（「只有 test 引用 = 0」「`buildSliceIndex` 入边 = 0」），**两个都是工具坏了，不是代码干净**。

> **判据：一个读对账表的人，必须能分清「我写错了」和「图谱抽漏了」。分不清的表等于没用。**

第四列不是一句形容词，它由四个**可验证**的来源合成：

| 来源 | 怎么看 |
|---|---|
| **(a) 金丝雀** | 该维度在 `INDEX.yaml` 的 `canary` 段有没有探针、`ok` 是不是 true、**`expect` 与 `actual` 自不自洽** |
| **(b) 分片健康** | 承载这条结论的 YAML 分片解析有没有告警（块标量 / flow 残留 / 缩进超子集 / 整片解析失败） |
| **(c) 盲区清单** | 该维度有没有被图谱自己的 `INDEX.blindSpots`（或 README「看不见什么」段）点名 |
| **(d) 本工具的降级** | 这一格是图谱**直接度量**的，还是本工具**代答**来的（如用 `brief` 长度代答 `description`） |

### 四个可信度等级

| 等级 | 什么时候出现 | 读表的人该怎么办 |
|---|---|---|
| **✔ 可信** | 有专属金丝雀且自洽 · 分片无告警 · 未落盲区 · 无降级 | 差异 ⇒ **改派单** |
| **◑ 存疑** | 无专属金丝雀（只有维度级泛化探针）/ 分片有告警 / 用了降级代答 / 盲区清单缺失 | 差异 ⇒ **先查图谱，再改派单** |
| **✗ 不可信** | 金丝雀 `ok:false`，或标了 ok 而 `expect`/`actual` **自相矛盾** | **别信这一行**，先修图谱 |
| **⛔ 图谱自认盲区** | `blindSpots` 里有一条 `dims` **点名**了这个维度 | 这类结论图谱**永远**给不实，靠它判事等于自欺 |

### ⚠ 盲区清单必须带 `dims`，不许只写散文

```yaml
blindSpots:
  - dims: [NOREF, REFCOUNT]
    text: "引用图只解析静态可见的调用；re-export / 高阶函数 / 依赖注入 / 字符串键分发 / 事件订阅这五类看不见"
```

只写字符串时，本工具只能拿关键词去撞，而**「两段文字有共同的词」不度量「它们说的是同一件事」**。
实测撞错过一次：「引用图看不见 **re-export** 形式的调用」（说的是 `NOREF`）被撞到了
**空文件声明**（`EMPTYFILE`，因为那条结论里也有 re-export 这个词）头上，
凭空给一条本来可信的结论扣上「图谱自认盲区」。
⇒ 现在：`dims` 命中才敢断言「自认盲区」；散文关键词命中只降到「**疑似**落在盲区」。

### ⚠ 金丝雀也分「专属」和「隔壁维度的」

`canaryFor` 先拿本行的具体符号 / 文件 / 注册表来源去撞 `probe`（词元**由长到短**试），
撞不到才退化到维度级关键词。退化时会在第四列**明写**：

> ⚠ 这条探针验的是「buildSliceIndex 入边」，不是本行的 `lineGranularity`；它只背书「这个维度的抽法能跑」。

词元按长度从长到短试，也是实测逼出来的：来源串 `apps/datacore/src/catalog.ts:279 ALL_SOLVER_CATALOG`
的短词元 `catalog.ts` 会先撞上「catalog.ts description 字段长度分布」那条**长度**探针 ——
于是一条**计数**结论被一条**长度**金丝雀"背书"了。同一个形态又来一次。

## 五、几个写死的数，以及它们的理由

### `--line-tolerance`，默认 **±12 行**

图谱记的是 `generatedFrom` 那棵树上的**声明行 / 引用行**；派单抄的坐标会随上游改动漂移。

- **12 ≈ 一个函数头 + 一段 JSDoc 的高度** —— 坐标写的是同一个符号时，漂这么多是常事。
- **再宽就会把隔壁符号认成「对上了」**，那比报不出来更坏（假绿）。
- ⚠ 即便对上了，第四列也会提醒：**`generatedFrom` 是哪个 commit；派单基于更新的树时，
  「±12 行内有东西」不证明是同一处。**

### 「一句话」的量化界 = **40 字**

定性长度声明（「是一句话 / 很短」）必须落到一个数上才能对账。取 **p90 ≤ 40 字** 为「确实是一句话」：
40 字是中文单句的常见上界。对照本仓实测：`CatalogItem.description` 的 **p50 是 49 字**，
**p90 是 301 字** —— 连中位数都超了这条线，所以「是一句话」这句判不一致，判得很稳。

### `registries` 与同标签原子的**交叉核对**

有 `registries[X].count` 时优先取它（它带 `source` 与 `breakdown`，可以逐段复算）。
同时会拿「图谱内 `tag=<selector>` 的原子条数」去互证，三种结果**都会写进证据列**：

- 两数相等 ⇒ `交叉核对：… 与注册表声明一致 ✔`
- 两数不等 ⇒ 降级说明「分片可能不全，本行取注册表声明」，等级降到 **◑ 存疑**
- **核不动**（词表没给标签选择器 / 图谱里没有该标签的原子）⇒ 照实写
  `**无法**与注册表声明互证，本行只有一个来源`

**「没做交叉核对」和「交叉核对过了」是两个不同的证据强度，不许含糊过去。**

## 六、工具自己的金丝雀（铁律 0.6）

> 任何 grep / 解析器 / 计数，在报出结论之前，必须先跑一个「已知必中」的样例。
> 金丝雀不中 ⇒ 报「**工具坏了**」，⛔ 不许报「没有命中 / 无此内容」。

**每次运行**（不只是 `--selftest`）都先把一段内置样例喂给 `extractClaims`，
必须抽到 `COUNT / NOREF / EMPTYFILE / COORD / LENGTH` 五个维度。抽不到 ⇒ **rc=4**，
打印「⛔ 抽取器坏了」，**拒绝**输出「本文件无可核声明」这类否定结论。

⚠ 金丝雀与主逻辑**共用同一份 `extractClaims`**，不是另抄一份正则 —— 抄了就是装饰品：
改主正则时金丝雀拿旧的去测、照样绿。

**变异反证（实测，证明它不是装饰品）**：把 `COUNT_UNITS` 里的「个|条」改成「ZZ个|ZZ条」后，
同一条命令从「本文件无可核声明」变成：

```
⛔ 抽取器坏了 —— 内置金丝雀样例抽不到 COUNT 维度。
   ⛔ 拒绝输出任何「无可核声明 / 没有问题」这类否定结论。「我没找到」≠「它不存在」。
   明细：EMPTYFILE@L4 NOREF@L6 LENGTH@L7 COORD@L8
RC=4
```

## 七、`--selftest` 跑的是什么

`scripts/ontology-graph/fixtures/` 下三份派单 + 两份图谱：

| 夹具 | 干什么用 |
|---|---|
| `wo-wrong.md` | 第一节那五条**真实错误**的原话 |
| `wo-right.md` | 同样五条，全部改成实测真值 |
| `wo-prose.md` | 纯散文、零事实声明 |
| `graph/` | 手写图谱夹具，**每一条都取自真仓实测坐标** |
| `graph-broken/` | 同上但 `counts:` 段被整段删掉 |

**五条用例 × 两个方向**：

- **方向 A**：`wo-wrong.md` 里每条都必须被点出来（判「不一致」）。
- **方向 B**：`wo-right.md` 里**一条差异都不许有**。
  ⚠ B 方向**不要求某类声明必须出现** —— 订正版把「是空的」改写成了「是薄 re-export」，
  那本来就不是一条空文件声明，**抽不到它才是对的**。硬要求它出现会逼工具去过度抽取，
  而过度抽取正是噪声的来源。

**加三条金丝雀**：

1. **纯散文** ⇒ 必须报「本文件无可核声明」，⛔ 不许报「全部通过 / 全绿 / PASS」。
   两者读起来很像，含义完全相反：前者是「我没核到东西」，后者是「我核过了，都对」。
2. **损坏的 `INDEX.yaml`**（`counts` 段删掉）⇒ 必须报「**图谱不可信**」并**产出 0 条对账行**。
   ⛔ 不许把读不到的 counts 静默当 0 —— 那会把「求解器 60 个」对成
   「图谱说 0 个，你多写了 60」，**一条把人支到完全错误方向的结论**。
3. **抽取器内置样例**（见上一节）。

## 八、⛔ 这个工具答不了哪类前提（诚实清单）

**这一节比前七节都重要。** 一个不说自己盲区的度量装置，会让人把「它没报」当成「没问题」。

| 答不了的 | 为什么 | 该用什么 |
|---|---|---|
| **「接对了、跑通了、但算错了」** | 图谱只记「谁引用谁」，**不记这条边算的对不对**。CLAUDE.md 铁律 1.5 那条 `9.75 / 9.75`（碳酸锂与铝箔各涨 15% 得到逐字节相同的成本压力）—— 链路完整、四包全绿、屏上有数，**本图谱一个字都看不见** | 铁律 1.5 判据一的**对照实验**：把 X 改成 X′，Y 必须按可预言的方式变 |
| **「接了线没数据」** | 一条 `src` 入边可能挂在一个恒假的分支上。图谱只说「接了线」，不说「跑没跑到」 | 真起服务（`SEED_DEMO=1`）跑一遍那条链 |
| **「生产传的那个值有没有测试覆盖」** | 布尔/枚举开关的分支覆盖，图谱不建模（铁律 0.5 判据 6 那类假绿） | 核对生产实参与测试实参的交集 |
| **间接调用** | re-export / 高阶函数 / 依赖注入 / 字符串键分发 / 事件订阅 —— **静态引用图这五类一条都看不见**。所以「零调用方」这类**否定结论**，本工具**永远**只能给到「◑ 存疑」或「⛔ 自认盲区」，给不到「✔ 可信」 | 铁律 0.5：沿调用链再追至少一层，追到触发条件为止 |
| **图谱本身的新鲜度** | 只能回显 `generatedFrom`，**不能判断它是不是落后于你的树**。图谱没重跑，它会拿旧答案信心十足地对账 | 先看 `generatedFrom` 是不是当前 canonical |
| **散文式前提** | 「这一层信息架构不合理」「用户找不到入口」这类判断没有可对账的事实声明 | 五视角 LOOP（铁律 3） |
| **词表外的名词** | `LEXICON` 只覆盖 求解器 / 规则 / 参数模式 / 切片 / 原子 / 边 / 对象类型 / 事件 / 门。其余名词的计数声明进「已识别·无法对账」区 | 扩词表，或在图谱里加一条 `registries[]` |
| **同名不同物** | 词表把名词映到**一个**注册表，但平台里「切片」至少有三份互不相干的实现（本体切片 / 导航切片 / 目录里那 2 条硬编码切片），「边」也既指引用图的边又指资源关系图的边。实测：`PRD-v2-slice.md` 里「资源关系图 = **2 条边**」被拿去和**引用图**的边数对账 —— **数字抽对了，比的不是同一个量** | 证据列**始终点名**它比的是哪个注册表、来源在哪一行；读到名不对物 ⇒ 这是词表该扩，不是派单写错 |
| **抽取器覆盖面** | 符号或文件在图谱里查不到时，本工具**分不开**「抽取器没覆盖该包」与「它真的不存在」，只能标明这一格「算『图谱抽漏了』的嫌疑更大」 | 查 `INDEX.atomShards` 覆盖了哪些包 |

## 九、给图谱抽取器（`WO-ONTOGRAPH`）的两条请求

本工具在这两处**只能降级代答**，抽取器补上就能升到「✔ 可信」：

1. **`INDEX.registries[]`** —— 每条注册表的 `name` / `aliases` / `count` / `source` / `breakdown`。
   没有它时只能拿「同标签原子条数」代答，而分片不全时那个数**必然偏小**。
2. **`INDEX.fieldStats[]`** —— 产品字段的长度分布（`n` / `minChars` / `p50` / `p90` / `maxChars` / `totalBytes`）。
   没有它时只能拿图谱侧 `brief` 的长度代答，而 **`brief` 是抽取器写的摘要，不等于产品字段本身**。

第三条不是请求是**要求**：`blindSpots[]` 每条**必须带 `dims`**（见第四节）。
