# 反思 · Maven 是做什么的 / 独特性 / 什么才是"具备 Maven 独特性"的问题

> 用户反问：先想 Maven 做什么、独特性是什么，再想哪些问题真具备 Maven 独特性。
> **审核方自纠**：前三批 30 题大多是"系统有没有对应求解器"——那是测"能不能算 X"，**不是**测"这题是否需要 Maven 独特性"。好分析师 + BI + 单源 + Excel 能近似答出其中一大半。本文重做这层思考，并据此重设题。

## §1 Maven 是做什么的（本质）

- 源起 Project Maven（2017·DoD）：用 AI 把海量 ISR/传感器影像**自动处理成可决策情报**，压缩"传感→决策"时间。
- 演为 Maven Smart System（Palantir）：把传感器+情报+后勤等**异构数据融成一张作战/决策图**，AI 辅助、**人在环**、跨指挥层级**在接缝处压缩决策→行动**。
- **本质一句话**：把**散落在多个系统里的异构数据，融成可决策可行动的统一图景，在系统与人的接缝处把"数据→决策→行动→学习"压到最短，且全程可问责。**

## §2 Maven 的独特性（不是什么 / 是什么）

**不是**（这些 BI+ML+好分析师都能做·不算独特）：
- ❌ 算得快 / 某个预测模型 / 某张看板 / 查询既有数 / 单源分析。

**是**（独特在"接缝"·价值不在单点）：
| 独特性 | 含义 | 为何单一工具/人做不到 |
|---|---|---|
| **① 本体即操作层** | 散数据→语义连接的**可决策可行动对象**（活体数字孪生） | BI 给你表/图你只能"读"·本体让你在其上"推理+行动" |
| **② 行动闭环+写回** | 答案不止数字·是**可执行的行动**+建模后果+写回真实系统+学习 | BI 只读·不闭环·不写回 |
| **③ 接缝处的决策压缩** | 跨系统/跨部门筒仓·把"数据→决策→行动"从天压到分 | 价值在**筒仓之间**·没人单独拥有全图 |
| **④ 冲突/不确定下融合** | 多源各执一词时**带置信+溯源**融成一张图 | 单源没有冲突·多源冲突是"融合"真难点 |
| **⑤ 人机协同+可问责** | AI 提议·人决断·**全链可审计**(为什么这么定·谁担责) | 自动模型给不出问责链·军用/受监管的命门 |
| **⑥ 可重定向** | 同平台配置即换任务/换域·不重写 | 定制系统换域=重开发 |

> **核心**：Maven 的护城河**不是任何一个 solver（算）**，是**连接组织（本体把数据变可行动 + 决策行动写回学习 + 跨筒仓压缩 + 冲突下带置信 + 人机问责 + 可重定向）**。**价值在接缝，不在单点。**

## §3 "具备 Maven 独特性的问题" 判据

一题真具备 Maven 独特性，须**同时**满足（缺一就退化为 BI 能做）：
1. **跨筒仓**：答案要融**多个本不互通的系统/源**（不是单系统的数）。
2. **行动性**：输出不止"是什么"·是**可执行的决策/行动 + 建模后果**（甚至写回）。
3. **冲突/不确定**：源之间会冲突 or 有真假混合·需**带置信/溯源**。
4. **可问责**：能完整复盘**为什么这么定、谁担责**。
5. **没人能单独答**：单一分析师 + 单源 + Excel/BI **做不出**（必须靠平台的连接组织）。

**反例自检**（前 30 题里"看着像 unique 实则 BI 能做"的）：
- "宜宾产能预测多少"→ 单源(MES)+模型·**非 unique**（Q14 的产能那半）。
- "库存压了多少可释放现金"→ 单源(库存表)·**非 unique**（Q26）。
- "换型序列怎么排省工时"→ 单源(排程)·运筹模型·**非 unique**（Q27）。
- "认证要多久"→ 单源(合规进度)·**非 unique**（Q28）。
- 这些**有求解器≠Maven-unique**——它们是"系统能算"，但不需要 Maven 的接缝价值。

## §4 真正具备 Maven 独特性的问题（少而精·每个跨筒仓+行动+问责）

| # | 问题 | 为何 Maven-unique（5 判据） | 命中本系统 |
|---|---|---|---|
| **MU1·接缝盲区** | "我的 ERP/MES/SRM/财务各自都说没问题，合起来看有没有一个谁都没单独看见的系统性风险在形成？" | 跨筒仓融合·各源单看皆 OK·风险只在**接缝**·单系统答不了 | 🔴 **N1 缺口**（多源冲突/融合·我之前找到的硬骨头） |
| **MU2·行动后果跨域同时模拟+写回** | "把常州这批产能调给 A 客户，同时告诉我对 B 客户 SLA/供应商承诺/季度毛利/碳目标的连锁后果，我点确认就写回排产系统。" | 行动→**多域同时后果**→写回真实系统·BI 不闭环 | 📐 **E2(沙盘进决策)+writeback**·部分在(传导/Action R4)·一键多域待 E2 |
| **MU3·冲突下的可问责决策** | "两系统对同一事实给相反结论，我基于哪个做了决策、当时置信几分、三个月后审计能完整复盘为什么吗？" | 冲突仲裁+置信+**问责复盘** | 🔴 N1 + 📐 **WO-AUDIT-OBS** |
| **MU4·决策压缩** | "一个跨 5 部门的决策平时开 3 天会各拉各的数——能不能 5 分钟融成一张图、给建议、让有权的人当场拍板执行？" | 跨筒仓**速度压缩**+人机权限+行动 | 📐 SCENE 铺开 + E2 + Action R4（接缝速度是 Maven 灵魂） |
| **MU5·越用越准的机构记忆** | "上次类似决策的实际结果，系统自动学进去让这次更准了吗，还是每次从零？" | 行动→回采→**学习闭环**(机构记忆) | 📐 **WO-E1**（校准活体·越用越准） |
| **MU6·可重定向** | "明天把这套决策能力用到全新业务线/行业，配置即跑还是重开发半年？" | 同平台**换任务即用** | ◐✅ R14(电池+物流两行业验)·视图 layout 待 G-5 |
| **MU7·AI 提议人决断的问责边界** | "AI 这个建议哪部分是算的、哪部分是猜的、我该信几分、出事责任在谁？" | AI/人**问责边界**+置信诚实 | ✅ **dataMode 诚实位(强项)** + 📐 AUDIT(责任链) |

## §5 关键结论（这才是"copy Maven"真正该补的）

**把 Maven 独特性当标尺重看，真正 Maven-unique 的问题，恰恰命中本系统最弱处——不是巧合：**

- 本系统这几个月把**"算"（46 求解器 + 本体 + 诚实位）做到了 Palantir 同级**——所以我前 30 题"有求解器"的大多能答。
- 但 Maven 的**独特不在"算"，在"接缝"**：①跨筒仓融合(N1) ②行动闭环写回(E2) ③冲突可问责(N1+AUDIT) ④决策压缩(SCENE+E2) ⑤机构记忆(E1) ⑥重定向(R14)。
- **而这正是本系统的缺口清单**（N1 多源仲裁 / E 活体闭环 / AUDIT 问责 / SCENE 铺开）。

> **一句话**：**"copy Maven" 真正的功夫不在再加求解器（算已够），在补"接缝"——多源融合(N1)、行动闭环写回(E2)、越用越准(E1)、可问责(AUDIT)、决策压缩(SCENE 铺开)。Maven 的护城河是连接组织，不是算法本身。** 我前三批 30 题误把"系统能算"当"Maven-unique"，本文纠正：**唯一真正 Maven-unique 的强项是 dataMode 诚实位（AI 提议的置信边界），其余 unique 题都落在 D+E+AUDIT+N1 这些待建/缺口上。**

## §6 对路线图的影响（据此校准优先级）

| Maven 独特性 | 真 unique 题 | 该补的 WO | 现优先级 |
|---|---|---|---|
| 跨筒仓融合（接缝盲区/冲突） | MU1·MU3 | **WO-MULTISRC-ARBITER**（N1·之前漏立项） | ⬆ **应提为 P1**（这是 Maven 灵魂、且是缺口） |
| 行动闭环写回 | MU2 | **WO-E2** + writeback 深化 | P1（已在 D+E） |
| 机构记忆（越用越准） | MU5 | **WO-E1** | P1（已在 D+E） |
| 可问责 | MU3·MU7 | **WO-AUDIT-OBS** | P2→可提（问责是 Maven 命门） |
| 决策压缩 | MU4 | SCENE 铺开 + E2 | P2 |
| 重定向 | MU6 | G-5 视图跨域 | P2 |

→ **建议**：把 **N1 多源融合仲裁从"新发现"提为与 D+E 并列的 P1**——因为它是 Maven 独特性的**第一条（接缝融合）**，且本系统恰缺。D+E（行动闭环+机构记忆）已对；补上 N1（融合）+ AUDIT（问责），才是"接缝"补齐。

## §7 诚实边界 & 本体
- 这是**对 Maven 能力模型的思考 + 据此重设题**·非真起服务实拍；Maven 取**能力模型/工程模式**·不涉 targeting/武器（民用工业决策）。
- **自纠**：前三批 30 题混淆了"系统能算"与"Maven-unique"·本文以"接缝判据"重筛·结论是真 unique 题落在缺口上。
- **本体**：Maven 独特性↔本体能力——①本体即操作层(§2 本体/对象)·②行动闭环(R4+writeback Phase9B)·④冲突融合(N1·建议 G-N1)·⑤问责(R13 溯源+AUDIT)·⑥重定向(R14)。建议 **N1 提 P1·入 §8 G-N1**。
