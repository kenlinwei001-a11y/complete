# PRD · 推演沙盘 v3「三区布局」改造

> 状态：待实施 · 提出人：仓主（2026-08-13 第三次反馈，附参考图）· 起草：审核方
> 前身：`WO-SANDBOX-DECLUTTER`（收进抽屉）→ `WO-SANDBOX-UI-INTEGRATE`（口径降浮层）→
> `WO-SANDBOX-KPI-LAYER`（顶栏读数按偏离度分层）。**本单是第四轮，也是第一次动整页骨架。**

## §0 · 来历：前三轮都只改了局部，没有改**骨架**

| 轮次 | 做了什么 | 仓主的反馈 |
|---|---|---|
| ① DECLUTTER | 就绪认证/世界列表等收进诊断抽屉 | —— |
| ② UI-INTEGRATE | 每个读数后面那截 `（0–100 指数·全对象均值）` 降进 `?` 浮层 | 「推演沙盘为何还是这么乱的信息」 |
| ③ KPI-LAYER | 顶栏 16 个读数 → 第一层留 3 个（按偏离度），其余进 `<details>` | 「布局还是这么密密麻麻，没有分层？」 |
| ④ **本单** | **换骨架**：三区布局，一层只回答一个问题 | 「参考这个图片的布局……其他目前系统页面的信息都放到二级页面」 |

**前三轮为什么不够（诚实定性）**：①②③ 都是在**既有骨架内**做减法 ——
把东西收进抽屉、把说明收进浮层、把读数收进折叠。骨架本身没变：
主屏仍然是「顶栏 KPI + 四张计数卡 + 阻滞点长列表 + 底部三栏」，
**四块内容平级铺开，没有一块是"这一屏要回答的那个问题"**。
形态（铁律 0.6 句式）：**「我用『每一块都变小了』当作『这一屏分层了』的证据，而前者并不度量后者。」**
把四个平级块各自压缩，得到的是四个更小的平级块，不是层级。

## §1 · 目标：三区，各回答一个问题

参考图（指挥系统）的信息架构是**左输入 / 主态势 / 下时序**，本单照此映射到业务语义：

```
┌──────────────┬────────────────────────────────────────────────┐
│              │                                                │
│  ① 左：扰动   │        ② 主：业务端到端路线图                    │
│     因素输入  │           （链路 + 节点 + 当前态）                │
│              │                                                │
│  「我要试     │        「这条链现在长什么样」                     │
│    什么？」   │                                                │
├──────────────┴────────────────────────────────────────────────┤
│  ③ 下：影响带 —— 逐节点指标影响 ＋ 财务指标随扰动的动态变化       │
│     「试了之后，哪里变了、值多少钱」                             │
└───────────────────────────────────────────────────────────────┘
```

三区各自的判据是**能不能用一句话说清它回答什么**。答不出 ⇒ 它不该在第一层。

### ①左区 · 扰动因素输入

- **承载物已存在**：`PerturbationKindSchema`（`packages/contracts/src/sim.ts:202`）、
  `createSimPerturbation`、`PerturbationTimeline.tsx`（读端已接线）。
  本单**不新造契约**，只把输入从当前埋没的位置提到左区一等位置。
- 内容：扰动类型选择 → 参数 → 作用范围 → 「施加」；下方是**已施加扰动列表**（可删、可看生效窗口）。
- ⚠ 本区是**唯一的输入区**。其余区一律只读 —— 输入与结果混排正是本页此前难读的根因之一。

### ②主区 · 业务端到端路线图

- **承载物已存在**：`ChainLineMapView.tsx`（现居底部中栏的一个 tab）。本单把它**提为主画布**。
- 现有的「物理拓扑 / 链路阶段 / 本体拓扑」三个同级 tab **保留为主区内的档位**，不再与路线图平级抢位。
- 节点可点 → 右侧检视（`InspectorNodePanel`）保持不变。

### ③下区 · 影响带

两半，左右分列：
- **逐节点指标影响**：承载物 `ImpactAnalysisPanel.tsx`（已存在，现居右栏）。
- **财务指标随扰动的动态变化**：这是**本单唯一可能需要新增取数的部分** ——
  实施前必须先按铁律 0.5 判定它属三形态里的哪一种（没接线 / 接了线没数据 / 接了线接错地方），
  **判定结果写进实施报告**，不许直接开工造新真值源。
  已知线索：截图里存在「订单回款 `order.cash`」面板；`finance_pnl` 在求解器注册表里。

## §2 · 二级页面映射（D4 守恒：**允许降层，绝不允许删除**）

下表是本单的**硬约束清单**。每一项都必须能在二级找到，且第一层留可见入口记号。

| 当前在第一层的东西 | 去处 | 第一层留什么记号 |
|---|---|---|
| 全局态 + 16 个 stateVar 读数 | 顶栏保留全局态 + 偏离最大 3 个（③轮已做），其余 `<details>` | 「其余 N 项」 |
| 卡点 / 堵点 / 断点 / 流动效率 四张计数卡 | 收进下区「影响带」的汇总条 | 四个数字仍在，但不再各占一张大卡 |
| 阻滞点长列表（截图里 7 行） | 二级：点下区汇总条展开 | 汇总条上的条数 |
| 范围（业务线/基地勾选） | 左区折叠段（它是输入，归左区） | 当前范围摘要一行 |
| 订单回款 / 逐环节归因 / 变量输入 | 主区节点检视面板（点节点才出） | 节点上的可点记号 |
| 就绪认证 / 世界列表 / 本体派生计数 | **已在诊断抽屉**（①轮已做），不动 | 抽屉入口的 issues 计数 |
| 多场景对比 / AI 指挥台 | **已在右栏折叠区**，不动 | 折叠区标题 |

**验收时必须两向都咬**（只咬一向证明不了收纳成功，这是 `sandbox-declutter.test.tsx` 立下的规矩）：
① 默认不渲染（是不渲染，不是 `display:none`）；② 展开后**同一批 testid、同样的文本**全部回来。

## §3 · 本体引用与影响（铁律 0 要求）

**触及的对象类型**（`docs/SYSTEM-ONTOLOGY.md` §2）：
- **SimSession**（会话状态机）· **SimCheckpoint**（命名存档）· **Perturbation**（扰动·一等公民）·
  **SimCertification**（就绪认证·派生投影对象，非真值）。
- 本单**不新增对象类型**，不改任何 schema。左区用的 `PerturbationKind` 是既有枚举。

**触及的链路**：`Perturbation 施加 → SimSession 世界态 → 传导 → 逐节点指标 → 财务指标投影`。
本单改的是**这条链在屏上的呈现顺序**，不改链本身。

**触及的事件**：`sim.perturbation_created`（读端已由 `PerturbationTimeline` 接线）、`sim.tick_completed`。
本单**不新增事件**。

**不变量**：
- **R4（真值写入经 Action 审批）**：沙盘是推演世界，左区「施加扰动」写的是 SimSession 的世界态，
  **不是本体真值**；「采纳」才走 ActionDraft。本单**不得**让左区出现任何直写真值的入口。
- **R6（确定性）**：布局改造不引入时钟/随机；`deriveBaseSnapshot` 的哈希派生保持不变。
- **D4 守恒**：见 §2 表，两向验收。

**触及的断点**：`G-SEG-SCOPE-SUPERSET-ASSERT`（范围裁剪的断言易恒真）——
左区「范围」若做筛选，其测试**不许**用 `toContain`（在未裁的超集上恒真），须用等号并逐档驱动。

**是否需要回写本体**：本单不新增链路/事件/对象类型/不变量 ⇒ **不需要回写 §2/§3/§4/§5**。
若实施中发现 §1③「财务指标动态变化」属「没接线」并因此新增了取数链路，**那时必须回写 §3 并补 §8 断点**。

## §4 · 验收判据（机器可核，不许只有肉眼）

1. **三区各自存在且可定位**：`sandbox-zone-input` / `sandbox-zone-canvas` / `sandbox-zone-impact` 三个 testid。
2. **第一层容量守恒**：第一层的信息块数**不随 stateVar / 阻滞点条数增长而膨胀** ——
   用 `check-ui-first-layer.mjs` 的 D1 判据现算，改造后 `SandboxView` + `SandboxConsole` 的
   第一层块数必须**低于**改造前基线（现基线由该门给出，实施时现测现记）。
3. **D4 两向**：§2 表逐行，默认不渲染 + 展开全回来。
4. **输入唯一性**：主区与下区内**零输入控件**（`<input>/<select>/<button type=submit>` 计数为 0，
   「展开/切档」这类纯视图控件除外并显式列白名单）。
5. **变异反证**：把左区扰动输入摘掉 ⇒ 相关测试必须红；还原必须绿。

⚠️ 判据 2 有个已知陷阱，实施方必须避开：`ui-first-layer` 门对 `SandboxView` 现存的那条
是**字号层级**（R-UI-2），**不度量信息块数**。拿它当"分层做没做"的证据会误判 ——
本单第三轮就吃过这个亏（16 个读数降到 3 个，该门条数**一条没动**）。
故判据 2 必须显式用 **D1（信息块数）** 那一条，不是看门总条数。

## §5 · 不做什么（边界）

- **不动契约**：`packages/contracts/**` 零改动（若发现必须改，停手并回报，属另一单）。
- **不动后端**：`apps/datacore/**`、`apps/agentcore/**` 零改动。
- **不修 §7 那条诚实位缺口**（`docs/WO-FOLLOWUP-2026-08-13.md` §7：顶栏读数占位值无来源记号）——
  那是**诚实位**改动，与布局是两件事；混在一张单里会让「分层」和「标记来源」互相掩护。
- **不删任何信息**（D4）。删了就是把仓主的「信息太多」修成「信息不见了」，那比现在更坏。
