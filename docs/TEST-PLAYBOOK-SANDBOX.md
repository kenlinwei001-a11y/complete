> **这份文档给谁**：不是实现者的**独立测试方**（二次测试）。实现方的自测已在各 WO 的交付说明里，本手册要做的是**不采信那份自述**、自己把链路跑一遍。
> 配套：`docs/WO-SANDBOX-SERIES.md`（14 单怎么拆） · `docs/PRD-sandbox-redesign.md`（设计与验收）。
> **测试方不需要读实现代码就能执行本手册**；需要读代码的地方本文会明确指出读哪里。

## 0. 三条前置认知（不读这节会误判）

### 0.1 「绿测试 ≠ 能用」
本仓的教训不是抽象口号，是反复发生的事故：单元测试在 mock 下全绿，而**链路接缝**（跨服务形状、数据半↔引擎半、前端↔后端口径）是断的。
**所以本手册的判据一律是"效果层"**：断言用户/下游**真正拿到的那个数**，而不是"函数被调用了""字段存在"。

### 0.2 本项目特有的四类假绿陷阱
测试时逐条对照，命中任何一条即判**不通过**，不管测试套件多绿：

| 陷阱 | 长什么样 | 怎么戳穿 |
|---|---|---|
| **静默兜底** | 缺数据时给一个"看着合理"的默认值，界面上完全看不出来 | 故意删掉一条数据 → 看结果**是否标 `EMPTY`**。若数字照常出现且合理，就是兜底 |
| **占位值冒充实测** | 图上有数字，但其实是种子/哈希造的 | 换 seed 或换租户 → 数字若纹丝不动或按哈希规律变化，就不是实测 |
| **两边一起改绕过接缝** | 改了阈值，同时也改了表达式，于是"当然一致" | 只改**一侧**（只改 params、不动 expression）→ 看另一侧是否真跟着变 |
| **口径错标** | 标签写着字段 A，回的是字段 B 的值（曾出现差 1e4 的真实案例） | 拿标签里的 `类型.ID.字段` 回仓储把真值捞出来，与界面显示的数**逐位对拍** |

### 0.3 有些用例**必须是"失败/空"才算通过**
这是本项目最反直觉的一点。链路上有几段今天**确实没有数据承载**，正确行为是**诚实标 `EMPTY` 并说明原因**，而不是画出来。
**如果这些地方出现了数字或图形，判不通过**——它意味着有人在编数。清单见 §5。

## 1. 环境与起法（必须真跑，不许只读代码）

```bash
pnpm install
pnpm -r build

# 内存模式双服务（无需数据库）
PORT=4001 JWT_SECRET=dev BLOB_DIR=/tmp/blobs SEED_DEMO=1 CREDENTIAL_KEY=<64hex> node apps/datacore/dist/server.js
PORT=4002 DATACORE_BASE_URL=http://127.0.0.1:4001 node apps/agentcore/dist/main.js

# 前端
pnpm --filter frontend-shell dev            # 接真后端
VITE_MOCK=1 pnpm --filter frontend-shell dev # mock 模式（用于对比 mock 与真后端口径是否一致）
```

**登录**：租户 `demo`，账号 `admin` / `planner` / `base_manager:常州`，密码均 `demo1234`。
**沙盘入口**：路由 `v/sim-sandbox`。若返回 **404 `FEATURE_NOT_FOUND`**，说明 entitlement `sim.sandbox` 未开——**这是设计行为不是 bug**（功能关闭 = 不存在）。开启方式见 PRD §10.1 的点亮判据。

**取退出码的纪律**（本手册所有命令都照此写）：
```bash
out=$(pnpm -r build 2>&1); rc=$?; echo "BUILD_RC=$rc"
```
**禁止** `cmd | tail -n; echo $?` —— 管道末端退出码恒 0，本仓曾据此把一个**编译失败**的提交判为"通过"并入正线。

## 2. 逐波次验收用例

### W0 · S0 契约冻结

| 用例 | 操作 | 通过判据 |
|---|---|---|
| S0-1 严格解析 | 给 `ChainStep` 传一个不在枚举内的 `kind` | **抛错**（不是被忽略、不是回落默认） |
| S0-2 多余字段 | 给任一契约多传一个字段 | **抛错**（strict） |
| S0-3 **等待期望公式** | 造 `Cadence{everyDays: 30}` | 期望等待 == **15**（= everyDays/2）。若得到 30 或 0，不通过 |
| S0-4 **损失守恒** | 造一组 ChainStep（含增值段与非增值段） | 全部**非增值**环节的 `pctOfChainLoss` 之和 == **100 ±0.001**；增值段**不计入分母** |
| S0-5 单源不内联 | 全文搜业务线名（乘用车/商用车/储能）与 13 个基地名 | 契约文件里**不应出现内联字面量**，必须从 `SEG_REGISTRY`/`BASE_REGISTRY` 派生 |

**变异复核（测试方亲手做，不采信 dev 自述）**：把守恒公式的分母改成"含增值段" → S0-4 必须**真红**；还原 → 绿。红不了 = 门没牙 = 不通过。

### W1 · 数据层

| 用例 | 操作 | 通过判据 |
|---|---|---|
| D1-1 节拍有值 | 查 S&OP 共识 / 开票对账 / 订单评审 等限流环节 | 各自有 `Cadence`，值可溯源（不是拍脑袋） |
| D1-2 **无节拍要诚实** | 删掉某节点的 Cadence | 消费方拿到 **`EMPTY`**，**不是默认值**。给了默认值即不通过 |
| D2-1 **耗时按责任方拆开** | 造一张缺料订单，看采购段耗时 | 必须能分解成 **供应商生产 / 在途 / 清关 / 到货检验** 四段。给一个合成数字即不通过——"晚了 10 天"但不知道找谁，等于没做 |
| D2-2 齐套日 | 同上 | 最早齐套日可给出，且与四段之和自洽 |
| D3-1 柜位是真约束 | 把化成柜位数调小 | `bottleneck_matrix` 的**判定结果真的变**。只是种子里多了个字段而判定不变 = 运输层假绿，不通过 |
| D4-1 OTD 口径写死 | 查 OTD 聚合的契约 | 判定口径（按承诺交期 / 客户要求交期 / 首次承诺）**三选一并写进契约**。没定口径就不通过——口径不统一时两个部门报的准时率能差 20 个点 |
| D4-2 库存双维 | 查库存输出 | 有**地点 × 时间**序列，不只是快照 |
| D4-3 **现金流允许诚实为空** | 查全链经营现金流 | 两种都算通过：① 真产出全链经营现金流；② **标 `EMPTY` 并在契约注释里写清为什么 `capex.ts` 的项目级按季投资现金流与 `credit_exposure` 的敞口快照不可相加**。**硬凑一个数 = 不通过** |

### W2 · 引擎层

| 用例 | 操作 | 通过判据 |
|---|---|---|
| E1-1 守恒 | 跑一次全链损失归因 | 非增值环节 pct 之和 == 100 ±0.1 |
| E1-2 **可溯源** | 任取一个环节的损失数字 | 能说出它来自哪个求解器 / 哪条派生边。且**标签所指字段的真值 == 回的值**（见 §0.2 第四条，本仓刚修过差 1e4 的真实错标） |
| E2-1 **业务线不泄漏** | scope 选「储能」推演 | 结果**只含储能订单**。混入乘用车/商用车即不通过（本仓有过"储能达成率下钻混入整车厂"的真实事故） |
| E2-2 三维可组合 | 同时选 业务线 + 基地 + 型号 | 三个条件都生效，不是只生效最后一个 |
| E3-1 阈值引规则 | 改规则的 `params` 阈值（**不动 expression**） | 阻滞点判定**真的跟着变**。不变 = 阈值写死在别处 |
| E4-1 **节拍语义** | 把 S&OP 节拍 30d 改为 7d | 全链前置期缩短，且缩短量 ≈ **Δ(everyDays)/2 = 11.5 天**。**只要"变小了"不算通过**——必须量对 |
| E4-2 批量释放现象 | 观察限流站 | 车流**堆积后一次性放行**，不是匀速通过。匀速 = 把节拍当固定时长处理了 |
| E4-3 R6 确定性 | 同 (seed=42, 场景, 参数版本) 跑两次 | 输出**字节一致** |

### W3 · 前端层

| 用例 | 操作 | 通过判据 |
|---|---|---|
| F-1 **三色系** | 逐档切 `dark`(黑曜石 `#223251`) → `light`(冷蓝 `#f5f7fb`) → `warm`(亮橙 `#E8590C`) | 三档都可读，无不可见文字、无对比度塌陷。**组件里搜不到写死的颜色值** |
| F-2 缩放平移 | 滚轮 / 拖拽 / `+ - 0` | 以光标为中心缩放；三个视图各自记住自己的缩放 |
| F1-1 站圈随数据 | 改引擎返回的 `LossAttribution` | 站圈大小与百分比**真的跟着变**（不是渲染写死） |
| F1-2 **合流站是 AND** | 看齐套站图元 | 与普通换乘站**图元不同**。地铁并线是 OR、齐套是 AND（五种料缺一不可），画成一样即不通过 |
| F2-1 **采购支线不许有车** | 看采购支线 | 在 D2 交付前**必须为空且明说原因**。有车 = 编数，直接不通过 |
| F2-2 排队可见 | 倍速 16× 观察限流站 | 车堆积、到点批量放行、堆积计数可见 |
| F3-1 基地是派生 | 改 `BASE_REGISTRY` | 视图跟着变（证明不是手抄）。**基地是 13 个不是 12 个** |
| F4-1 **七类变量分组** | 看变量面板 | T时长/K节拍/B批量/C能力/P概率/R规则/S结构 **分组呈现** |
| F4-2 **S 类不是滑杆** | 看结构类变量（运输模式、替代料开关、解耦点位置） | 必须是**离散选择**。做成连续滑杆即不通过——它是换拓扑不是改数值 |
| F4-3 缺数据标注 | 看每个变量 | 无契约承载的变量标"缺"，**不给假默认值** |
| F5-1 定时器无泄漏 | 跑前端全量套件 | 无 `[leak-guard]` 报错。本仓刚修过 4 处「覆盖 ref 时漏清 → 孤儿定时器 → 整包随机红」 |

## 3. 跨单接缝用例（**最高优先级**）

单个 WO 全绿而这几条不通过，**整个系列判不通过**。这是本项目的头号判据。

**SEAM-A · 一条改动贯穿三层**
改 **D2「S&OP 共识节拍」** 从 30d → 7d，然后一路看下去：

1. 数据层：`Cadence.everyDays` 变了
2. 引擎层：`propagateTick` 的等待期望变了（≈ −11.5 天）
3. 归因层：该环节的 `pctOfChainLoss` 下降，且**全链非增值之和仍 == 100%**
4. 前端：站圈变小、百分比变小、线路图上该站排队变短
5. 底部指标：前置期缩短、按时交付率上升

**任一层没跟着变 = 接缝断了**。特别注意第 3 步的守恒——只有一个环节的百分比降了而总和不再是 100%，说明分母算错了。

**SEAM-B · 阈值单源**
只改规则 `params`（**expression 一个字不动**）→ 阻滞点判定翻转 → 前端展示的百分数跟着变。
⚠ 这条专门防「两边一起改」：若测试方看到实现里改阈值时**同时**改了 expression，直接判不通过。

**SEAM-C · 业务线全链贯通**
scope 选储能 → 从节点图、环节损失、底部四个财务指标，**全链每一处都只反映储能**。任何一处混入其他细分即不通过。

**SEAM-D · 口径对拍**
任取界面上一个可下钻的数字 → 按它标签里的 `类型.ID.字段` 回仓储捞真值 → **逐位相等**。差任何倍数（尤其 1e4 这种单位差）即不通过。

## 5. **必须为空的清单**（出现数字即判不通过）

这一节是本手册最容易被跳过、也最容易出事的一节。以下位置在对应 WO 交付前**必须诚实为空**：

| 位置 | 应有表现 | 前置 WO |
|---|---|---|
| 采购支线的在途批次 | 空 + 明说"本体缺 ASN / 在途批次对象" | D2 |
| 供应商交期 / MOQ / 断供概率 | `EMPTY` | D2 |
| 化成柜位容量 | `EMPTY` 或标"数据薄" | D3 |
| 全链经营现金流 | `EMPTY` + 写明两种口径不可相加 | D4 |
| 物理拓扑各格的利用率/OEE/节拍 | 显式标注"占位值（seed 派生·非实测）" | 接真值前 |
| 无 Cadence 的节点 | `EMPTY`，不显示 0 也不显示默认节拍 | D1 |

**验证手法**：换一个 seed 或换一个租户重跑。若这些数字**纹丝不动**（写死）或**按哈希规律变化**（占位），而界面没有任何"占位/EMPTY"标注，就是在编数。

## 8. 给测试方的三句话

1. **不要采信交付说明**。实现方说"变异反证红了"，你自己再红一次；红不了就是门没牙。
2. **grep 的结果不是结论**。要下"这里没接线"的判断，必须沿调用链再追一层——本仓已因此连错四次，其中三次是同一个病。
3. **发现"该空的地方有数字"，优先级高于任何功能缺失**。功能没做完是进度问题，编数是信任问题。
