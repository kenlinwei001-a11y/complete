## 0. 三种闭环辨析（先说清本文与上一增量的分工）

| 闭环类型 | 含义 | 状态 |
|---|---|---|
| 引用闭环（referential） | 配置页的下拉/绑定可达目标资源、可新建、不死路 | 管理面闭合性增量已覆盖 |
| **数据流闭环（data-flow）** | A 模块的产出真正写入并被 B 模块读取消费，逐跳无断链 | **本文，此前仅零散覆盖** |
| **联动刷新闭环（live-propagation）** | 上游变更后，下游页面**自动反映**（刷新/通知/角标），用户无需手动重查或重登 | **本文，此前无统一规则** |

> 后两者缺失的典型表现：上传按钮返回 200（"能上传"）但建模页看不到这个数据集（断链）；或合成数据生成完成但驾驶舱数字没变（未刷新）。本文确保这两类不发生。

## 1. 上传入口全清单与前向链（每个上传 button 的"上传→落地→下游可见"链路）

| 上传入口（页面·按钮） | 落地 | 前向流转链（→ 表示自动/一键可达的下一跳） | UI 反馈（每跳须有） |
|---|---|---|---|
| 连接器/数据接入·上传结构化文件(CSV/XLSX/JSON) | RawDataset（合成连接器实例） | → 字段画像页 → 建模建议(A3) → 本体草案 → 发布 → 对象化作业 → objects → 派生 → 驾驶舱/场景数据 | 上传进度→画像表→"去建模"按钮→草案 diff→对象化进度→"数据已就绪 N 对象" |
| 数据接入·上传时序文件 | ts_points | → 聚合规约匹配 → 快照属性 → 派生 → 看板曲线/求解器输入 | 上传进度→"时序已入库 N 点"→聚合作业状态 |
| 规则库/文档审核·上传规则文档(pdf/docx) | rule_docs | → 解析 → 候选规则 → 审核台 → 发布 → 规则库 → workflow/agent 绑定下拉可见 | 解析进度→候选数角标→审核队列→"已发布 N 条规则" |
| Skill 编辑器·上传资源附件 | BlobStore + skill.resources | → read_skill_resource 工具可读 → agent 加载时可用 | "已上传，mime/大小"→技能内引用校验 |
| 数据工坊·上传真实样本(贴样模式) | 样本画像 | → 拟合 GenSpec → 生成(走结构化/时序正门) → 全模块 | 画像对比图→生成 GenSpec→生成作业 |
| 知识库连接器·上传文档 | kb_chunks(向量) | → search_knowledge 工具 → agent 回答可引用为溯源 | 分块进度→"N 块已索引"→检索测试框 |
| 配置迁移·导入 bundle | import_jobs | → 两段 Saga 应用 → 全部配置资源 → 各管理页可见新资源 | 干跑 diff→应用进度→"N 资源已导入" |
| 合成数据向导·（非上传，一键生成） | GenSpec→生成 | → 走 L1/L2 正门 → 全部模块 + 模拟时钟 | 六阶段 stepper→校验报告→"已就绪，去驾驶舱" |

**强制规则（UP-1）**：每个上传入口完成后必须给"下一步"直达入口（如画像页的"去建模"按钮），不允许"上传成功"后用户自己去别的菜单找——这是"数据在模块间流转"的可操作性保证。

## 2. 模块产出-消费接线图（12 条主数据环，逐跳须接线且下游可见）

> 记法：`产出模块 →[载体] 消费模块`。实现须保证每条边：① 产出方写入持久层；② 消费方读取该持久层（非各存各的）；③ 消费页在上游变更后联动刷新（§3）。

| 环 | 链路（逐跳） | 闭环点（最终回到哪） |
|---|---|---|
| L1 数据接入环 | 上传/连接器 →[RawDataset] 建模 →[OntologyDraft] 发布 →[objects] 派生 →[派生对象] 驾驶舱/场景推演 | 推演结果可溯源回 RawDataset 行（血缘） |
| L2 时序环 | 连接器 →[ts_points] 聚合规约 →[快照属性] 派生 →[派生] 看板曲线 + 求解器输入 | 求解器用的 OEE 来自上传的实绩 |
| L3 规则文档环 | 文档 →[候选] 审核 →[规则] 规则库 →[绑定] workflow/agent →[校验] 推演拦截 | 推演里的 C 规则拦截源于上传的文档 |
| L4 配置发布环 | 工作流/skill/agent/意图 创建 →[PUBLISHED] 引用方下拉 →[绑定] 场景入口 →[触发] 前台推演 | 新建的场景在前台可点击推演 |
| L5 行动环 | 推演 →[action_draft] 审批页 →[APPROVED] 写回 →[回声对账] objects →[反映] 驾驶舱 | 采纳的方案最终改变看板数字（经审批） |
| L6 学习环 | 预测对象 ×[实际(L2)] 配对 →[MAPE] 校准 →[提案] 审批 →[参数版本] 求解器 →[下次预测] 报告页 MAPE↓ | 报告页看到"越用越准"曲线 |
| L7 孵化环 | 兜底问句 →[FallbackTrace] 聚类 →[promote] 草案意图 →[编辑发布] 意图目录 →[命中] 前台 | 曾答不了的问题现在能命中工作流 |
| L8 合成环 | 数据工坊 →[GenSpec] 生成 →[走 L1/L2] 全模块 →[tick] 增量 →[聚合/派生] 看板刷新 | 推进模拟时钟→各页数字联动变化 |
| L9 知识环 | 知识库 →[kb_chunks] search_knowledge →[hit] agent 回答 →[provenance] 溯源弹窗 | 回答里的知识点可溯源到上传文档 |
| L10 实体解析环 | 多源接入 →[merge_candidates] 人审 →[golden] objects →[全查询] 检索/推演 | 合并后所有页只见黄金记录 |
| L11 权限环 | 用户属性/角色 →[策略] 数据层过滤 →[全检索/推演/历史] | 换账号→所有页数据集随权限变 |
| L12 功能开通环 | 功能配置 →[features] workspace →[导航/视图/意图候选/求解端点] 全联动 | 关一个域→图谱/搜索/建模/聚合同时消失 |

**接线验收（WIRE-1）**：每条环的每一跳，产出方与消费方读写**同一持久层键**（不得 A 写表 X、B 读表 Y 的"平行宇宙"）——VLE 的"行数守恒/血缘完整/同源相等"不变量（§闭环验证引擎）即此接线的自动证明，本文将 12 条环逐环登记进 VLE 断言矩阵。

## 3. 联动刷新规则（上游变更→下游页面自动反映，统一机制）

1. **事件订阅**：每个消费页声明它依赖的领域事件（如驾驶舱依赖 `objects.changed`/`derivation.completed`；意图绑定下拉依赖 `workflow.published`；规则绑定依赖 `rule.published`）；产出方完成即发事件（复用 outbox/通知中心机制）。
2. **前端反映三档**（按时效要求选档，实现须明确每页用哪档）：
   - **即时**（当前任务/SSE 流）：推演步骤、Action 状态——已有 SSE；
   - **会话内**（路由切换/窗口聚焦时拉取 + 收到事件即失效缓存）：配置类（下拉新增、视图变更）、驾驶舱数字——TanStack Query 缓存按事件 key 失效；
   - **通知触达**（铃铛角标 + 列表）：跨用户的待办（审批、催办、校准提案、合并候选、隔离区告警）——通知中心。
3. **传播 SLO**：上游变更到下游可见 ≤60s（事件通路）/ TTL 兜底（功能/配置类 5min）；**不允许"必须重新登录才看到"**（重登才更新 = 验收不通过，PROP-1）。
4. **生成/tick 后的批量刷新**：合成生成完成、模拟时钟 tick 完成 → 发 `dataset.regenerated`/`clock.ticked` → 所有打开的数据消费页（驾驶舱/风险/场景）收到即整页失效重拉（§A8 已有 `synthetic.tick_completed`，本文统一为消费页强制订阅）。

## 4. 断链审计（举一反三：已识别的"产出了但没接到/没刷新"风险点）

| # | 风险点 | 修复要求 |
|---|---|---|
| DL1 | 上传结构化文件后，建模页**不自动列出**该 RawDataset | 建模页数据集选择来自 `GET raw-datasets`，上传完成事件触发其刷新 + 上传页"去建模"直达 |
| DL2 | 本体发布后，依赖该本体的派生/驾驶舱**不自动重算/刷新** | 发布→`ontology.published`→触发受影响派生重算→`derivation.completed`→驾驶舱缓存失效 |
| DL3 | 规则发布后，agent/workflow 的规则绑定下拉**仍是旧列表** | `rule.published` 失效绑定下拉缓存（会话内档） |
| DL4 | 采纳→Action 批准→写回后，驾驶舱数字**不反映** | L5 回声对账写回 objects→派生→驾驶舱失效（批准是异步，经事件非即时） |
| DL5 | 校准提案批准后，**下次预测未用新参数** / 报告页 MAPE 不更新 | 参数版本+1 后求解器读 latest；报告页订阅 `calibration.applied` |
| DL6 | 兜底 promote 生成草案意图后，**停在原页**不跳编辑 | promote 返回 intentId→前端跳意图编辑器续填（管理面闭合 §5 已提，此处确认数据接续） |
| DL7 | 模拟时钟 tick 后，**已打开的驾驶舱不变** | `clock.ticked` 强制消费页整页失效（§3-4） |
| DL8 | 实体合并后，**其他页缓存仍显示被并对象** | `objects.merged` 失效相关对象查询缓存；被并对象查询重定向 golden |
| DL9 | 连接器同步新数据后，**驾驶舱/场景不更新** | 同步批完成→派生增量→消费页失效 |
| DL10 | 知识库上传后，agent **检索不到**（索引异步未就绪却已可被问） | 索引完成前该 kb 的 search_knowledge 返回"索引中"，完成发事件 |

## 5. 轨迹验收用例（trace tests：跟随一条数据走完全程，逐跳断言可见）

| # | 轨迹 | 逐跳断言 |
|---|---|---|
| TR1 | 上传订单 CSV → 推演 | 上传→画像页见字段→建模发布→对象化→驾驶舱订单数+N→在风险视图"影响哪些订单"推演命中这些新订单（全程不手动刷新页、不重登） |
| TR2 | 上传规则文档 → 推演拦截 | 文档→候选→审核发布→在工作流编辑器规则绑定下拉见新规则→绑定→前台触发→推演被该规则拦截 |
| TR3 | 建新场景 → 前台推演 | 建切片→建工作流→建意图绑定→挂场景入口→启动器出现新卡→点击→推演出结果 |
| TR4 | 采纳 → 审批 → 看板变化 | 推演采纳→审批页待办角标+1→批准→写回→≤60s 驾驶舱对应数字变化且可溯源到该 Action |
| TR5 | tick → 全页联动 | 推进模拟时钟→已打开的驾驶舱/风险卡数字联动变化（不重登）→校准报告 MAPE 序列延长 |
| TR6 | 学习环闭合 | 注入偏差→预测→实际配对→提案→批准→下次预测用新参数→报告页 MAPE 下降可见 |
| TR7 | 权限联动 | czmgr 登录→所有消费页（驾驶舱/搜索/场景/历史）数据集一致地只含常州（同一过滤贯穿全链） |
| TR8 | 合成一键 → 全模块 | 一键合成→驾驶舱/本体图谱/规则库/20 场景卡 全部有数据且跨页同一事实数字相等（VLE 不变量） |

**总判据（DF-ACCEPT）**：TR1–TR8 全部成立 = 数据流闭环通过。任一轨迹中出现"产出了但下游看不到"或"必须重登才更新"，即未通过。

## 6. 实施与裁决

- 新增工单 **W45 联动刷新框架**：领域事件总线（消费页订阅声明 + 前端缓存失效路由 + 通知中心接线），所有 §2 环按此接线、§4 断链按此修复；
- 裁决表追加 **D-29：任何"产出型操作"（上传/发布/生成/审批/tick）完成后，必须发对应领域事件，且其下游消费页必须订阅并在 ≤SLO 内反映；禁止"需重登/手动重查才更新"**；
- VLE 登记：12 条环（§2）入断言矩阵的血缘/守恒/同源不变量；TR1–TR8 入 VLE 的 UI 轨迹子集（FULL profile）；
- 与既有机制对齐：本文不新建消息系统，复用 outbox（执行语义增量）+ 通知中心（运营完备性）+ TanStack Query 缓存（前端 PRD）+ SSE——本文只补"消费页订阅声明 + 刷新路由"这一层此前缺失的接线规范。
