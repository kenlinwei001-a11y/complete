四张 PNG 是 1440×**924** 的基准渲染。

>

## 怎么用（前端 dev 必读）

**这些是要移植的，不是要重新解释的。**
`px` 值、`grid-template-columns`、`height`、`font-size` 逐个照抄进 CSS Module。
自己重新排一版「差不多的」= 一定不是 1:1。

### 唯一允许改的两件事
1. **色值** —— HTML 里已经全部换成产品 token 的真值
   （`--bg #223251` / `--panel #2c3d5e` / `--panel2 #1c2942` / `--txt #e9eef5` / `--accent #4c90f0`
   / `--ok #62be77` / `--warn #e8b54a` / `--danger #e0626c` / `--c-capacity #43b7d7`，
   逐值取自 `apps/frontend-shell/src/styles/tokens.css`）。
   移植时**改成引用 `var(--bg)` 等 token**，不许把十六进制抄进组件。
2. **数据** —— HTML 里的数字是占位。移植时换成真实端点，**形状不许变**。

### 复刻基准
```bash
# 渲染基准（本目录的 HTML）
/opt/pw-browsers/chromium --headless --disable-gpu --no-sandbox --hide-scrollbars \
  --force-device-scale-factor=2 --window-size=1440,1012 --virtual-time-budget=6000 \
  --screenshot=ref.png file://$PWD/docs/ux-spec/sandbox/sandbox-home.html
# 上下裁到 924（= 画布 897 + 抽屉 27）：crop((0,0,w,round(h*924/1012)))
```
把 React 页面按同样参数渲染成 `got.png`，逐像素比 `ref.png`。

> 这两个数是**一起改的**，别只改一个：窗口高 = 内容高 + 87px 余量（旧配方 984 = 897 + 87，
> 今天 1012 = 924 + 87），裁切分子 = **内容高**。只改窗口不改裁切 ⇒ 底下多一条 87px 的空白；
> 只改裁切不改窗口 ⇒ **抽屉被裁掉**，而裁掉之后的图长得和"没有抽屉"一模一样 ——
> 那正是本仓反复吃亏的形态：**失败方向是"看起来正常"**，没有任何东西会报错。
> 本单实测撞过：先按旧配方（984/897）渲染，屏上抽屉在、裁出来的图里没有。
> 复验判据（跑完必看，别只看图）：结果必须是 **2880×1848**，且末 50 行里
> `#1c2942` 是主色、含约 1600 个 `#ced7e1` 量级的亮像素（抽屉标题条的字）。

## 为什么把 HTML 提交进仓库

规格写成文字会被读歪，写成截图会被照着"大概画"。
**只有可执行的那份不会。** 下一个人要改版面，改的是这里，然后重出基准 PNG ——
而不是去猜三个月前的截图当时是怎么想的。

## 画布外的抽屉（`WO-EDGE-PANEL-4PAGES` · 2026-08-23）

四页各在**画布外**、紧贴 `.app` 下沿多了一条 **26px 的折叠抽屉**（`.dock` / `.dockSum`），
展开后是共享件 `EdgeActivePanel`（「关掉一条传导边，看这次推演的数怎么变」）。

**为什么在画布外**：`.app` 是**定死的 1440×897 且 `overflow:hidden`** —— 塞进画布的任何东西
都必须挤掉既有内容。抽屉挂在外面且**默认折叠**，于是画布内的信息密度逐像素不动
（实测 `diff-px = 0`），代价只有页脚多出 27px。

**为什么是 `<details>` 而不是"跑出结果后才显示"**：门 `check-edge-active-mounts.mjs` 拦的正是
后者 —— 本仓真发生过把这个面板挂进 `SchemeCard` / `VersionDetail` 这类子组件，
净效果是**没跑过推演就看不见开关**，而「先关一条边、再看结果」恰恰是最常见的用法。
`<details>` 任何时候都在、任何时候都能展开。

**规格里只画了抽屉这条壳**，展开后的面板不在这四份 HTML 里复刻 —— 它是四页共享的一个组件
（`apps/frontend-shell/src/views/sim/EdgeActivePanel.tsx` + 它自己的 `.module.css`），
抄进四份规格就是造四份会各自漂移的第二真相源。

## 已知的取舍（照实说，别当 bug 修）

- **竖排组名逐字换行**，没用 `writing-mode: vertical-rl`。
  容器里的字体（WQY）无竖排度量，竖排下每字前进量为 0，三个字会叠成一个黑块。
  真浏览器里 `writing-mode` 可能正常 —— 但**逐字换行在任何字体下都成立**，所以选它。
- **页2 左侧地铁图被面板边界裁切**，段名（需求/订单/产能/物料/交付）看不见。
  这是照参考图「地图延续出画面」的效果，不是渲染缺陷。
- **四页的数字是内部自洽的一套占位**（产能 −18% → 稼动率 −18.0pp → Q3 缺口 6 万套 → 外协 ¥1,840万），
  接真数据时整套换掉，别只换一半 —— 换一半屏上就自相矛盾。
