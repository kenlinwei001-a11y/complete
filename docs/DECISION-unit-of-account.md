# 记账单位裁决（B1）与指标盘上线范围

> **状态**：仓主已拍板（2026-08-28）。本文件是**口径的单一出处**，量纲收口以此为准。
> 两条决定：① **钱与产能一律以 kWh 记账**；② **指标盘只上后端已有的，没有的暂不上。**

---

## 一、B1 裁决：钱与产能的记账单位 = **kWh**

### 1.1 原问题是个伪选择题

原问法是「一套 = 1 颗电芯 / 96 颗 / 166 kWh，三选一」。**三个都不是答案**，因为矛盾不在数据，
在于「套」被同时当成**钱的分母、产能的分母、物料的分母**三样东西。

### 1.2 实测：`packEnergyKwh = 166` 不是物理常数

`packages/contracts/src/base-registry.ts:65` 定义 `packEnergyKwh = 166`，
其上注释（`:57`）自称「**scale 无关物理常数**」。**同一段注释的下一行就推翻了这句话**（`:58`）：

> 名牌套 = Σ(Base.gwh)×1e6/packEnergyKwh；有效套/年 = 名牌套×util。
> **取值令有效产能≈需求锚 375 万套**

亲手反推，逐位吻合：

```
Σgwh 758.20 GWh × 1e6 ÷ 166  = 名牌 456.7 万套
                  × util 78.3% = 有效 357.6 万套   ← 注释自己写的锚正是 375 万套
```

**⇒ 166 是为了命中需求锚反推出来的标定旋钮，不是物理量。** 注释里「物理常数」四个字是错的，
而它恰好写在最容易被信的地方 —— 下一个人会拿它当不可动的常数去对齐别处。

### 1.3 实测：166 与系统自己的电芯数据对不上

`Model.energy` 本身**是干净的**：单位是 **Wh/电芯**，且六个型号逐个满足 `energy = capacity × voltage`
（`battery.ts:4048-4053`，如 4680-NCM：300 Ah × 3.7 V = 1110 Wh ✅）。

拿它 × `packCellCount = 96` 去对 166 kWh：

| 型号 | 96 电芯 = | 与 166 kWh 的差 |
|---|---:|---:|
| 4680-NCM | 106.6 kWh | 1.56× |
| 方形-LFP | 96.5 kWh | 1.72× |
| 4680-LFP | 76.8 kWh | 2.16× |
| 方形-NCM | 53.3 kWh | 3.12× |
| 圆柱-LFP | 30.7 kWh | 5.40× |
| 2170-NCM | 17.3 kWh | **9.61×** |

**六个型号没有一个对得上。** 最接近的 4680-NCM 也差 1.56 倍。

### 1.4 用真实市场价交叉验证：合理的「一套」是 45–62 kWh

系统里 `SO-3391` 的 `unitPrice = 21626 元/套`（`solvers/service.ts:1900`）。
按 2025 年真实电芯价（动力 LFP **0.35 元/Wh**、三元 **0.48 元/Wh**、储能最低 **0.26 元/Wh**、
BNEF 全球最低 36 USD/kWh ≈ **0.252 元/Wh**）反推这一套到底多大：

| 若「一套」= | 隐含单价 | 对照真实 |
|---|---:|---|
| 166 kWh（现契约） | **0.130 元/Wh** | **比全球最低电芯价还便宜 48%** ❌ |
| 106.6 kWh（4680-NCM×96） | 0.203 元/Wh | 仍低于最低储能电芯价 ❌ |
| **53.3 kWh（方形-NCM×96）** | **0.406 元/Wh** | **落在 LFP 0.35 与三元 0.48 之间** ✅ |
| 45 kWh | 0.48 元/Wh | = 三元价 ✅ |
| 62 kWh | 0.35 元/Wh | = 动力 LFP 价 ✅ |

**⇒ 与真实价格自洽的区间是 45–62 kWh，正好是一个乘用车电池包，也正好是「方形-NCM × 96 电芯」。
166 kWh 会让系统的电池看起来比世界上最便宜的电池还便宜一半。**

### 1.5 裁决与它解掉的东西

> **钱与产能一律以 kWh 记账。「套 / 电芯」只保留为物理计数，不再充当任何金额或产能的分母。**

**这条一旦落地，`packEnergyKwh` 就不再承重**：
- **产能**：直接用 `Base.gwh`（kWh 同族），**不需要换算成「套」** —— 换算本身消失
- **钱**：单价、成本、毛利一律 元/kWh（对外可写 元/Wh），**不需要知道一套是多大**
- ⇒ **1.56×–9.61× 那个矛盾不必先解决就能收口 17 个金额字段** —— 它降级成一个纯展示用换算

`packEnergyKwh` 保留，但**必须改名成它实际的身份**（标定锚，非物理常数），并删掉「物理常数」那句注释。
若将来仍要显示「套」，取值应落在 **45–62 kWh**（建议 53.3，= 方形-NCM×96，同时满足电芯数与市场价两个约束）。

## 二、与真实中创新航的校准差（**只记录、只标注，本轮不重算**）

仓主已定「先把有的先上」，故本节**不触发任何重算**，但这三个差必须在屏上标出来，
否则 COO 会把沙盘数当成公司实况：

| | 系统 | 真实中创新航 | 差 |
|---|---:|---:|---|
| 毛利率 | 隐含 23.4% | **15.9%**（2024） | 1.47× 偏高 |
| 订单簿 / 年营收 | 507.26 亿（12 个月） | **277.52 亿**（2024） | 1.83× 偏高 |
| Σ名牌产能 | 758.20 GWh | 装机 **39.4 GWh**（2024）<br>规划 >500 GWh(2025) / >1000 GWh(2030) | 名牌量级可辩护；<br>但 ×78.3% util ⇒ 年产出 ~594 GWh ≈ 真实装机 **15×** |

**要害是第三行**：758 GWh 作为**规划名牌**是站得住的（介于公司公布的 500→1000 GWh 之间），
但把 78.3% 的利用率套在规划名牌上，等于假设所有规划产线都已建成并满负荷 ——
**「名牌」与「已投产」被当成了同一个数**。这与本仓反复犯的那个形态同源：
用一个看起来相关的数当判据，而它并不度量要度量的东西。

**本轮处置**：屏上把该口径标注为「规划名牌产能」，不改数。真要对齐实况，是另一张单。

## 三、指标盘上线范围（仓主定：有的先上，没有的暂不上）

组装型制造（电芯→模组→PACK）的特殊性：**多工位串联，良率相乘、缺一件全线停**。
下表按链路排，不按部门排。

### ✅ 直接上（7 项，后端已有且可信）

| 指标 | 现值 | 出处 |
|---|---|---|
| OEE 设备综合效率 | 0.820–0.828 | `Base.oeeIndex` |
| 排产达成率 | 91.1% | `avg(Line.schedule_attainment)`（已修 100× 显示错 `ab50ccff`）|
| 瓶颈工序 | 常州=化成柜 | `Base.bottleneck` |
| 齐套率 | 79% | 组装型的命门指标 |
| 物料缺口 | 9 行/3 种单位 | `MaterialBalance`（单位已修）|
| 单点供应敞口 | 19 个 / 最大 223 | 扩容后新增，PRD §8.6 断点已闭 |
| 供应商准时率 | 0.92–0.98 | `Supplier.onTimeRate` |

### ⚠️ 上，但先修掉缺陷（6 项）

| 指标 | 缺陷 | 处置 |
|---|---|---|
| OTIF 准时且足量 | `otdBatch.rate = 0`（53 张全逾期） | 先查是真逾期还是判据错，再上 |
| 逾期敞口金额 | **双计**（63.16 亿 vs 89.58 亿，1.418×） | 按 SO 去重；基地卡标注不可直接相加 |
| 订单交付周期 | 是 `hash(so) mod 3` 估算 | 上，但必须标「估」 |
| 产能利用率 | 同名两套量纲 | 已修一半，补完 |
| 毛利率 | 量纲未声明 + 校准偏高 | 声明 kWh 口径；偏高按 §2 标注 |
| 库存周转 DIO | 部分 | 有多少上多少 |

### 🔴 暂不上（7 项，后端没有）

FPY 直通率 · 客户端不良 PPM · 质量成本 COPQ · 换型/换线损失 · 线平衡率 / 在制品 WIP · 现金转换周期 CCC

⚠️ **缺口集中在质量链（FPY/PPM/COPQ）与换型/WIP —— 恰好是组装型最吃紧的一段。**
本轮不做，但记在此处：**不是不重要，是暂缓**。尤其 FPY——组装型良率是**相乘**的
（10 个工位各 99% ⇒ 全线 90%），没有它就看不出「为什么每个工位都达标而整线不达标」。

## 四、落地顺序

1. **量纲成为数据的一部分** —— `PropertyDef` 补 `unit` + `scale`。走**封装**（构造点必填）不走门：
   禁令 3 冻结新增门，而铁律 0.6 的「门/封装/检查清单」三选一里，封装未被冻结；
   检查清单已被本仓自证无效（「检查清单是文档，不是机器」）。
   实测 `battery.ts` **597 个构造点全是对象字面量**、无单一收口点 ⇒ 改必填会产生约 603 处编译错，
   绝大多数填 `dimensionless`。**这正是要的效果：把沉默变成明确声明。**
2. **按本文件 §1 的裁决收口 17 个金额字段** —— 一律 元/kWh。
3. **前端**只忠实渲染声明，不许猜。**排在最后。**
