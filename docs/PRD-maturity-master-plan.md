# PRD · 迈向 Foundry+AIP 80% 成熟度的总纲与路线图（Maturity Master Plan）

| 项 | 值 |
|---|---|
| 版本 | v1.0（主纲文档；统辖既有 27 份增量，定义"80% 成熟度"的可度量含义与达标工程路线；基线裁决 #29，WBS 段 W46–W60） |
| 地位 | **能力路线权威**：与单篇增量冲突时以本文成熟度模型与相序裁决为准；本文不重述已 spec 的算法/契约，只定义"从 spec → 工业级成熟"的 delta |

## 0. 读法与裁决总则

- 本文把"成熟度"拆为 **8 条轴**（§2），每轴定义 L0–L5 的客观判据（§3），当前档位有证据支撑（§4），目标为各轴 **L4（=80%）**；
- 每条达标路径落为一个 **Epic（E1–E14）**（§5），含：范围 / 关键规格出处（复用既有增量，不重写）/ 验收门 / WBS 工作量级 / 依赖；
- **裁决 #29**：成熟度以 VLE（闭环验证引擎）的可量化报告为唯一验收口径——任何 Epic"完成"= 其验收用例进 VLE 断言矩阵且 FULL profile 绿。主观"做完了"不计入成熟度。
- 工作量级记法：`S`≈1–2 人周，`M`≈1–2 人月，`L`≈1 季，`XL`≈2–3 季（团队 4–6 人口径）。

## 1. 与 Foundry+AIP 的能力地图对齐（范围锚定）

| Foundry/AIP 能力域 | 本平台对应 | 现状 |
|---|---|---|
| Data Connection（连接器/同步） | A1 连接器 | mock/file 级，无生产连接器与 CDC |
| Pipeline Builder / Transforms（管线计算） | （缺）派生管线是对象级，无数据集级转换引擎 | **最大空白** |
| Ontology（对象/链接/动作） | A4 本体核心 | 架构忠实、规模 demo 级 |
| Foundry Rules / Functions | A5 规则 DSL + 求解器 | 8/21 求解器实现 |
| Marking / Security / Governance | A6 行级权限 + 治理增量 | 有行级，无数据分级 marking、无 SOC2 |
| Contour/Quiver/Workshop（分析与应用搭建） | 前端视图 + renderer | 视图固定，无 widget/应用搭建器 |
| AIP Logic / Agent Studio | B1 Agent + QOS | 受控分析 agent，LLM 全 mock、无评测 |
| AIP Automate（自动化/调度） | S3 调度 + 回放编排 | 有骨架，无可视化与生产监控 |
| Time Series / Foundry Streams | A8 时序 | 有，规模与流式欠 |
| Marketplace / 多行业模板 | A9 GenSpec + 行业模板 | 单行业（电池）成型 |

## 2. 八条成熟度轴（评估维度）

`M1 数据集成` · `M2 计算/管线` · `M3 本体规模化` · `M4 AIP-Agent 质量` · `M5 自动化与编排` · `M6 治理/安全/分级` · `M7 自助前端/应用搭建` · `M8 生产化运维`

## 3. 成熟度判据（L0–L5；L4=80%=目标）

| 轴 | L2（当前多数轴所在） | **L4 目标（80%）判据** |
|---|---|---|
| M1 数据集成 | mock/file 上传可用 | ≥3 类生产连接器（DB-CDC/OData-SAP/REST 分页+鉴权）、增量同步 cursor、schema 漂移入隔离区、连接健康 SLA |
| M2 计算/管线 | 对象级派生 | **数据集级转换引擎**：声明式 transform DAG、增量物化、列级血缘、回填与时间旅行；10⁷ 行级性能基线 |
| M3 本体规模化 | 数百对象/内存或单 PG | 10⁵–10⁶ 对象分区索引、写回事务、Action 类型库 ≥20、对象存储后端可插拔 |
| M4 AIP-Agent 质量 | LLM 全 mock、无评测 | 真模型接入 + OC2 评测套件（意图准确率≥0.9/工具正确率≥0.85/幻觉率可测）、agent studio、影子发布 |
| M5 自动化编排 | plan DSL + 校验后端 | 可视化编排器、cron/事件触发、运行监控与重试看板、SLA 告警 |
| M6 治理/安全 | 行级过滤 + 审计 | 数据分级 marking + 基于血缘的访问、SSO/SCIM、不可篡改审计、SOC2 控制项映射 |
| M7 自助前端 | 固定视图 + 27 管理页 | 工作流/切片/域/评测等编辑器闭环（#27 §3/§6）、DSL 自动补全（D-28）、Workshop 级 widget 搭建、联动刷新（#28） |
| M8 生产化 | docker-compose + 内存/PG | HA/多副本、备份恢复演练、可观测（trace/metric/log）、规模压测、蓝绿发布 |

## 6. 相序与里程碑（裁决 #29-a：先打通"真实性"再扩"规模/生态"）

```
Phase α（先回答"到底行不行"，~1 季）：E4 真实 LLM 评测 + E12 数据规模切片 + E2 转换引擎 MVP
  → 里程碑 M-α：真模型在 10⁴ 量级数据上，20 场景端到端绿、agent 质量有数字
Phase β（自助闭环可卖，~1–2 季）：E7 编排器 + E10 前端闭环 + E5 Agent Studio + E6 求解器补全
  → 里程碑 M-β：客户零代码自建场景（AC8），#26 20 场景全实装
Phase γ（工业级集成，~1–2 季）：E1 生产连接器 + E3 本体规模化 + E8 自动化平面
  → 里程碑 M-γ：接 1–2 个真实源、10⁶ 对象、自动化运行可观测
Phase δ（生产/合规，~1 季）：E9 安全分级 + E13 SRE + E14 合规 + E11 Workshop
  → 里程碑 M-δ：综合成熟度 L4（80%），可签 $1M 级合同
```

总量级：**约 18–24 人月有效工程（4–6 人团队 ~5–6 个季度）**——这是把 30% 抬到 80% 的诚实代价，PRD 改变不了这个数量级。

## 7. 验收（成熟度的可量化定义）

- 成熟度分 = Σ(轴权重 × 轴档位/5)；权重默认等权，可按客户场景调；**80% = 加权 ≥ L4.0**；
- 每季度 VLE FULL profile 出"成熟度报告首页"（复用 §VLE 工程验证度公式扩展为 8 轴雷达）；
- **裁决 #29-b**：成熟度只认 VLE 自动化证据 + 真实数据规模基线，不认 demo 演示。

## 8. 边界与诚实声明

- 本文覆盖"达 80% 的**路线与判据**"，不覆盖"实现本身"（那是 §5 各 Epic 的数人月工程）；
- "80%" 是**本垂直平台范围内沿 8 轴的成熟度**，非 Foundry+AIP 全功能面的 80%（后者非任何单团队可及）；
- 现有 27 份增量 + 本文 = 规格层已足够支撑到 L4；**到 L4 的剩余 95% 是工程与真实数据，不是更多 PRD**。
