# 功能清单 · 客户需求 ↔ 现有系统（按修法分类，不按判定分类）

> **仓主定的原则**：「**不轻易开发功能，而是把已有功能对照需求完善，调整 UX**」
> ⇒ 本清单**按修法排**，不按「已有/部分/整条缺」排。
> 理由：42 项实测里「部分」占 79%，**而「部分」之间的代价差是数量级的** ——
> 有的只是没接到用户面前（一天），有的是算法退化到算错（一周），有的是一条纵向链（一个月）。
> **按判定排会让最便宜的和最贵的混在一起。**

**证据来源**：`docs/evidence/COO-GOALMAP-20260911.md`（42 项实测 + 7 条真服务复核）· `docs/evidence/goalmap-20260911/`（9 份原始报告）· `docs/evidence/goalmap-20260911/FE-INVENTORY.md`（97 屏盘点）

**排序尺子**：**场景敞口 = 单次涉及金额 × 年频次**，不是技术难度、不是做得漂不漂亮。
可用的真数：订单簿 **454.64 亿 / 500 单 / 20 客户**（⚠ 不是 601.50 亿，那是供给侧计划口径）· 13 基地 · 6 型号 · 130 产线 · 260 工单

# A 类 · 接上已有的 —— **能力建好了，没接到用户面前**

> **这一类是本清单最值钱的部分**：它不需要造任何新能力，代价与「从零建一个功能」完全不同。
> 判据：该能力**今天已经能算出正确结果**，只是没有任何一张屏消费它。

| # | 要接什么 | 今天的实测状态 | 为什么值钱 |
|---|---|---|---|
| **A1** | **主读数接上权重** | 真拖滑杆实测：引擎**真按权重重解**（延误 −43% / 代价 +5.8%，帕累托方向正确），但**屏上头条四个数一个没动** —— 只有副读数行的 7 行文本在变 | 用户看见的那排大字与旋钮无关 ⇒ **今天拖滑杆看起来"没反应"**。改法是把主读数接到对权重敏感的那条回包上 |
| **A2** | **ATP 承诺上屏** | **全系统唯一**把「现货 + 在制未交 + 交期前可排产能」算进一个数的地方，出承诺日 / 可承诺量 / 缺口 / 瓶颈。**零前端视图引用**，只能靠自然语言问 | 直接答「这单能不能接、何时能交」—— 敞口 = 全部 500 单 |
| **A3** | **供应脆弱度上屏** | 出**真供应商 id + 物料 id + 恢复路径三态 + 恢复时间**（无备份报 null 不报 0）。**前端零消费方**（金丝雀：同目录另一求解器命中 19 文件） | 今天风险卡只到「物料齐套」这句文案，**下不到"哪一家供应商"**；这个求解器正好补上 |
| **A4** | **产能台账利用率上屏** | 三处利用率里**最像"优化"的那个**，**前端零消费方**（金丝雀：同路径另一求解器命中 17 个前端文件） | 目标 2 明写「最大化整体产能利用率」，而屏上读的是 13 个手写常数（见 B7） |
| **A5** | **可披露性范式搬到主力推演页** | 风险处置那条路**已经做对了**：每个系数打「治理口径 / 代码兜底」标，兜底时原文写「本值是代码兜底默认，不是被治理过的口径」，前端真渲染。**这个范式没搬到主力页** | 目标 3「支撑管理层科学决策」的兑现物。**不是造能力，是抄自己已有的那一套** |
| **A6** | **预警送达** | 阈值 ✅ 触发 ✅ **送达 ❌** —— 告警只落事件出站表；通知服务 **5 个调用方全部在审批流**，风险与规则两处命中 0；前端 60 条事件目录里不含这三个 | 「预警」这个词今天只兑现了一半：算出来了，没送到人手上 |
| **A7** | **传导轨迹上屏** | 逐边带对象 id、**真能反查**，但前端**只有 mock 引用** | 目标 3 补充「溯源定位」的现成实现 |
| **A8** | **决策台账 list 路由** | 两条 404 的 message 不同已硬坐实（`decision not found` vs `route not found`）⇒ 路由真的不存在 | 「沉淀决策资产」今天**只能按 id 查**，等于查不出来 |
| **A9** | **给「归因与风险」11 项明确的页签位** | 该组 5 项全被收编隐藏 ⇒ **整组不渲染**；「推演」组声明 12 项、屏上只剩 6 项。里面是采购四段腿（「今天该打哪通电话」）、断供影响半径、净室归因 | **删掉会不会有人发现？已经等于删掉了，而没人发现** —— 这本身就是半个答案 |
| **A10** | **导航条目按功能位过滤** | 两张屏导航条目**在**、点进去 **404**（导航只按角色过滤，不看功能位） | 用户点了就撞墙 |

**A 类共 10 项。这一批做完，屏上能多出的东西比造任何新功能都多。**

# B 类 · 算错了 —— **第四态：接对了、跑通了、但结果不对**

> 三分法（没接线 / 没数据 / 接错地方）查不出这一类：链路完整、屏上有数、测试全绿。
> **不修的后果不是"缺一块"，是"印一个看起来像真的假数"。**

| # | 哪里算错 | 实测证据 |
|---|---|---|
| **B1 ★** | **成本完全不取决于「造的是什么」** | 成本公式 = 延期罚 + 换型 + 成品持有 + 拆批固定，**BOM 用量 / 物料成本 / 工时 / 能耗 / 折旧 各 0 命中**（正向金丝雀：确在公式里的 4 项分别命中 4/4/2/2）⇒ **两张同量、同交期、同基地但物料成本天差地别的单，目标函数给出完全相同的 cost** |
| **B2** | **重排产的「挪」是假的** | 腾出的产能**恒落第一个基地**，而竞争者结构里**根本没有基地字段** —— 被挤单在哪个基地**一次都没被读过** |
| **B3** | **跨基地调剂杠杆是个平标量** | 缺省 `0.6`，**不选目标基地、不查目标基地有没有空闲产能** |
| **B4** | **运费不在目标函数里** | `baseCost = 解的成本 + 运费`，运费**加在解之外** ⇒ **选哪个基地时完全看不见运输代价**。对一个「跨基地多工厂协同」的系统，这处最反直觉 |
| **B5** | **订单状态机三处坏** | 唯一的流转驱动写的是**枚举外的值**；条件是「交期 vs 日历」与现场进度无关；**跳过「生产中」**；且**常态下压根不执行**（实测相隔 12 分 57 秒两次取数**整包字节级相同**，永远停在播种比例 10:20:70） |
| **B6** | **产出偏差两处量纲错** | ① 聚合口径错配 —— 产出的尺度锚是**基地级**、对比分母是**单线**级，一基地约 10 线 ⇒ 比值 **4.665** 而非 ~1；② 达成率是小数比率却按百分号声明 ⇒ **100× 显示错** |
| **B7** | **基地负荷率是 13 个手写常数** | 实测 min 70 / max 88 / 均值 78.3，无时序落到它上面，视图也不轮询。⚠ **同名陷阱**：产线利用率**是**真时序（89.77–94.13），但**跨基地决策读的是那个常数** |
| **B8** | **决策提交了，却一张派工单都没派出去** | `commit` → 200 / `COMMITTED`，但 `actionDraftIds: []`、派工单仍 0 条。且关联是**单向**的（决策指向草稿，草稿侧无反向字段） |

**B 类共 8 项。⛔ 这一类不修，屏上的数会继续骗人 —— 比「算不出来」坏，后者不说谎。**

# C 类 · 口径与维度 —— **一条纵向链，不是一个屏**

| # | 断在哪 | 实测证据 | 影响面 |
|---|---|---|---|
| **C1 ★** | **单价与单位成本分母不同** | 声明单位都是裸「元」，**真实分母是 套 vs 电芯**，实测比值 **25.7×–40.6×**、**6 个互不相同的比值** ⇒ 毛利轴被系统**自己下架**并带原因串上屏 | 「推演利润最优方案」这条承诺的**根** —— 不修这条，利润轴永远回不来 |
| **C2** | **经营目标无基地维、无期间维** | 7 条目标真对象、带责任人与权重（年度四条权重和 = 1.00），但**没有 baseId / period 任何一个**，层级只有两档 | **13 个基地共用同一套企业级目标**，不能按基地考核、不能按月/季设目标 |
| **C3** | **24 个系数 100% 走内联兜底** | 系数的来源规则**全仓只有读方没有写方**；实测 30 条已发布规则里**没有任何一条**是它（金丝雀 C01/C06/C27 全中） | 「应用层无业务常数」这条纪律在这条路上没守住 ⇒ 系数不可校准 |
| **C4** | **「快速匹配」缺 SLO 与埋点** | ⚠ **缺的不是速度** —— 实测 p50：portfolio **25.1ms** / 缺口归因 **21.4ms** / 重排产 **17.3ms**。预算分支三臂对照：未设 ❌ · 2000ms **❌仍未进入** · 1ms ✅ 进入且行为正确 ⇒ **阈值比被测量大两个数量级** | 这条承诺今天**无法证伪也无法证实** |

# ⛔ 本清单自己的边界

1. **「整条缺」的不许进这一轮 UX 设计** —— D 类要单独走功能单，⛔ 不混进重组。
2. **26 条「需起服务复核」尚未全部跑掉** —— 已跑 7 条（6 条成立、1 条劈成两半、3 处坐标订正）。剩余的可能改判部分条目。
