## §0 · 一页话

我今天做了一个实验，一个实验就够了。

我打开推演沙盘，把**常州基地的负载指数设成 100**（顶格，等于"常州彻底压死"），
推进两天，读毛利。然后我**什么都不做**，重来一遍，同样推进两天，读毛利。

| tick | 什么都不做 | 常州负载拉满 100 | 施加 3 条扰动 |
|---|---|---|---|
| t0 | 118.90 → **-210.48** | 118.90 → **-210.48** | 118.90 → **-210.48** |
| t1 | 118.90 → **-479.15** | 118.90 → **-479.15** | 118.90 → **-479.15** |
| t2 | 118.90 → **-1,532.13** | 118.90 → **-1,532.13** | 118.90 → **-1,532.13** |

**逐位相同。一个小数点都没动。**

这不是"精度不够"，不是"边没接全"。这是：**这台机器不读我的输入。**
我按下的那个按钮上写着「施加扰动」，屏幕上老老实实显示「已施加 1 条」，
然后给出一个和没按之前一模一样的答案。

而且它给的那个答案是：**我这家公司的毛利，在两天之内从 118.90 掉到 -1,532.13，跌 1,388%，
因为没有任何原因。** 这个数今天就在屏幕上，谁登录谁看得见。

> **一句话交代董事会**：
> 我们花 11 周、58 万行代码，造了一个方向盘做得极其精致、但没有连传动轴的驾驶舱。
> 方向盘转到底，车不动。仪表盘上还显示着一个不可能的数。
>
> **裁决：选 B（收敛）。** 理由和三条止损线在 §2 / §4。

## §1 · 这套系统今天值多少

### 1.1 · 它替我做成了几个决策

**COO 的数是 3 / 18。我复核了他的取证方法，接受这个数，并且自己验了其中最关键的一条。**

我今天亲手打开「订单进展与卡因」，SO-3391 这一单上写着（**我实测，截图 `m-订单进展与卡因.png`**）：

> 统一结论：**不建议接**
> · 信用占用超限（C13），需先收款/降额
> · 周供给 P90 2,520 套/周 < 本单需求 7,259 套，需夜班/外协对冲
> · 三元正极 缺口 1,858 吨（C06），最早齐套 **2026-06-28**
> · 毛利率 19% vs 毛利底线 12%

**这一条是真的。** 一个结论 + 三条理由 + 一个日期。我今天就能拿去否掉销售总监。
**整个系统里，这样的东西存在，只是只有这么几处。**

**但我要把这个 3 说得更难听一点。**
这 3 条不是 3 台机器，是 **2 台**：

| 决策 | 靠哪台引擎 |
|---|---|
| B1 接不接 SO-3391 | 接单三关联判（`affected_orders` + C02/C06/C13/C15） |
| B4 给长安放不放账 | **同一台**（那条「信用阻断 C15/C13/C18」就是三关联判的第 ③ 关） |
| A1 铝箔什么时候补 | 长协覆盖（COO 实测，我未复验） |
| A5 保乘用车还是保储能 | 藏在一条折叠详情里，要点开 `imp_BOTTLENECK.CAPACITY.cross-segment-contention_changzhou` 才看得见 |

**⇒ 2 台能用的引擎，服务 3 个决策，外加 1 个藏起来找不到的。**

**这张表里有一个数是替这个项目说话的，我不藏它**：**3.7 周一个可用决策。**
这个团队被指到一件真事上的时候，四周就能交一台能用的引擎（接单三关联判就是证据）。
**问题从来不是能力，不是速度。是准头。96% 的产出没有落在任何一个决策上。**

**钱都去哪了，一张表就看明白**：

| | 行数 |
|---|---:|

| **比** | **10.8 : 1** |

**我们给一台不工作的引擎，配了一个 11 倍大的仪表盘。**

### 1.3 · 对标：同样的钱去买现成的

> ⚠️ **本节是我的行业常识估计，不是实测。** 数字标注为区间，董事会请按估计读。

我们今天真正能用的 3 个决策，逐条对应到市面上什么东西：

| 我们的决策 | 市面上叫什么 | 估计价格（国内，50–200 用户） | 估计周期 |
|---|---|---|---|
| 接不接这张单（ATP + 信用 + 缺料） | ERP 的**可用量承诺(ATP) + 信用管理 + MRP 例外** | 一次性 ¥300 万–1,000 万，年维护 15–20% | 6–12 个月 |
| 长协覆盖与补缺 | 采购计划模块的**长协执行分析** | 含在上面 | — |
| 保哪条线（毛利权衡） | S&OP 模块的**粗产能/毛利权衡** | 含在上面 | — |
| 33 个看板 / 经营驾驶舱 | **BI（帆软 / Power BI）** | ¥50 万–150 万 | 2–3 个月 |

**这个对标的结论很难听，我照直说**：

1. **我们做出来的那部分，是买得到的**（ATP + 信用 + MRP 例外，是任何一套中端 ERP 的基本功能）。
2. **我们做不出来的那部分，才是买不到的**（跨链路推演、影响传导、决策窗口）——
   **而那正是今天不工作的那部分。**
3. 所以严格讲，我们花 58 万行代码，**做出了商品化的部分，做砸了差异化的部分**。
   这是资本配置上最坏的一种组合：**贵的地方省了，省的地方贵了。**

**唯一替我们说话的一条**：ERP 那套东西跑在真数据上，我们这套跑在合成数据上。
所以严格说，我们连"买得到的那部分"都还没真正拥有 —— **我们拥有的是它的样品。**

## §2 · 三条路，选一条

### A · 止损：停新功能，只维护，钱投到别处

| | |
|---|---|
| **投入量级** | 新功能 0。但 581,283 行、101 道门、4 个包的绿线**不是免费的** —— 估计常态 **1–2 人**才守得住 |
| **多久见效** | 立刻。下个月账上就少一笔 |
| **成功后值多少** | 保住今天那 2 台引擎当内部小工具用。**估值≈0**：因为它跑在假数据上，没人会依赖它做真决策 |
| **失败的信号** | 两个季度内那 2 台引擎也没人用了 —— 它们吃的是种子数据，没人喂就烂 |

### B · 收敛：砍掉大部分，把主线一条做深做真

| | |
|---|---|
| **投入量级** | **1 个季度 · 2–3 人**。范围：接单三关联判 + 长协补缺 两条线接真数据；沙盘那 56,018 行**先冻结、按 §4 红线 1 决定去留**；71 个导航入口砍到个位数 |
| **多久见效** | **8–12 周**看到第一个真实订单上的真结论 |
| **成功后值多少** | 一台每天跑真单的接单闸门。价值可度量：**否掉的坏单数 × 单均毛利风险 + 报价周转天数**。按今天在手 24 张单、46.77 亿的量级，拦住一张 3 亿的坏单就回本 |
| **失败的信号** | 接真数据之后，销售总监对系统结论的**同意率 < 60%**（见 §4 红线 2）——那说明结论只在假数据上成立 |

### C · 加倍：补齐数据与建模，做成真正的决策系统

| | |
|---|---|
| **投入量级** | **3–4 个季度 · 6–10 人**，外加进 MES/ERP/WMS 的数据工程。估计 **¥800 万–2,000 万**（含人力与集成，估计非实测） |
| **多久见效** | 9–12 个月 |
| **成功后值多少** | 做成了就是买不到的东西 —— 跨链路、带时间轴的经营推演 |
| **失败的信号** | 两个季度后，传导图仍然给不出一个 CFO 肯签字的金额差 |

### ✅ 我选 **B**

**一句理由**：
**C 的整个论点是「推演引擎是差异化资产，喂真数据就值钱」——
而这个论点今天已经被我亲手证伪了：引擎不读输入。**
把真数据喂进一台不读输入的机器，只是把一个便宜的错答案换成一个昂贵的错答案。

**为什么不是 A**：因为 3.7 周就能造出一台能用的引擎（§1.2），而且接单闸门是真的能用。
沉没成本只有 11 周不是 3 年 —— **把唯一一条通的路修完的边际成本，比它已经花掉的钱小得多。**
现在停，等于花完了钱，在离终点最近的地方掉头。

**为什么不是 C**：因为 C 的入场券只值两周，而我们还没买。
入场券是一个数：**让「常州停线」和「常州没事」在毛利上出现两个不同的数字。**
今天它们逐位相同。这张券两周之内买不到，C 就不是投资，是许愿。
**买到了，B 自己会长成 C** —— 因为把一条边真正接通，就是 C 的第一块砖。
**C 想跳过 B 直接开工，等于在通电测试之前先把整栋楼的电线全买了。**

## §3 · 无论选哪条，下个月必须先做的三件事

### 第 1 件 · 让「常州停线」和「常州没事」在毛利上是两个数

- **做什么**：不加新功能、不改版面。只做一件事 —— 把**任意一条**从业务量到金额的路真正接通，
  接到"输入变，输出跟着变"为止。哪一条都行，我不指定。
- **谁做**：1 个工程师，**2 周**，不许扩编，不许顺手重构。
- **怎么算做完了**（**可验证**）：
  > 打开推演沙盘，跑两遍：① 什么都不做推进 2 tick；② 常州 `负载指数` 设为 100 推进 2 tick。
  > **两遍的毛利数字必须不同**，并且截两张图并排放在一页纸上交给我。
  >
  > **今天的基线是：两遍逐位相同**（118.90 → -210.48 → -479.15 → -1,532.13）。
- **为什么排第一**：这是唯一一件能决定 C 是否成立的事。它通了，后面 37 条边是一张能算的排期表；
  它不通，后面 37 条边是一堆柴火。

### 第 2 件 · 把接单三关联判接到真订单上

- **做什么**：接单三关联判（今天全系统唯一能签字的那台引擎）从合成种子切到本月真实进来的订单。
  只接这一条，别的一律不动。
- **谁做**：1 个工程师 + 1 个销售运营。
- **怎么算做完了**（**可验证**）：
  > 本月真实订单里**随机抽 20 张**跑一遍，**销售总监逐张签字**写"同意 / 不同意"，
  > 交给我**一个百分比**。
  >
  > **今天这个数不存在**；今天系统在 24 张合成订单里只分析了 8 张（我实测，屏上原话
  > 「订单池 24 张 · 本次分析 8 张」）。

### 第 3 件 · 屏上每个钱都带单位，且同一个指标全系统一个数

- **做什么**：不是加免责声明，是**改数**。做不到就把那个数从屏上撤掉。
- **谁做**：1 个工程师，**1 周**。
- **怎么算做完了**（**可验证**）：
  > ① 随机抽屏上 **20 个金额，20 个都必须带单位**。
  > ② 同一时刻取「毛利」这一个指标，**驾驶舱与沙盘必须是同一个数**。
  >
  > **今天的基线（我实测，同一时刻，三个数）**：
  > 驾驶舱「毛利总额（亿）」= **118.85 亿** ｜ 沙盘基线 = **118.90** ｜ 沙盘投影 = **-210.48**。
  > 再加一条数学上不可能的：驾驶舱毛利 **118.85 亿 > 全部 24 张在手订单合计 46.77 亿的 2.5 倍**。
- **为什么它值一个名额**：前两件做成了，我还是不能拿去开会 —— 因为我没法向财务总监证明哪个数是对的。
  **一个我不能引用的正确答案，等于没有答案。**

> **这三件加起来 ≈ 1 人 · 5 周。** 我不批更多。
> **五周之后拿这三张纸来见我，我按 §4 决定后面的钱。**

## §5 · 我怀疑但没证据的

> **本节只提问题，不下结论。每条写清楚：要验它需要什么。**

**1 · 那 3 条能用的结论，会不会也只是合成数据长出来的形状？**
SO-3391 那个「不建议接」，靠的是信用额度 151,294 和周供给 P90 2,520 ——
**这两个数都是种子造的。** 换成真额度、真产能，这个结论会不会翻过来？
**要验它需要**：一张真实订单 + 一份真实信用档案 + 一条真实周产能，跑一遍看结论翻不翻。
（这正是 §3 第 2 件事，所以它排在第二。）

**2 · 毛利 118.85 亿 > 在手订单 46.77 亿，到底是单位错还是口径错？**
COO 也没追到底，只报了"这两个数并排放着谁读都觉得不对"。
差 2.5 倍是个可疑的倍数 —— 不像单位错（那通常是 10 的整数次幂），更像口径混了
（年度累计 vs 在手？含税 vs 不含税？）。
**要验它需要**：写这段的人给出那个 118.85 的**分子和分母各是什么**，
以及它和那 24 张订单是什么关系。**这不是查代码，是要一句话的定义。**

**3 · 我今天全程用的是 admin。一线看到的是同一套东西吗？**
后端按角色下发不同的导航和视图。如果 `planner` 和 `base_manager:常州` 看到的更少，
那"3/18"对一线可能是"1/18"甚至"0/18"。**而真正每天要做决策的是他们，不是我。**
**要验它需要**：用另外两个账号各走一遍我今天这 40 分钟，各报一个"能用几条"。

**4 · 61 个求解器，我今天只碰到了 5 个。剩下 56 个有生产调用方吗？**
我今天实际触发过的是 `chain_loss_attribution` / `chain_impediments` /
`finance_world_projection` / `risk_timeline` / `affected_orders`。
**要验它需要**：一次真实的**调用计数**（打点跑一周，看每个求解器被调了几次），
**不是 grep 源码**。这个仓库自己的铁律 0.5 写着：grep 的结果不是结论。

**5 · 我跑的是内存模式的演示数据。接了真库还是这个行为吗？**
代码注释里自己记着一次真 PostgreSQL 事故：一个列表接口回了 **285 MB / 9 秒**，把浏览器打崩。
**内存模式测出来的"能用"，可能在真库上是"打不开"。**
**要验它需要**：起一次真库，把我今天这 40 分钟原样重跑一遍，记录每一页的加载秒数。

**6 · 那个 -1,532.13 到底是"算错了"还是"这个面板本来就不该响应扰动"？**
我测到的是行为：输入变、输出不变。**两种解释我都没排除** ——
① 引擎读了输入但那条路通不到钱；② 这个面板设计上就跟扰动无关，只是恰好摆在扰动按钮下面。
**要验它需要**：写这个面板的人回答一句话 ——「已施加 N 条」这个计数和它下面那三个金额，
**是不是同一次计算出来的**？
⚠️ **但这两种解释导向同一个资本决定**：一个我按下按钮却不动的数字，
和一个根本不该出现在那里的数字，**对签字的人是同一件坏事**。

## §6 · 我和 COO、和工程师的分歧

### 6.1 · COO 说「86% 的环节碰不到钱是天大的事」—— 我同不同意这是第一优先级？

**诊断我完全同意。排序我不同意。**

COO 量的是**图上有没有路**：44 个环节，38 个走不到钱。这个测量是对的，
而且是前三轮里最有价值的一次测量 —— **前两轮一次都没算过这个数。**

**但我今天量的是另一件事，它排在他前面**：
**那 14% 有路的，也不通电。**

我把常州负载拉满、施加 3 条扰动、什么都不做 —— 三种输入，**三个 tick 的毛利逐位相同**。
（金丝雀：这三个数**在 tick 之间是会变的**（-210.48 → -479.15 → -1,532.13），
所以我的读数工具是好的，这台机器也确实**有能力**吐出不同的数 —— 它只是不因为我而变。）

**所以顺序必须是**：

> **先修「输入不影响输出」，再谈「输入的种类不够多」。**

**反过来会怎样**：按 COO 的排序，我们花一个季度把那 38 条边接上，
接完之后回来一测，**还是 118.90 → -1,532.13**。
**一个季度的钱，换一个和今天一模一样的屏幕。** 这是我今天最不想批的那种预算。

**这不是驳他，是接着他往下走了一层。**
他证明了路不够；我证明了现有的路上没有车。**修路之前先证明车能开。**

### 6.2 · 工程师说「A1 补一条线就解锁三步」—— 从投资角度我怎么看

**我听过很多次这句话。这次我不打算靠"感觉"来判断，因为这个仓库自己把账记下来了。**

`CLAUDE.md` 铁律 0.6 第 5 条，白纸黑字，**2026-08-20 一天之内五张单的前提被实测推翻**：

| 「收掉残口 ②③」 | **②③ 都已闭**，源码零改动 |

铁律 0.5 里还有一条更贵的：**一次把「接一条线」错报成「造一道门」，直接歪掉排期。**

**所以我的判断不是"不信"，是改计价方式。**

| | 以前 | 从今往后 |

**这次凭什么不一样 —— 就一句话**：

> **前五次的验收物是"某一行状态标成绿的"。**
> **这次的验收物是两张截图上两个不同的数字。**

而且我把话说全：**如果两周之内那两个数字真的不一样了，那我会当场加钱**，
按"每通一条边多少钱"批剩下的 37 条 —— 那时候「再补一条线」就不再是一句话，
