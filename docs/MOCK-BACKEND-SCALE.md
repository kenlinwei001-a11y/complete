## 3 · 区间的裕度是怎么定的（不许拍脑袋 · 定得够宽等于没门）

统一 **±1%**。两侧都有实测证据，不是「感觉差不多」：

| 边 | 判据 | 实测 |
|---|---|---|
| **下界**（不能比噪声还窄，否则天天假红） | 两侧都是确定性的（seed=42 · R6 字节一致），唯一合法抖动是浮点与 `round(x,4)` 末位 | 实测最大一例：`s2 total` 真后端 **27.919999999999998** vs mock **27.92** ⇒ 相对差 **7.1e-16**。1% 比它高 **13 个数量级** |
| **上界**（必须**严格小于**本表任一行能发生的最小结构性变化，否则等于没门） | 找出本表各族「少一项 / 多一项」能造成的**最小**相对变化 | ① 归因族最小：真后端需求端最小那一叶 `seg_bias:dseg-1` 占该侧 **0.3815 / 24.4501 = 1.560%**；② 量轴族最小：少一个基地（扬州 **0.6846 / Σ22.6839 = 3.018%**） |

⇒ **1% 夹在 7.1e-16 与 1.560% 之间** —— 是同时满足「不误报」与「咬得住最小的真变化」的那个量级。
**再宽一档（±2%）就漏掉 1.560% 那一条**，那就是用宽区间买绿。

### ① `gate-roster:check` 咬红：**第一版的受检面是手抄的，覆盖率只有 23%**

## 6 · 这道门做不到什么（诚实边界 · 先读，免得把它当成它不是的东西）

1. **它不判定这些比值本身对不对。** 它只守「登记的比值不许漂」。
   档 B 那 18 行今天登记的是 `2.3313×` 这种**明知是错的**比值 —— 门守的是「别再错得更多」，
   **不是**「它是对的」。要不要把 mock 的写死比例改成真算的，那是产品/数据决策，本单红线之外。
2. **受检面 = 两侧回包的交集，不是「全部 S&OP 的量」。**
   本门探针取哪些回包（S&OP 五步 / plan-versions / 四个求解器 / 三类对象仓）是**人定的**；
   探针没取的端点，它一个量都看不见。**它保证的是「取回来的这些，一个不漏地都比过了」**，
   不是「S&OP 的量都比过了」。加端点要改探针（一处显眼 diff）。
3. **归一规则 `ARRAY_KEYS` 是人写的。** 新数组漏登 ⇒ 退回按下标比 ⇒ 大概率报**假红**。
   这是**刻意选的失败方向**（宁可吵，不可静默变绿），但它确实是噪声来源。
4. **`s3.perBase` 只能按「月产能降序名次」归一，不能按基地身份。**
   因为两侧 `baseId` 字段**装的不是同一个东西**：真后端是拼音 id（`changzhou`），
   mock 落的是册里的中文名（`常州`）。⇒ 本门能证明「13 个值两侧一一对上」，
   **不能**证明「常州那一行两侧都是常州」。要证后者得先统一那个字段，属另一单。
5. **它要起两个子进程**（`--experimental-transform-types` + datacore 内存起服 + 合成种子），
   单跑约 12–15 秒，属**中画像**。故**刻意不接** `pnpm gates` 链（gates 已约 28 分钟）。
   触发时机：改动 `scripts/gate-ledger.json` 里它的 `guardedPaths` 覆盖的任一文件时手动跑。
6. **它不覆盖「结论一致」层。** 「同一份基线两边给同一个 verdict」由
   `mock-scale-truth.seam.test.ts` 的 L3 守（今天两侧都是 `43 / 站不住`，一致）。
   本门与它**分工不重叠**：它守数量级 + 结论，本门守倍数区间 + 跨口径关系 + 一侧独有。
7. **`--experimental-transform-types` 是实验特性。** 哪天 node 去掉它，本门**报 RC=2**
   （「探针起不来」），**不会**报「量级一致」—— 失败方向是对的，但届时要换 build 路径。
