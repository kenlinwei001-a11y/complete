## 7.10 规划体检（renderer="plan-audit"）

**布局**：左栏 380px 固定（输入面板）+ 右栏自适应（诊断结果），对齐原型双栏。

**输入面板**：三组数字字段（与求解器 S1.6 输入一一对应）——需求侧 `dem / seg_pas / seg_ess / seg_com`（step 0.1）、供给侧 `sup / ltaCov / kitGap`（kitGap step 10）、财务侧 `gmTarget / cashCushion / capex`（step 0.5）。基线值来自当前定稿 S&OP 版本（`GET {A}/a/v1/plan-versions/current`），头部注明「基线：{版本号}·改任意字段即时体检」；「重置输入」恢复基线。

**结果区**（消费 `plan_audit` 输出 `{score, verdict, H[], M[], S[]}`）：
1. **结论卡**：评分大数字 + 档位（≥85 绿「通过」/ 60–84 黄「有条件通过」/ <60 红「不通过」），边框取档位色。
2. **三段卡列表**：硬矛盾（红左边框 ⛔）→ 软风险（黄 ⚠）→ 建议修正（绿 ✓）。每卡：`title` + 规则徽章（ruleRef，点击弹规则 expression 浮层，复用全局规则浮层组件）+ `why` 全文（数值已由后端代入）。
3. **一键应用 fix**：卡内按钮（文案=fix.label）→ 将 `fix.patch` 合并进左栏字段 → 触发重算；按钮旁固定脚注「演示用——实际生效走 S&OP 议程与 Action 审批 (C10/C22)」。
4. **时序推演折叠**：H/M 卡带「⏱ 时序推演（不解决会怎样）」折叠开关 → 展开调 `risk_timeline` 同构传导数据渲染**传导链时间轴组件**（横向 stepper：事件窗→约束越线→波及订单→财务击穿，节点按严重度着色；受影响订单行可点开订单弹窗）。该组件与 7.11 的问题卡共用，全局唯一实现 `PropagationTimeline`。

## 7.11 规划建议（renderer="plan-generate"）

**目标面板**（顶部横条）：五个目标输入（收入增长% / 毛利底线% / 份额增pct / CAPEX上限亿 / 现金底线亿），其中毛利/现金/CAPEX 各带「硬约束」开关 chip（on=红描边，对应 S1.7 的 hard 标志）；改动即重算全部方案。

**三方案卡**（纵向堆叠，消费 `plan_generate` 输出 `plans[{no,name,pathRef,outcome}]` + `recommendedNo`）：
- **折叠头**：编号色块（稳健绿/均衡青/进取紫）+ 名称与基于路径 + KPI 行（收入增/毛利率/份额/CAPEX/现金垫，mono 字体）+ 综合分大数字；`hardViol` 非空 → 分数位置显示 ⛔ 且整卡降透明度 0.85；推荐方案右上角「★ 推荐」徽章。
- **展开体**三栏：①目标达成清单（六项 meet* 布尔 → ✓/✗ 行）②**五维雷达**（自绘 SVG 组件 `RadarChart(scores, color, size=180)`：三环网格+五轴+多边形填充，维度顺序固定 盈利/规模/现金/增长/稳健）③取舍矩阵表（gain 绿 / give 橙 着色）。
- **展开体下部**：硬约束违反清单（红条，含解锁提示如「调高 CAPEX 上限可解锁」）+ 问题卡列表（每问题：标题+规则徽章+why+传导链 `PropagationTimeline`）。
- **采纳按钮**（卡尾）：actionType=`采纳经营方案`，payload=方案快照+当前目标面板值。

## 7.12 S&OP 平衡台（renderer="sop-balance"）

**顶部**：KPI 条六卡（需求 P50 / 可供给 / 产销缺口（>2 红）/ 收入预算达成% / 毛利率 vs 预算 / 现金垫 C18 状态）——每卡可悬停溯源（公式与来源，复用 ProvenancePopover）；右侧**版本徽章**：`V{n} 评审中`（紫）或 `V{n} 已定稿·C22 锁定`（紫+锁图标）。

**五步 stepper**（chips 可点切换，状态来自版本对象 `currentStep`）：

| 步 | 内容组件 | 关键交互 |
|---|---|---|
| ①产品评审 | 可产矩阵变更表（变化类型/型号×产线/状态/供给影响/来源） | 只读 |
| ②需求评审 | 三线对照表（细分行：目标/滚动P50/P90/上月实际/偏差%），偏差 >±10% 行尾 `C21 差异提报 → 进议程` 黄 chip | chip 点击跳转⑤对应议程项 |
| ③供应评审 | 逐基地供给表 + 缺口汇总（=S1.2 月聚合输出） | 只读 |
| ④财务整合 | 毛利率 roll vs 预算、现金垫 C18 校验结果卡 | C18 不过 → ⑤入口禁用 + 原因 tooltip |
| ⑤高管决策会 | 议程列表（C21 项 + 缺口对策 + 财务越线项）+ **决议增量编辑器**（行：措施名/供给增量万套，添加后顶部供给与缺口即时重算）+ **定稿按钮** | 定稿 → actionType=`定稿月度计划版本`（payload=版本快照+决议清单）；草稿创建成功后版本进入待审批态 |

**锁定态**（版本 FINAL）：全部编辑控件只读、决议编辑器隐藏，顶部横幅「已定稿——变更须走变更 Action」+ 发起变更按钮（actionType=`计划版本变更`）。后端 409 `PLAN_LOCKED` 时前端兜底展示同横幅。

## 7.13 项目推演（renderer="project-sim"）

**参数区**：型号选择器（选中写入 `selectedObjects`，供查询 Dock 上下文）+ 模式切换「整单 / 分批」。整单：需求量（万套）+ 交付周数；分批：批次表格编辑器（行=数量/交付日/交付地址下拉，增删行，地址变更显示物流时长天数）。任何参数变更 → 重算 `capacity_forecast`。

**六步 stepper**（上一步/下一步 + 进度 n/6，步序与原型 PM_STEPS 一致：①场景解析 ②可产基地收敛 ③驱动因子装载 ④逐级聚合 P50 ⑤瓶颈定位 ⑥结论与对策）：每步主体为数据表（消费 `perBaseRows / batchRows / pendingCertList / mainBn` 等字段；④步合计行展示 `P50 与 P90=×healthFactor`，健康度降级时附黄字说明；⑤步内嵌**多维瓶颈矩阵**弹窗入口——基地×7因素热力表，主瓶颈格 ◉ 标记，色阶绿→黄→橙→红按紧张度）。

**DAG 面板**（与 stepper 并排，常显）：自绘 SVG 分层 DAG，六层固定（需求→型号→可产基地(≤6+折叠)→驱动因子×3→求解器×2→产能预测结论）；布局=层内均分横排、贝塞尔连线带箭头；**随步骤点亮**：节点/边 `lit = 节点.st ≤ 当前步`，未点亮透明度 0.28，当前步节点左上角「本步」角标；结论节点颜色=可达绿/缺口红。

**结论与 what-if**（第⑥步）：结论卡（`ok` → 绿「✓ 产能可满足」/ 红「✗ 缺口 {gap} 万套」+ P50/P90/需求三数对照）；**what-if 调参区**三滑杆——加夜班 0–3 班、扩化成通道 0–6、外协 0–20%（step 5）——拖动即按 S1.2-7 公式重算并实时显示「缺口归零·富余 x」或「缺口 x」；外协超 20% 滑杆截止并提示 C08。采纳按钮：actionType=`采纳产能保障方案`，payload=参数组合+推演快照。
