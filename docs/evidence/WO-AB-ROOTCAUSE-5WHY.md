# 「同一个格子的值由谁定」· 连续追问 5 个为什么

> 2026-10-06 · 对 `WO-AB-PLAN-three-layers.md` §3 的**自我复审**：§3.2「逐格裁决」停在补丁层，本件给出根因层。
> 方法按仓规：连续追问 5 个为什么；每层结论必须有证据，不靠推理。

---

## 第 1 问：为什么「值由谁定」会成为问题？

因为**两套机制都认为自己是该格的写入方**：传导边（`PropagationRule`）与派生规格（`DerivationSpec`）。
证据：`WO-AB-DUALWRITER-census.txt` —— 33 格有规则、24 格有规格，**重叠 14 格**。

## 第 2 问：为什么两套机制都能写世界态？

因为它们**回答的是同一个问题**：「这个格子的值从哪来」。
- 派生规格的立项原话（`2dc9febe6` WO-SLICE-DERIV-EMPTY）：「形态=接了线没数据 ⇒ 补数据」——管**初始值**。
- 传导边的职责：扰动沿边传播——管**变化量**。

## 第 3 问：为什么「初始值」和「变化量」会写进同一个格子？

**因为世界态是单层的。** `world.state[objId][stateVar]` 既存「这格现在是几」，又被传导当「基值」累加。
证据：`propagation.ts:629` `bucket[targetStateVar] = cur + amount`（读当前值、加增量、写回）——**基线与增量在同一次写入里合流**。

## 第 4 问：为什么没有把「基线」和「偏离」分开？

**因为消费端早就混着用了，而且是两种相反的假定：**

| 消费端 | 它假定这格是什么 | 证据 |
|---|---|---|
| 求解器 `finance-world.ts` | **偏离**（`金额 = 基线 × (1 + 压力 ÷ divisor)`） | 目录描述原文 |
| 屏（0–100 压力标度） | **水平** | 终裁 (b) 记载的两口径对立 |
| 派生规格 `model_cost_pressure` | 产出**水平**（成本占售价比，实测 2.5–3.9） | `seed-derivation-specs.ts:136` |
| 传导核 | 读**偏离**（`drive = sourceVal − ref`） | `propagation.ts:1143` |

**⇒ 同一个格子，四个使用方，两种互斥的语义假定。** 这不是谁写错了，是**这格的语义从来没被定过**。

## 第 5 问：为什么这个语义一直没被定过？

**因为全仓没有任何一处承载「语义」这件事。** 逐处查过：

| 承载物 | 它定了什么 | 它**没**定什么 |
|---|---|---|
| `STATE_VAR_DOMAINS` | `min` / `max` / `restPoint` —— **值域** | 语义 |
| `STATE_VAR_VALUE_REFS` | 值由哪个 spec 算 —— **来源** | 语义 |
| `PropagationRule` | 谁传谁 / 多少 / 怎么合 —— **传动** | 语义 |
| `DerivationSpec` | 用什么公式算 —— **算法** | 语义 |

**至今没有任何一处声明：「这个格子里的数是水平，还是偏离」。**

---

## ⇒ 结论：根因不在「三个所有者」，在「状态量没有语义声明」

**「同一个格子的值由谁定」是症状。** 因为语义没定，所以任何机制都能按自己假定的语义写它；
而一旦语义定了，**「谁能写这格」就是推导出来的，不是拍出来的**。

### ⇒ 对原方案 §3 的自我修正

`WO-AB-PLAN-three-layers.md` §3.2 写的是「给每格选一个 owner」——**那是补丁**：

- 它只是把**今天的**冲突按**今天的**理解拍平；
- 明天加一个新写入方（新规格 / 新动力学 / 新求解器缓存），冲突会以新形态再来一次；
- 而且「选 owner」这个动作**没有回答「为什么是它」**——无法防止下一个人重蹈 `03c4c8391` 的选择。

### ⇒ 根因解：给状态量加【语义声明】，让写入权成为推导结果

**1) 新增唯一真相源 `StateVarSemantics`**：每个 `(typeKey, stateVar)` 声明量纲二选一——

- `LEVEL`：水平值，世界的绝对量，有独立物理含义（如 `Model.costPressure` 若定义为成本占售价比）
- `DEVIATION`：偏离值，相对静息点的偏移，**静息态恒为 0**

**2) 由语义【推导】写入权（不是拍的）**：

- 声明为 `DEVIATION` ⇒
  - 静息值**必须**是 `restPoint`，且 `restPoint` 必须登记（**取不到不许退回 0**，沿用既有纪律）
  - 产出天然是 `LEVEL` 的规格**不允许**登记为该格的 producer ⇐ **`order_cost_pressure` 在此被自动挡下**
  - 传导边是合法写入方 ✅
- 声明为 `LEVEL` ⇒
  - 派生规格是合法 producer
  - 传导边写入前**必须换算**，不得把偏离当水平直接加

**3) 编译期一致性校验**：任一格的写入方量纲与该格语义声明不符 ⇒ **编译期报错点名**。
⚠ 触碰「禁令 3：新增门/棘轮/基线 JSON 冻结」边界 ⇒ 请仓主裁决落地形态。

### ⇒ 用 `Order.costPressure` 验证这个解法

- 语义 = `DEVIATION`（求解器按偏离读它）⇒ 静息值必须是 `restPoint` = 0
- **⇒ 90.38 这个值本身就是错的 —— 偏离量的静息态必须是 0。它就是「凭空声称今天成本已经偏离了 90.38%」。**
- 规格 `creditUsedRatio × 100` 产出 `LEVEL` ⇒ 量纲不符 ⇒ 编译期挡下 ⇒ **无需逐格拍，14 格一次性收口**

### ⇒ 为什么这条解法能防住 `03c4c8391` 那类事故

`castSeedBaseValue` 那段注释（`battery.ts:3966`）原文已经写对了：
> 「压力必须是**相对今天基线的偏离**，静息态就是 0。掷一个 0–100 的值进去，等于凭空声称「今天成本已经偏离了 0–100%」」

**铸造器那一支想对了。** 但 `03c4c8391` 终裁回退时，把规格复原、没回退铸造器 ——「想对的一半」与「想错的一半」并存至今。

**⇒ 回退的人并非不负责：他手上没有「语义声明」这个承载物，只能按「用户会不会立刻看到坏东西」来选。**
**⇒ 一次因为缺少承载物而必然发生的误判，靠复核是防不住的 —— 只有把语义落到承载物上才防得住。** 这就是根因解与补丁的分界。
