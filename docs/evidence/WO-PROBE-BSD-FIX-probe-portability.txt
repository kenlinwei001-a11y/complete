  ⚠ 本机**同一个命令名有两套实现，取决于在哪个解释器里跑** —— 这是本档最重要的一行：

    上下文 A = bash scripts/*.sh（脚本真实解释器，也是本 WO 的修复对象）
    上下文 B = Claude Code 的工具 shell（shell 快照里植入了同名函数，函数体实测为：
               find () { ... ARGV0=bfs "${CLAUDE_CODE_EXECPATH}" -S dfs -regextype findutils-default ... }）
               ⇒ 复现方式：zsh -c "source <snapshot>; find --version"

    命令   | 上下文A: bash（脚本真实解释器）  | 上下文B: 工具 shell（快照 shim）
    ---------+----------------------------------------------+------------------------------------
    find     | find: illegal option -- -  [/usr/bin/find]   | bfs 4.1.1  [函数 shim]
    grep     | grep (BSD grep, GNU compatible) 2.6.0-FreeBSD | ugrep 7.5.0 x86_64-apple-macosx +avx2; -
    ps       | /bin/ps(BSD · 无 --version)                | /bin/ps(同一支)
    bash     | GNU bash, version 3.2.57(1)-release (x86_64-apple-darwin22) | （同左）
    stat     | stat: illegal option -- c                    | （同左；实测 -f%z 可用：213）
    date     | date: illegal option -- d                    | （同左；实测 -r 可用：1970）

  自证方式（不是推断）：
    · find : 上下文A 回 find: illegal option -- -（BSD find 不认 --version）；上下文B 回 bfs 4.1.1。**同一命令名，两条实现。**
    · grep : 上下文A 回 BSD grep, GNU compatible 2.6.0-FreeBSD；上下文B 回 ugrep 7.5.0。
    · ps   : 两上下文同为 /bin/ps；ps -eo pid,args --no-headers 回 ps: illegal option -- -（5 行 stderr），
             真进程表 462 行 ⇒ 必须用 tail -n +2 剥表头。

  ★ 由此推出本 WO 的核心判据（不是「哪个写法对」，是「哪个写法两边都对」）：
    -newermt 的两种写法**语义相反**，各在一侧是坏的 —— 实测矩阵见 §1.5。
