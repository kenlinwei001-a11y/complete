### 🔴 1.2 最要命的一条：S&OP 的「产销缺口」两端同源

```
   预测(375万套·3行常量) ──只贡献一个均价 P̄──┐
                                             ↓
产能rollup ──×52──► 年度计划demand ──►月度目标──► S&OP②「需求」──► S&OP③ gap = 需 − 供
   ▲                                                                      ▲
   └──────────────── 同一个产能数，绕了一圈 ───────────────────────────────┘
```

`需` 追到底是 **产能×52**；`供` 是 **产能 rollup × 认证系数 × 爬坡曲线**。
**⇒ 这个「产销缺口」度量的是认证/爬坡折扣，不是需求与供给的不平衡。**

# 🔴 跨条目的四个结构性发现

这四条不是某一行的缺口，是**横跨多行的同一个病**，比单行判定值钱得多。

## 一、计划链的「需」与「供」是同一个数绕了一圈

- 年度计划的需求 = **认证产能 × 52**
- S&OP 的供给 = **产能 rollup × 认证系数 × 爬坡曲线**
- ⇒ **「产销缺口」度量的是认证/爬坡折扣，不是需求与供给的不平衡**
- 而系统自己那份预测（375 万套）**只贡献了一个均价**，量根本不流
- 计划员屏上的「需求」= 前端常量 1531.2 万套，是系统预测值的 **4.08 倍**

**这一条同时解释了 1.2① / 2.6 / 3.2 三行的判定。** 它不是三个缺口，是一个。

## 二、「算得出的」与「屏上看得见的」是两批东西

反复出现同一形态：**能力建好了，但没挂到有人看的那条路上**。

| 造好了 | 挂上了吗 |
|---|---|
| 产能台账的利用率（三处里最像"优化"的那个） | **前端零消费方**（金丝雀：同路径另一求解器命中 17 个前端文件） |
| 脆弱度求解器（出真供应商 id / 物料 id / 恢复路径 / 恢复时间） | **前端零消费方** |
| 推演传导轨迹（逐边带对象 id，真能反查） | **只有 mock 引用** |
| ATP 承诺（全系统唯一把现货+在制+产能算进一个数的地方） | **零前端视图引用**，只能靠自然语言问 |
| 风险处置路的**可披露性范式**（每个系数打「治理口径/代码兜底」标） | **没搬到主力推演页** |
| 决策成效统计（已归集成排序权重、有 REST 出口） | **建议求解器零处读它**，且前端零调用回填 ⇒ 双重空转 |

⇒ 这不是「做不出来」，是「**做出来的东西没有被接到用户面前**」。
**修它的代价与从零建一个功能完全不同 —— 这是排期时最值钱的区分。**

## 三、「会预测的不自动，自动的不预测」

- **真·事前**的两个（越线日预测 / 未断但脆弱）：**零定时调用方**，必须有人点开页面
- **真·自动**的六条规则：判据**全是当下快照**（偏差已发生 / 已呆滞 90 天 / 缺口已存在）

⇒「预警」这个词今天**两个字各兑现了一半，但不在同一条链上**。

## 四、成本与利润这条轴，从底层就断了

| 层 | 实测 |
|---|---|
| 目标函数 | 5 个目标**无利润轴**；成本只有 4+1 项调度罚金，**不含物料/工时/能耗/折旧** ⇒ **成本只取决于"何时、在哪"，完全不取决于"造的是什么"** |
| 系数来源 | 24 个系数**规则表里没有写方**，100% 走内联兜底 |
| 维度 | **事业部维度整条不在册**；基地、客户**无收入字段**；只有型号维同时有收入与成本 |
| 口径 | 单价与单位成本**分母不同**（套 vs 电芯，比值 25.7×–40.6×）⇒ 毛利轴被系统**自己下架** |
| 落点 | 损益求解器只回 **3 行零维度**；通用维度器**零生产调用方**且绑定字段**两个都不存在** |

⇒「**推演利润最优方案**」这条承诺，今天从**目标函数 → 系数 → 维度 → 口径 → 落点 → 兑现** 六层**每层都断**。
**这不是补一个屏能解决的，是一条纵向的链。**
