② 截断豁免集 / 对象域门按身份判
   本批**遇到了本批的形态**：`query_timeseries_agg`（截断豁免集成员）、
   `get_object` / `aggregate_objects`（对象域门成员）都在本批里。
   - 截断豁免：判据已是身份归一（`isTruncationExemptTool` → `resolveBuiltinToolIdentity`），
     本批直接受益、无需再改；接缝套件 B4 逐条咬「全名形态仍豁免 / 非豁免件不被误豁免」。
   - 对象域门：归一位置在 scope 门之后、对象域门之前（上一单定的），本批直接受益；
     接缝套件 B3 用全名真调域外类型 ⇒ DENIED 且**拒绝行记的是裸名**（证明门按身份判、且在归一之后）。
   - 新遇到的一处（本批新增点名）：analyst 的 `scopeDeclaration.toolNames` 里有一条
     `aggregate_objects` —— 它在**声明面**里、却从来不在**授予面**里。它已属内置工具 MCP 面，
     声明面按契约惯例必须记**全名**（记裸名会让「哪天真的授予它」时被 scope 门用全名拒，
     又是一次「声明面与模型面记法漂移」）。已改；接缝套件 C1 咬「声明面不再记裸名」。

③ 工具 scope 门用全名校验
   三道门（scope 门 / 对象域门 / 授予面）都保持全名校验，未削弱：
   - 授予面：本批每一件都以**全名**进 `toolFilter`，`scopeDeclaration` 同步记全名（C1/C2 逐 agent 扫）。
   - scope 门：接缝套件 B3/E4 用真调用咬 —— 域外/未授予一律 DENIED，且**拒绝行的审计名是裸名**
     （引用原文）而**拒绝时点用的是调用原名（全名）**。
   - DSH 允许表：`mcpServers[].toolAllowlist` 与授予面同源同滤（C3/D3 咬「换授后允许表恰为那一件」）。

   - 新遇到并点名的**同族第二处**（不在本批处置范围内，已定位、留给迁 `create_action_draft`/`invoke_solver` 的批次）：
