【结论（一句话）】
「响应与输入成比例（线性/可加）」不是这台引擎**声明、推导或守卫**过的性质，而是世界**恰好停在线性带外**时的副产品。
域表只声明值域（min/max/restPoint/λ），投影只声明「新读数的入口不变量」，回执只声明「压了谁」；
而静止值（不动点）**也必须落在投影语义内**这条约束**从来没有被声明过** ——
于是世界态里可以永久存着一个投影自己也不认的值（幽灵不动点，投影若执行会把 92.5496 压成 85.3113、
把 99.9405 压成 87.4851），而它正是全部下游响应的锚：扰动的作用不是「输入×传递函数」，
而是**把这个锚从幽灵点踢到压缩吸引子**的一次性迁移 —— 与幅度无关、与扰动来源无关。
⇒ 幅度线性（r≈1）与横向可加性（rAB≈rA≈rB）同时不成立，且**改前改后是同一个病**（改的只是 6 个量名的操作点）。

【十问十答】
1. 为什么「正幅度下多数格超差」（比值 ≠ 幅度比）？
   答：因为那些格的响应不是幅度响应，是一次**不动点迁移**：+3 与 +20 收敛到同一个吸引子。
   证据：4053 P3 89/89 超差、r 中位数 0.9037；被扰动格 92.5496 → +3: 82.847176168302 / +20: 82.8472155885
        （差 3.9e-5，相对 4.7e-7）。TICKS=40 时最大相对偏差恒 0.85 = |1 − 6.6667|/6.6667 ⇒ r=1.000。

2. 为什么响应与幅度无关？
   答：因为扰动只负责「把格子从幽灵不动点上踢下来」，落点由压缩吸引子决定，与踢的力度**无关**。
   证据（同一支 trace 探针）：
        · 4053 utilPressure：+1e-6 → 82.847125527976 / +3 → 82.847125603156 / +20 → 82.847125908124
        · 4052 zigong.blockedPressure：+1e-6 → 84.444152895526 / +3 → 84.444154118926 / +20 → 84.444159395287
        · 1e-6 与 +20 的**第一拍**就已分开（87.485 vs 90.006），但 10 拍后并到同一处（差 < 1e-5）。

3. 为什么格子在「幽灵不动点」上（值在带内却不被压缩）？
   答：因为该值恰是 C2 合成与核衰减的**复合不动点**：核 x' = rest + (1−λ)(x−rest)、
        C2 x'' = x' + λ(base−rest)，在 x = base 处两者恰好抵消 ⇒ 每拍**净变化 0**；
        而投影入口的判据① 是「本拍没有新读数 ⇒ 一个字节不动」（world-projection.ts:81-84）⇒ 永久豁免。
   证据：4053 utilPressure 零臂 12 拍逐字节 = 92.5496；4052 zigong.blockedPressure 11 拍逐字节 = 99.9405。
        而 sat(92.5496)=85.31126027036682、sat(99.9405)=87.48510727766042 —— 投影若执行，世界态就不该是这两个数。

4. 为什么投影要写「没变就不碰」？
   答：因为 saturateToDomain 在域内不是恒等、也不幂等：每拍无差别重投影会造一条与动力学无关的暗流。
   证据：world-projection.ts:20-23「⛔ 不许丢掉判据①」；propagation.ts §4 迁出注：
        「把 next 变成『自己上一拍输出』的第二遍投影（实测 SET 80 零驱动 12 拍自己缩到 76.4706）」。

5. 为什么「没变」会被当成「合法」？
   答：因为投影的职责被定义成**新读数的入口不变量**（「值进入世界态时保证在域内」），
        不是「世界态的静止值也必须在投影语义内」。不动点的正确性被留给了三条写路的复合动力学，
        而三条写路（播种/核/C2）**没有任何一方知道软带**这件事。
   证据：world-projection.ts 头注「本模块只做一件事：把「域」从某个消费者的实现细节提升为值进入世界态的入口不变量」。

6. 为什么复合动力学的不动点会落进压缩带？
   答：因为不动点 x = base，而 base（种子读数）本身就在带内：压力族 [0,100] 的软带从 75 起
        （band = 0.25×(max−rest) = 25、knee = 75），而种子读数是 round(hash×100) 的整值。
   证据：4052 零臂 |v|>75 有 **613 格**（blockedPressure 76 格、最高 99.9405；forecastBias −98、−85；…）。
        saturateToDomain 的带定义见 propagation.ts:414（SATURATION_BAND_FRACTION=0.25）、:481-491。

7. 为什么 base 会播在带内（而不是静息点 0）？
   答：因为播种按「水平」播，而这些格在语义表里是「偏离」（DEVIATION）——种子值与语义不一致。
   证据：4052 vs 4053 同格对照：Line.utilPressure 零臂 0 vs 92.5496；Base.loadIndex 0 vs 97.5181；
        Order.costPressure 0 vs 90.384615384615（后者的 −8.09 假信号是 WO-SEMANTICS-DECLARED 已立案的那笔）。
        battery.ts:4145 起 STATE_VAR_SEMANTICS 表。

8. 为什么归位之后 4052 上还有幽灵（病没有消失）？
   答：因为归位修的是**播种值**（把 6 个量名移出带内），不是「投影只认新读数」这条判据：
        语义表只收逐格裁定过的格（缺省 LEVEL = 保持现状），未裁定格照旧按水平播 ⇒ 只要 base 还在带内，幽灵就在。
   证据：4052 今天的活标本 zigong.blockedPressure = 99.9405（1e-6 踢 ⇒ 84.4441）；同族还有 76 格 blockedPressure。

9. 为什么这件事一直静默（没被发现）？
   答：因为披露层的账（`saturations[]`）只记**实际压过**的格；幽灵格因为「没变」永远不进账 ——
        而它恰是全部下游响应的锚。契约原话是「每一次饱和都必须能在披露层看到」——
        它成立，前提是把「饱和」定义成「压过」；「**该压却没压**」这一类不在任何账上。
   证据：4052 零臂 tick 回执 saturations 只有 2 条（handan-grading / yangzhou-assembly 的 blockedPressure），
        **没有** zigong-winding（99.9405）。contracts/sim.ts:1136-1141 SaturationEvent 契约。

10. 为什么没有承载物？（追到底）
    答：因为「**世界态的静止值/不动点也必须落在投影语义内**」这条约束从来没有被声明过：
        · 声明层（结果 1092-1131 StateVarDomainSchema）：只有 min/max/restPoint/decayRef/unit/source ——
          **没有一个字段说「带内是压缩的、因而带内读数不可按比例读」**，也没说「静息值必须在带外」；
        · 推导层（播种/核/C2）：三方都不知道带，谁也算不出「这个值在不在带内」；
        · 记账层（saturations[]）：只记「压了谁」，幽灵格不进账（第 9 问实测）。
        ⇒ 「响应与输入成比例（线性/可加）」不是被声明、被推导或被守卫的性质，而是世界恰好停在带外时的**副产品**。
        所以它既不可断言也不可检验 —— 工单给的三条候选（域钳位/未收敛/combine:max）都是在猜「机制」，
        而真缺的是承载「这个性质在什么条件下成立」的**声明与判据**。

【修法】
· 主干：把投影的适用条件从「**有没有新读数**」改成「**这个值是不是投影意义下的合法值**」：
    判据① 改为 `unchanged && sat(raw) === raw ⇒ 一个字节不动；否则收回 sat(raw)`（tick0 播种路同判据）。
    等价说法：**世界态里每一个值（含不动的）都必须是投影的不动点**。
· 配套：① 回执把「带内但未压」的格子也点名（把 SaturationEvent 的语义从「压了谁」扩到「谁在带内」）；
    ② 推演回执声明「本次响应是否全程在带外（可线性读/可加）」——正好兑现 WO-2 PRD 那句
      「若引擎非线性，则须声明不可加并给出正确读法」。
· 「这样改，同族的错还会不会以另一种形态出现？」—— 会，且形态可枚举（两类已实测）：
    (a) 域把响应**吃掉**：4052 上 leadDays+3 的整条链是死的 —— 唯一出边 demo_order_leaddays_to_model_horizon
        系数为负、目标 Model.costPressure 域是 [0,100] 且 rest=min=0（硬地板），
        每拍真落下 amount = −0.010511363625 却被压成 0（回执每拍都在：`bound:"min"`）⇒ 世界态恒 0、下游全无反应。
    (b) 还手边 hinge `drive = max(0, 水平 − tolerance)`（propagation.ts:1116-1117，码里已留档「本单未处置」）
        与 combine:"max" 天然不可加。
    这三类与饱和带那一类的**唯一区别**：它们都是**声明过的**（tolerance / combine / 域都是显式字段与显式值），
    而饱和带那条「带内读数的响应语义」**没有任何声明**。⇒ 修法要治的是「**未声明的非线性**」，
    不是「消除非线性」——保序饱和是刻意设计（为了「别把引擎夹死」，见 propagation.ts:416-465），消除它才是换成另一种病。
