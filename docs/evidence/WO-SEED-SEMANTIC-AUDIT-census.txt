§1.4 ⚠ 中间态：被当作「真值字段」、实际是哈希/rng 整形的
--------------------------------------------------------------------------------
  判据：本仓称 `Order.qty/unitPrice/leadDays` 为「WO 红线真值字段」（不登记 valueRef）。
  实测（读赋值点，非读注释）：
   · `Order.qty`   `battery.ts:6467` `qty: shapeBusinessTypeQty(businessType, randInt(rng,1420,7668), so)`
     ⇒ **randInt(rng)** 播种；`shapeBusinessTypeQty`(`:557`) 对商用车再乘一个
       `factors[hashString(so) % factors.length]` 哈希选中的波动因子。**不是真值，是随机播种。**
   · `Order.unitPrice` `:374 orderUnitPriceOf` = `SEG.priceWan*1e4 * (1 + priceVar)`，
       `priceVar = ((hashString(`${so}:unitprice`) % (2*ppk+1)) - ppk)/1000`（`battery.ts:377`）
     ⇒ 基价真有出处（`SEG_REGISTRY`），**单间价差是哈希抖动的 ‰ 级**。
   · `Order.leadDays` `:6414/:6477` `leadDays: dueDay` —— 由 `status`+`dueSpread` 决定，**真**。
  ⇒ 仓主口径「其他数据都预设、不来自随机播种」若照字面执行，`qty` 与 `unitPrice` 的抖动
    也在待补范围内；本单只登记，不判该不该补（属建模/业务判断）。

S2 · 消费侧：读「水平」还是读「偏离」
--------------------------------------------------------------------------------
判据（照派单）：`×(1 + x/100)` / `base + x` / `x − rest` = 当偏离读；`x` 直接当量 = 当水平读。

C-1 偏离读（**命中本单病灶**）—— 全仓 3 处，全部集中在世界态→金额/量的投影：
  · `solvers/finance-world.ts:326`  `costFactor = 1 + costAgg.value / divisor`（divisor=100）
      ← 消费 `Order.costPressure` ⇒ 直接**乘以 [1.40,1.89]∪{2.15}**
  · `solvers/finance-world.ts:408`  `arProjected += amount * (1 + custPressure / divisor)`
      ← 消费 `Customer.receivablePressure`
  · `solvers/finance-world.ts:411`  `overdueExposure += amount * ((od ?? 0) / divisor)`
      ← 消费 `ARInvoice.overduePressure`
  · `sim/world-read.ts:303`  `factor = rule.direction==="up" ? 1 + raw/divisor : 1 - raw/divisor`
      （4 条 SIM_WORLD_PROJECTION_RULES：`costPressure`/`loadIndex`/`utilPressure`/`demandPressure`）
      ⇒ 其中 `costPressure`(M3) 与 `demandPressure`(M1) 两个源是铸造值。

C-2 水平读（**不构成本单病灶**，但要记清楚以免误判）：
  · `sim/propagation.ts:1344` `baseAmount = round12(coeff * drive * factor)`，`drive = sourceVal`
    —— 源读数按**水平**乘系数。对 pressure 族自洽（`STATE_VAR_DOMAINS` 声明 restPoint=0），
    故 M1/M2/M3 经传播链（seed.ts:374 `Order.demandPressure → Model.demandLoad` 等）**不是**偏离读。

C-3 已查证并**排除**（避免误记）：
  · `solvers/capacity.ts:765` `effectiveDemand = (…) * (1 + demandDelta)`
    —— 此 `demandDelta` 是 `num(args.demandDelta, 0)`，**求解器显式入参**（capacity.ts:764），
    **不是** `Order.demandDelta` 这个铸造 prop。同名不同物，排除。

B-1 `Order.costPressure`（源 M3 `creditUsedRatio`）
  今天：授信占用率(水平 0.40–1.15) ×100 → 被 `finance-world.ts:326` 当成本**偏离百分比**读。
  真源：`Customer.receivables` / `Customer.creditLimit`（**有赋值**，见 S4-2），二者相除即

  ⇒ 换算式须二选一，本单不代选（属建模判断）：
     (a) 若成本压力要的是**偏离**：真源不该是授信占用率，应取成本类偏离
         （候选：`Material.devPct`→`priceShock` 链 / `Model.unitCost` 对本体的偏离）；
     (b) 若沿用授信占用率：客户级 `receivables/creditLimit` 已在
         spec `customer_receivable_pressure` 用上，Order 级需另定口径。
  ⚠ 无论 (a)(b)，`finance-world` 的 `×(1+p/100)` 与「占用率」语义**必须二选一改一处**，
     不能两处都不动（现状 = 零扰动下成本即被放大到 1.40–1.89 倍）。

B-2 `ARInvoice.overduePressure`
  今天：全仓零赋值 ⇒ seed-world 哈希占位（[0,100]）⇒ `finance-world.ts:411` 当偏离读。

  ⇒ 换算式须定：逾期压力 = 逾期天数/账期天数，还是逾期金额/发票金额（本单不代选）。

S4 · 两条机制发现（比单个字段更值钱）
--------------------------------------------------------------------------------
S4-1 ⚠ **派生规格的产物会被盖上「实测」章**
  `sim/seed-world.ts:473-477` 判「实测/派生」的唯一判据是
    `const real = o.props[v]; if (typeof real === "number" && Number.isFinite(real)) → "measured"`
  而派生规格的产物也写进 `o.props`：`ontology-core.ts:537  obj.props[spec.targetProp] = value;`
  ⇒ **凡由规格算出的格子一律盖 `measured`，哪怕它的输入是 hashString 铸出来的。**
  今天 `Order.costPressure` / `demandPressure` / `shortageRisk` 三格出处章都是 `measured`，
  而它们的唯一输入是 M3/M1/M2 三个哈希值。⇒ 「34% derived」这个数**低报**了：
  它只数了走 seedHash01 那一档的格子，没数「经规格间接铸造」的格子。

S4-2 `Customer.creditLimit` / `Customer.receivables` **有真源**（派单线索此处需订正）
  两字段在 `battery-extended.ts:892 / 894`（名册客户）与 `:904 / 906`（规模补足客户）有真赋值，
  值是 `rng()` 播的（**随机播种**，不是 `hashString`）。
  故 spec `customer_receivable_pressure` = `receivables*100/creditLimit` **没有绕过**它们、用的正是它们。
  真正被绕过的是 **`Order.creditUsedRatio`**（M3）—— 它才是「有真源（客户级占用率）却另造了一个哈希量」的那一条。
