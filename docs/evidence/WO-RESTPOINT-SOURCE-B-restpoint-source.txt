§1 病灶：今天的行为是 X，应该是 Y
──────────────────────────────────────────────────────────────────────────────────────────
X（改前）：`drive = sourceVal` —— 源读数**整值（水平）**当流量。一个停在 90.38 的源，
          每拍往下游灌 `系数 × 90.38`，**零扰动的世界照样一路漂**。
          实测指纹（本单复现）：`Customer.receivablePressure` 唯一入边系数 ×0.5，
          零扰动下 3 拍从 15.7452 翻到 65.4029（×4.15）。
Y（应该）：`drive = sourceVal − 源侧静息点`，静息点优先级：
          ① `baseSnapshot[objId][stateVar]`（这个世界 tick0 的基值 = 零扰动世界该格的静息值）
          ② `domains[stateVar].restPoint`（无基值格的兜底）
          ③ 两处都没有 ⇒ **不归一**（整值直读，与改前逐字节相同）+ `unresolvedRestPoints` 显式点名
          ⛔ 绝不 `?? 0`；⛔ 不评「该格是水平还是偏离格」（审核方终裁：保留真源、不退役）。

本体依据：§2.I 不变量 ③ `x* = rest + 流入/λ` ⇒ 零扰动 ⇒ 流入必须为 0。

🔴 **判据① 只算部分达成 —— 诚实结论**：
  零扰动的**注入式漂移**已被根治（t0..t5 / t0..t3 逐字节恒定，改前的指纹 ×4.15 消失），
  但**第 40 拍仍非恒定**（receivablePressure 首偏 t6、costPressure 首偏 t4，残余 35/40 与 37/40 拍在动）。
  残余漂移的根因**已实测定位**，且**不在本单允许的改动面内**：
  · 机制：§0'' 衰减相 `bucket[sv] = round12(rest + (1-λ)(cur - rest))` 用的是 `domains[sv].restPoint`（= 0），
    而不是该格的静息值。实测 t0→t1 有 **2014 格**逐格衰减 **×0.63 = (1−λ)**（λ = 0.37 =
    `C35.pressureDecayPerTick`，作用于 33 个状态变量），衰减到 0 的那些格从 ~t4–t6 起把压力族拉下来。
  · **同族病灶（静息点读错）的第二个相位**：驱动相读的是「水平」，衰减相读的是「域的 0」。
  · 试过的修法（dist 实验，非源码）：把衰减相的 rest 也换成 baseSnapshot ⇒ 立刻变**双拉**：
    `costPressure` 均值 63.308304 → **84.832998**（+34.0%），cust_14 recv 15.7452 → 72.95，
    因为 `spec-base-synthesis.ts`（本单明令冻结）已经补过一项 `λ·(base − rest)` 来抵消核的衰减。
    ⇒ 衰减相的修必须与 C2 的代数**同一个改动**落地，改动面超出本单范围；**已回退，未留下任何补丁残留**
    （原始读数见 §6 的 decayexp 段）。

§7 追加守卫：两条线必须喂同一份源侧静息点（复核方追加要求；本单引入的新不变量）

【为什么必须补】本战役根因是「同一个量被两个口径同时读，而全仓无物守着二者一致」。
本单让 `propagateTick(` 的第 11 位实参出现在**三处**（同一次 tick 推进）：

不变量 = 三处喂**同一份** `s.baseSnapshot`（`app.ts` 自己的注释：「两条线只许差『有没有扰动』
这一个变量，任何别的差异都会直接污染信噪比那个读数」）。复核方要求**先实测再答**「有没有东西守着」。
⚠ 注意「同源」不是「同值」：判据落在**表达式唯一**上（见下 §1），不是落在数值相等上。
