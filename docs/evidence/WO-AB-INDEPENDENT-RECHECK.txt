### 第二层：costPressure.value 本身 ❌ 对不上
  从世界态逐单独立累加（value = qty×unitPrice，与对象属性 value 校验一致）：
    订单总数                        = 150（世界态里的）
    Σ(qty×unitPrice)                = 15663001584  (156.6 亿)
    承载格数(|costPressure|>0)      = 24
    Σ(costPressure×value)           = 72085653.888483
    手算 value = 72085653.888483 / 15663001584 = 0.004602289
    回包 value                                 = 0.001586
    比值 = 2.9018

  ★ 稀释因子找到了：
    回包的 Σ权重 = 45464327004 (454.6 亿 = 全订单簿 500 张)
    世界态里的 Σvalue = 15663001584 (156.6 亿 = 150 张)
    45464327004 / 15663001584 = 2.9025   ← 与 2.9018 同一致
  ⇒ **分子只累加世界态里的 150 张单，分母却用全订单簿 500 张** ⇒ 固定稀释 ≈2.90 倍。

### ⛔ 我当初「证伪」过这件事，而那个证伪是错的（第六个同族错，自曝）
  当时判据：「稀释会随输入比线性缩放 ⇒ db/da 应随输入比走；实测 db/da 趴在 0.95~0.99 不动 ⇒ 稀释出局」
  **真因：固定倍数的稀释根本不会让 db/da 变。**
  ⇒ 那个判据只能排除『随输入变的稀释』，排不掉『固定倍数的稀释』——**判据不度量目标**。
  ⇒ 与 F/D 同族：空集判绿 · 金丝雀度量错对象 · 对象id按名猜 · utilPressure 静息态推反 · 14格口径偏窄。

### 结论
  用户最初的怀疑成立：**单张订单的扰动被全域分母按 Order.value 稀释了 ≈2.90 倍。**
  而这一层**不在本单已修范围内** —— 本单治的是『静息态被播成非静息值』，
  这条是『聚合分母口径』（分子用承载集、分母用全订单簿），是另一处病。
  ⇒ 屏上那个「1.6 亿」**因此偏小 ≈2.9 倍**（若该口径确为病）。⛔ 但『该不该改』是建模判断，未裁。
