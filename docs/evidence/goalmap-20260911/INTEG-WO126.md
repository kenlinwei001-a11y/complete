### 失败的是哪一条、差在哪
用例：`WO-CHANGE-IMPACT-PREVIEW · 预览与实际一致（传导族 · 真跑 propagateTick 差分）
> 预览 recompute 集合 === 真跑 N tick 后实际变值的对象.状态变量集合`
原文断言（`apps/datacore/test/change-impact-preview.seam.test.ts:102`）：

```
AssertionError: expected [ …(1641) ] to deeply equal [ …(1413) ]
    102|     expect(previewSet).toEqual(actualSet);
```

**预览多出 228 条**（1641 − 1413）。逐条看这 228 条：
- **207 条** 是 `obj_order_*.costPressure`
- **21 条** 是 `obj_arinvoice_*.overduePressure`（被闸住的那批单的下游）

### 病因（已追到实现，不是猜）
`apps/datacore/src/sim/change-impact.ts` **按「类型 + 链路」做静态可达展开，从不读逐对权重**：

```
grep -c "viaLinkKey"                              apps/datacore/src/sim/change-impact.ts  → 8   （🐤 金丝雀：工具是活的）
grep -c "weightRef\|pairWeight\|buildPairWeights"  apps/datacore/src/sim/change-impact.ts  → 0
```

而 WO-2 给种子规则 `demo_model_cost_to_order_cost` 挂上了
`weightRef: { basis: "target_on_hand_gate" }`（`apps/datacore/src/seed.ts`），
该口径把 **350 张 `COMPLETED` 单的逐对权重压成 0**（§5.2 实测 `zeroPairs=350`）。
⇒ **引擎真跑时它们不动了，而预览层不知道这回事，照旧把它们列进「会重算」。**

**形态**：「预览用『结构上可达』当作『真跑会变』的证据 —— 在引入 0/1 闸门之后，前者不再度量后者。」

### 最小修路径（我**没有动手**，止损纪律：⛔ 不重写已有实现）
`change-impact.ts` 的展开需要与 `pair-weights.ts` 共用同一份口径：
对挂了 `weightRef` 的规则，逐对权重为 0 的那些对**不进 recompute 集合**。
⛔ **不建议改测试期望去迁就** —— 那会把「预览承诺了一个引擎不会兑现的集合」这个真问题盖掉，
而它恰恰是本仓 SEAM-GATE 要堵的那种断在接缝上的假绿。

**⇒ 结论：WO-2 以现状并入 canonical 会把这条红带进正线。WO-1 / WO-6 无此问题。**
