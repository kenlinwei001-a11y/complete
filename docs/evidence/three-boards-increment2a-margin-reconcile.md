# 轨M 增量2a · 综合毛利率逐细分贡献勾稽闭合（母版 §1.A/§1.B）验证

> 母版：台账综合毛利率 = 逐单贡献求和勾稽闭合；项目级聚合勾稽表（负+正=缺口闭合）。
> HANDOFF：能扩 `margin_attribution` 就扩、真不能才换、不盲目另起。

## 1. 接/扩/换判定（不盲目另起）
- `margin_attribution` 是**逐对象成本项倒挂**分解（targetType+costFields），与订单台账的**细分毛利率**模型不同（Order 无成本字段，毛利来自 SEG_REGISTRY 细分毛利率）→ **真不能复用其口径**。
- 故**扩 `affected_orders` 聚合**（台账真实数据源）加 `marginLedger`，复用 SEG_REGISTRY（segMargins/SEG_PRICE 单一来源）+ `planBaseline.gmTarget`（config）——**非另起新求解器**。

## 2. 勾稽口径（确定性·零写死·可溯）
- 综合毛利率 = Σ_细分( 营收占比 × 细分毛利率 ) → **Σ贡献 = 综合毛利率（闭合）**。
- 缺口(实际−目标) = Σ_细分( 营收占比 × (细分毛利率 − 目标) ) → **Σ缺口贡献 = 缺口（负+正闭合）**。
- 真价/利：SEG_REGISTRY（乘 2.2万/18% · 储 1.4万/13% · 商 1.8万/15%）；目标：`planBaseline.gmTarget=16%`（config 单一来源）。R6 确定性、R13 可溯、RL5 零业务常数。
