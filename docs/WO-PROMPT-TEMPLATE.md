# 给 dev 的正文（以下全部照抄，`<>` 处逐单填）

## 1 · 开工第一段：把坐标原文读出来

把我给的坐标**原文读出来**，各写成一句「**今天的行为是 X，应该是 Y**」。
**写不出来别动手。**

⚠ 我给的 `file:line` 与状态是**线索不是结论**。
若实测发现**已经做了** ⇒ **停手，把证据（file + 符号 + 触发条件）顶回来，改台账不改代码。**

> 本仓真发生过：判某道门今天做不了，实际那个函数**早已存在且接了两处** ⇒ 把工作量从「接一条线」错报成「造一道门」，**直接歪掉排期**。

## 2 · 自证你的树在 PIN 上

⚠ **本仓 agent worktree 一律从旧树起步**（实测落后数千提交，连续 10 个 agent 全部撞上）。**别信我写的 PIN，自己测：**

```bash
git rev-parse --short HEAD
git merge-base --is-ancestor HEAD <PIN> && echo "落后⇒必须 detach" || echo "不落后"
wc -l <树龄探针文件>        # 旧树 ≈<N> 行；PIN ≈<M> 行
```

落后就 `git checkout --detach <PIN>`（**只准 detach 到 PIN**，不切命名分支）。树龄探针对上才算移过去。
**报告头回显这三个数。**

> 不纠正的后果是实的：本仓出过同一个问题在两棵树上得到「20 单」与「500 单」两个都正确、**差 25 倍**的答案。

## 3 · 第一条命令：建分支 + 空提交 + push

```bash
CANON=<canonical 分支>
git fetch origin && git checkout -B <wo> $CANON
git commit --allow-empty -m "WIP·<wo> 起点"
git push -u origin HEAD:refs/heads/claude/handoff-<wo>
```

之后**每改完一个文件**就 `git add -A && git commit && git push` 一次
—— 不是「写完一个功能」，更不是「测试跑绿了再推」。提交信息写 `WIP·未验` 都行。

> **为什么是第一步而不是收尾**：upstream 从第一分钟就存在 ⇒ 后续 push 不用想 refspec、不用判断「这算不算一个可命名单元」。**把判断题变成肌肉记忆。**
> 「什么时候算完成一个单元」这个判断，正是本仓三次丢产出事故里每次都被推迟到「再写一点」的那一步。

## 6 · ✅ 测试（**本次重写的那一段**）

### 你只跑这三样

| | 跑什么 | 它度量什么 |
|---|---|---|
| ① | **自己的接缝门** | 驱动接缝的**组合**测试，不是各半 unit |
| ② | **变异反证** | 这道门**有没有鉴别力** |
| ③ | **爆炸半径** | 只跑 import 了你改动文件的那批测试 |

### ⛔ 不跑全量四包

全量四包是**并入正线的门**，由主持方在**合成好的集成线**上**跑一次**。

> **形态**：「我用『跑了全部 N 个用例』当作『这次改动没有咬红东西』的证据 ——
> 而它度量的是『**今天整个仓库绿不绿**』。跟本次改动无关的那部分，**跑一万遍也不会因为它而变**。」
>
> 实测代价：一次全量 2462 用例 ≈ 3 小时，而它在跟关键路径抢 CPU，结果**当时不可行动**。

### ② 变异反证不能省

**一道从没红过的门，绿了不说明任何事。**
把实现**改坏**（如让分类器恒报一个值、让闸门常开）⇒ 门**必须红**，记 RC；**还原** ⇒ 必须净，记 RC。
**报告里给两个数。** 没有这两个数 = 这道门是装饰品。

⚠ 金丝雀**必须与主逻辑共用同一份实现**，不许各抄一份正则 —— 抄了就是装饰品：改主逻辑时金丝雀拿旧的去测、照样绿。

### 退出码

```bash
cmd > out.log 2>&1; RC=$?
```

⛔ **禁止** `cmd | tail -n; echo "EXIT=$?"` —— `$?` 取的是 `tail` 的退出码（**恒 0**）。
本仓曾据此把一个**编译失败**的提交判为「BUILD 通过」并入正线，直到部署方 build 失败才暴露。
失败时打印 `error TS|FAIL|AssertionError` **原文**，⛔ 不许只 tail 几行把错误挤掉。

## 7 · ✅ 对照实验（**不做这条 = 本单不算验收**）

**「跑得起来」不度量「算得对」。**
不是问「跑不跑得起来」，是问：**「把 X 改成 X'，Y 必须按某个可预言的方式变。」**

**必须给四个数**：修改前两个、修改后两个。**缺一个都不算交付。**

本单的判据：`<逐单写死，例如：碳酸锂 +15% 得两个数、铝箔 +15% 得两个数；修前四数中两两相同（这就是病），修后必须按 BOM 占比拉开>`

⚠ 这条判据**不需要读一行代码就能设计** —— 它来自业务常识。
**一直在读代码却设计不出这种判据，本身就是信号。**

## 8 · 🐤 金丝雀（报否定结论前必跑）

报「没有 / 零调用方 / 做不到 / 整条缺」之前：

1. **沿调用链再追至少一层** —— grep 是线索不是结论。
   注意间接调用：re-export / 高阶函数 / 依赖注入 / **字符串键分发** / 事件订阅 —— 这些 grep 一次都看不见
2. **先跑一个已知必中的样例**。金丝雀不中 ⇒ 报「**量法坏了**」，⛔ 不许报「不存在 / 零命中 / 代码干净」
3. 报告里**每一条否定结论都必须附金丝雀的命中证据**

⚠ 已知工具坑：含通配的 pathspec **不当目录前缀用**（`git grep -- 'apps/*/src'` **恒 0 命中**，要写 `apps/*/src/*`）

## 9 · 四态（混了必修错地方）

| 态 | 判据 | 修法 |
|---|---|---|
| ① 没接线 | src 调用方为空（**只有 test 引用 = 已排练，不是已实现**） | 接线 |
| ② 接了线没数据 | 有 src 调用方，但输入恒空/恒假，分支从未进入 | 补数据或删死分支 |
| ③ 接了线接错地方 | 挂在错误的路径上 | 补挂载点 |
| ④ **接对了、跑通了、但算错了** | 链路完整、屏上有数、**测试全绿**，但公式缺项/口径不对 | 改公式/改口径 |

⚠ **前三态查不出第四态，必须单独看公式。**
实例：`amount = coeff × sourceVal × factor` **没有用量项** ⇒ 碳酸锂（BOM 大头）与铝箔（很小一块）各涨 15%，得到**完全相同**的成本压力。

## 10 · CPU 与端口

- **起 vitest 前数并发**：判据是「**父进程不是 vitest 的 vitest 进程**」（每棵进程树只算它的根）。
  **双向金丝雀**：机器空闲**必报 0**（报非 0 ⇒ 把自己或 worker 算进去了）；只跑一个 run **必报 1**（报 ≥2 ⇒ 在数 worker）。
  **跑不出这两个数 ⇒ 量法坏了，⛔ 不许拿它做避让决策。**
- **端口**：本机**没有** `ss`/`netstat`，**探针的沉默不等于端口空闲**。
  唯一可靠判法是**真去 bind**。起服务后必须**自证「我连的是我自己起的那一个」**（回显端口 + 一个只有自己新代码才有的字段）。
  > 本仓真发生过：探针报「空闲」，实际端口被别的 agent 占着，于是**读了别人遗留的旧服务**，对**自己的代码**下了错误结论。
- ⛔ **杀进程别用会自匹的 `pkill -f`** —— 命令行里含该字串会把探针自己也匹进去（本会话已自杀 4 次）。
  用 `ps -eo pid,args --no-headers | grep -F '<key>' | grep -v grep` 取确切 pid。

## 11 · 📤 产出

**报告头**：起点 HEAD · detach 后 HEAD · 树龄两个数 · 分支 tip · `git status` 是否为空

**正文**：
- 「今天的行为是 X，应该是 Y」**逐条原文**
- **对照实验四个数**
- **变异反证两个 RC**（改坏 / 还原）
- 爆炸半径测试 RC（逐包给，⛔ 不许只写「全绿」）

**末尾两节**：
- **《屏幕上多了什么 / 少了什么》** —— **答不出 = 这一轮无效**
